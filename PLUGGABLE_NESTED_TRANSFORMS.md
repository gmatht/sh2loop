# Pluggable Nested Transforms — a generated tree of native-emission capabilities

## Problem

The shIR renderer accumulates hand-written native-lowering functions, one per
shell idiom. Today in `src/ir.rs` they include `try_native_grep_test`,
`native_grep_chain`, `native_literal_pipeline` (printf|sort/head/tail/wc),
`native_cat_heredoc`, `native_cmp`, plus `single_line_payload`/`try_lift_grep_contains`
in `shir.rs`. Most of these are really the SAME parent pattern —

> *a pipeline whose first stage is a single-line producer (`echo` / `printf`),
> dispatched on the consumer command*

— yet each independently walks the tree and re-derives the producer payload and
the "is stdout consumed" facts. Each new consumer (`sort`, `head`, `tail`, `wc`,
`grep`, `cmp`, …) will fork another near-identical tree-walker. That does not
scale: adding an idiom means editing a growing `match` and duplicating traversal.

This file records the architecture for replacing that ad‑hoc growth with a
**tree of transforms** whose dispatch (and, at the next step, whose IR node set)
is *generated at build time* from per-capability declarations.

## Part 1 — the capability tree (renderer/native-emission layer)

A parent transform **owns the traversal once** and dispatches to focused leaves:

```
src/pipeline_native/            (crate module: the parent)
  mod.rs                        - recognize a pipeline (or single stdin-reader cmd)
                                - extract producer payload + consumption facts into a Ctx
                                - call the generated dispatch
  producer.rs                   - echo/printf single-line-literal payload extraction
  capabilities/                 <- the subtransform dir (build.rs scans this)
    sort.rs                     - one command, one file: `emit(ctx) -> Option<String>`,
    head.rs                       self-gating (None unless ctx.cmd == "sort" etc.)
    tail.rs
    wc.rs
    grep.rs
    cmp.rs  cat.rs  ...
  dispatch_gen.rs               <- AUTOGENERATED by build.rs; never hand-edited
```

- **The parent walks once.** Everything that is not a pipeline (cmp file-pair,
  cat-heredoc) stays in a small forest, not forced under one parent.
- **Leaves never walk.** The parent hands each leaf a ready `Ctx`
  (`cmd`, literal payload, whether stdout is consumed, the stage IR).
- **Adding a consumer = dropping a file** into `capabilities/`; no transform
  edits a shared `match` by hand.

### The `build.rs` codegen for the dispatch

```rust
// build.rs (crate root of `debashl`)
fn main() {
    let caps = Path::new("src/pipeline_native/capabilities");
    println!("cargo:rerun-if-changed={}", caps.display());
    let mut mods = String::new();
    let mut chain = String::new();
    for e in fs::read_dir(caps).unwrap().filter_map(Result::ok).filter(|e|
        e.file_name().to_string_lossy().ends_with(".rs"))
    {
        let name = e.file_name().to_string_lossy().trim_end_matches(".rs").to_string();
        mods.push_str(&format!("    pub(crate) mod {name};\n"));
        chain.push_str(&format!(
            "        if let Some(s) = capabilities::{name}::emit(ctx) {{ return Some(s.into()); }}\n"));
    }
    let out = env::var("OUT_DIR").unwrap();
    fs::write(format!("{out}/pipeline_native_gen.rs"), format!(
        "// @generated by build.rs — do not edit\n\
         pub(crate) mod capabilities {{\n{mods}}}\n\
         pub(crate) fn native_pipeline_dispatch(ctx: &PipelineCtx) -> Option<String> {{\n\
         {chain}    None\n}}\n")).unwrap();
}
```
`mod.rs` does `include!(concat!(env!("OUT_DIR"), "/pipeline_native_gen.rs"));`.
The dispatch is a **linear attempt** over all leaves; each leaf self-gates
(`if ctx.cmd != "sort" { return None }`), so `build.rs` never needs to introspect
a leaf's behavior — it only enumerates the directory and re-generates the chain.
`rerun-if-changed` on the directory re-runs the script when a leaf file is added
or removed.

### Tree-walking across nodes the transform does not understand

The parent must still reach `echo| …` pipelines **nested inside nodes it was not
written against**. Two facts make this sound:

1. **Structural traversal ≠ semantic transformation.**
   - *Discovery* needs only one answer from a node: *"what are your `IrStmt`
     children?"* — a structural fact, not a semantic one.
   - *Rewriting* must be **location-atomic**: replace the exact matched
     sub-statement and put it back in the same slot; never re-shape the unknown
     node's internals or assume its evaluation/scoping semantics.
2. **The child walker is generated from the same node declarations that drive
   JSON and rendering.** A declaration like
   `node CountedFor { var: String, body: [Stmt], cond: Expr, … }` tells
   `build.rs` which fields are `Stmt`/`Expr`; it emits a `children_of(&mut IrStmt)`
   that exhaustively enumerates the union. **Add a node → rebuild → the walker
   descends into it** — pre-existing transforms automatically reach pipelines
   inside the new node, because they walk *"this node declares these children,
   descend"*, not *"I know this node"*.

   The open (trait-object) alternative — a runtime `fn children_mut(&mut self)
   -> Vec<&mut IrStmt>` on a `Node` trait — gives the same reachability without
   a recompile (the new node implements one method). Both restore "append-only
   IR still composes".

3. **`traversal_safe()` gating.** Some nodes carry semantics that change what a
   nested rewrite means (ordered/backgrounded bodies, `wait`-synchronized
   regions, name-scoped blocks). Such nodes signal `traversal_safe() == false`;
   a *discovering* transform may still descend to FIND patterns, but a
   *rewriting* transform defers that subtree to the node owner (the marketplace's
   `refuse > guess`, applied at the traversal layer). The walk must be
   deterministic in order and idempotent about which capability consumes which
   subtree (no two leaves may both claim the same `echo| …`).

## Part 2 — the IR as a build.rs-generated union of transform-declared nodes

Goes one level deeper: not just the **dispatch**, but the **node set itself**
is the union of nodes each transform declares. In `debashl` the A1 JSON contract
is hand-written in three places that can drift — `ir.rs` (the enums),
`shir_json_in.rs` (parser), `shir_json.rs` (serializer) — plus
`frontends/shir-contract/schema.json` that `harness/contract-gen` and
`sh2runtime` validate against.

Given a node declaration, `build.rs` can emit **all of these from one source**:

```
node CountedFor { var: String, init: Index, cond: Expr, step: Index, body: [Stmt] }  // tag "CountedFor"

=>  (a) the enum arm `IrStmt::Ext(… )` / a wrapper type
    (b) #[derive(Serialize, Deserialize)] #[serde(tag="type")]  →  JSON gen + parse together (can't drift)
    (c) the child accessor `children_of`  →  traversal reachability (Part 1)
    (d) a schema.json fragment  →  the contract sh2runtime validates
    (e) render delegation → the owning transform's capability
```

Because Rust sum types are closed, "open union" has exactly two realizations:

| | (A) trait objects / `serde_typetag` | (B) build.rs reified closed enum |
|---|---|---|
| add node | new struct + register | drop a declaration → rebuild |
| JSON gen/parse | built-in (typetag) | generated (derive or hand-duals) |
| exhaustiveness | runtime refuse for Ext | generated dispatch, `_` → refuse |
| perf | one `Box` indirection per Ext | flat enum |
| build.rs | none | yes — must parse declarations |

**Recommended: hybrid.** Keep a small closed **core spine** (`Assign`, `Expr`,
`Block`, `If`, `While`, `Call`, `Declare`) for compiler exhaustiveness and
speed, and a single extensible slot:

```rust
pub enum IrStmt { /* closed core … */, Ext(Box<dyn Node>) }
```

`build.rs` aggregates the transform-declared nodes into that slot and generates
their JSON mapping, child accessor, schema fragment, and render delegation.
This is the protobuf / FlatBuffers / CDDL schema-driven-codegen pattern — a good
fit here precisely because there is a schema-first consumer (`sh2runtime` via
`schema.json`), not just an in-process enum.

**Costs to accept.** (1) the declaration DSL is a second source of truth if you
write it by hand (or you accept generated, never-hand-edited Rust); (2) you lose
the *compile-time* "a pass forgot this node" canary for extension nodes — the
generated dispatch turns it into a *runtime* refusal (which is also, arguably,
the marketplace point: graceful per-backend verdicts).

## Layer separation

- **A1 op synthesis** (`shir.rs try_lift_grep_contains`, `single_line_payload`):
  producing a *shared* cross-backend shIR node/op (e.g. `contains`). This is a
  normal transform operating on the A1.
- **Native emission** (this tree): how one backend renders a node natively.
  These are **per-backend capabilities** — a perl tree and (eventually) a
  distinct estree tree share only the Ctx/schema shape, not the emit logic.
