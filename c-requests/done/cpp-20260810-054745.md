# cpp: bare unary `!<var>` in an if-test drops the branch in the estree run

## NEED
The clib test-string lowering must render a bare unary-not on a
variable (`if (!no)`) so the estree/JS run takes the branch. Today
`!(a == 1)` works (t33_logic.c) but `!no` renders a `test("! $no")`
string that the estree runtime evaluates false — the branch is silently
dropped in the JS run while native C prints it.

## WHY
The cpp prototype's `bool` desugar (bool→int) exposes the gap directly:
`bool no = false; if (!no) printf("bang\n");` — native g++ prints
"bang", the transpiled run does not. Pure C has the same bug
(reproduced via c-sh-go on `if (!no)`), so it is a C-owned lowering
gap, not a C++-surface issue.

## MINIMAL-C-CHANGE
In c-sh-go's test-string emission for the unary `!` operator: when the
operand is a plain variable, emit the proven parenthesized form
`!(VAR == 1)` (or handle `! $var` in the runtime test tokenizer) so
the negation is evaluated. The proven `!(a == 1)` shape in
t33_logic.c is the model.

## FAILING-CASE
frontends/cpp-sh-go/testdata_cpp/bang_var.c:
```c
#include <stdio.h>
int main(void) {
    int no = 0;
    if (!no) printf("bang\n");
    return 0;
}
```
expected stdout: `bang`

## VALIDATION
`make -C frontends/cpp-sh-go test-cpp` green (the cpp gate re-pins
`!no` once the shared lowering lands; t02_bool.cc currently avoids the
form with the proven `!(no == 1)`).
