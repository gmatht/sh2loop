## WHY

Unchanged from the 18 earlier filings: `unset x` (and `read x`, `local x`,
`declare -i x`) record no write to a 1–2 letter name, so copy-propagation still
believes the name holds its single assigned literal and substitutes the stale
value into every later read — the shipped A1 has lost the read, and no renderer
can repair it. Not perl-specific and not posix-sh-go-specific: estree, c, go,
java, python, rust and zig are all handed a program whose output contradicts
bash.

## MINIMAL-CORE-CHANGE

As quoted above (the 18th filing's hunk). Write sites are only ever ADDED, so it
can only refuse a fold, never invent one (REFUSE > GUESS); the worst case is a
plain `getVar`/`param` node every renderer already lowers.
