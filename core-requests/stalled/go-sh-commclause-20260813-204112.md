# go-sh: A1 contract has no channel/select vocabulary — Go commClause is inexpressible

## NEED
The A1 contract must gain a **channel/select vocabulary** so the go-sh
frontend can lower Go's `select` statement and its communication
clauses (grammars-v4 golang rules `selectStmt` / `commClause` /
`commCase` / `recvStmt` / `sendStmt` / `channelType`). Concretely:

1. a channel value type + creator, following the A1's whitelisted-helper
   convention (`Call` with `purity:"Emulable"`), e.g.
   `Call{func:"sh2.makeChan"}` returning a runtime FIFO (the ESTree
   runtime can back it with an array);
2. `Call{func:"sh2.recv", args:[ch]}` (blocking receive, used for both
   `<-ch` and `v := <-ch` — the latter additionally Assigns the result)
   and `Call{func:"sh2.send", args:[ch, v]}` (send);
3. a **`Select`** node (sibling of `Case`/`If` in src/ir.rs + the A1
   serialization in shir_json.rs / shir_json_in.rs) with a list of
   comm clauses, each carrying `comm: "recv"|"send"|"default"`, the
   channel expr (+ optional guard var / sent value) and a body of
   statements — i.e. `{type:"Select", clauses:[{comm:"recv",
   target:"v", ch:{...}, body:[...]}, {comm:"default", body:[...]}]}`,
   which the ESTree renderer lowers to a round-robin non-blocking poll
   of the channel FIFOs (bash has no native select-on-channels; the
   runtime emulates the semantics).

`channelType` alone (`chan int` in a `var` decl) is currently
silently *dropped* by the frontend (the var-decl parser skips the type
and registers the name as `""`), which is fine for the value-less
declaration form — the missing piece is the operations: make/recv/
send/select.

## WHY
The coverage hook (`rules-gap.sh`) reports `commClause` as a golang
grammar rule no testdata example exercises. No example can exist: the
frontend cannot express it — there is no lowering path and the A1 has
no target shape. The hand-rolled parser in frontends/go-sh/go-sh.go
has no `select` statement case in `parseStmt` (only if/for/switch/
return/go/var), the lexer has no `<-` operator (multiOps =
`:= == != <= >= && || += ++`), and `chan`/`make(chan ...)` are not
understood, so any select program fails loudly (exit 2):

    $ ./go-sh --shir /tmp/sel.go --raw
    go-sh: line 3: expected assignment operator, got "{"
    exit=2

    $ printf 'package main\nfunc main() {\n\tch := make(chan int)\n}\n' \
      | ./go-sh --shir /dev/stdin --raw
    go-sh: line 3: unexpected token "int" after expression
    exit=2

This is NOT a by-design subset refusal: go-sh's FRONTEND.md lists no
channel exclusion, and PARSER_GAPS.md classifies the whole cluster
(`selectStmt`/`commClause`/`commCase`/`recvStmt`/`sendStmt`/`goStmt`/
`channelType`) as category-1 A1-EXTENSION — "goroutines/channels/select
are process-model semantics; the A1's `Background` is shell
backgrounding, unrelated" — explicitly making Go's `select`/channels
*requestable* A1 extensions, not dead ends. (The worker ledger
frontends/coverage/refused-go-sh.txt does contain `selectStmt`/`sendStmt`
from an earlier cycle — that is why `rules-gap.sh` surfaced `commClause`
instead — but `commClause`/`commCase`/`recvStmt` were never ledgered,
and the ledger's core-pending mechanism exists precisely to prune
escalated gaps once the contract has them, so the gap is retried.)
Adjacent concurrency IS partly expressed: `go func() { ... }()`
lowers to `Background(Subshell(body))` + `wait` (t44_background.go),
and switch/type-switch lower to the `Case` dispatch — the frontend
would lower select the same way if the A1 had the nodes. The A1's
`Background` is shell backgrounding (fire-and-forget + wait) and is
unrelated to Go channel rendezvous, so no existing node/field can
carry comm-clause semantics. This follows the py-sh-go sliceop /
lambdef / star-expr precedents: inexpressible because the A1 contract
has no node/field, not because the subset refuses it (PARSER_GAPS.md
categories the whole cluster as category-1 A1-extension).

## MINIMAL-CORE-CHANGE
1. src/shir.rs / src/ir.rs: add the `Select` stmt node
   (`{type:"Select", clauses:[...]}` — clause = comm kind, channel
   expr, optional target var (recv) / value expr (send), body), and
   whitelist `sh2.makeChan` / `sh2.recv` / `sh2.send` in the
   emulable-helper table alongside the existing `sh2.*`/`param(...)`
   helpers. No change to existing node shapes, so current emits stay
   byte-identical.
2. src/shir_json.rs / src/shir_json_in.rs: serialize/accept the new
   node + helpers in the strict ingress deserializer (mirror the
   `Case`/`Background` handling); frontends/shir-contract/schema.json
   gains them (workspace-side, keeps check_schema.py green).
3. src/estree.rs: render `Select` as a non-blocking round-robin poll
   over the channel FIFOs (recv: shift-or-block on empty; send: push;
   default: run when no clause is ready), and back `sh2.makeChan` with
   an array value so `recv`/`send`/`Background` interaction works.

The frontend side (lexer: `<-` operator; parser: `select { case …:
… default: … }` → `Select` with comm clauses) is go-sh's own fix and
lands after the contract has the shape; the coverage worker retries
the gap automatically once this request completes.

## FAILING-CASE
Minimal Go program (valid Go; `go run` blocks on the recv unless a
sender runs — with a default clause it prints `none` and exits 0):

```go
package main
func main() {
	ch := make(chan int)
	select {
	case v := <-ch:
		fmt.Println(v)
	default:
		fmt.Println("none")
	}
}
```

stdout: `none`.

Current behavior: `./go-sh --shir` fails at the channel creator
itself — `go-sh: line 3: unexpected token "int" after expression`
(exit 2) — and even with the make removed, the `select` keyword is
not a recognized statement start (`go-sh: line 3: expected assignment
operator, got "{"`, exit 2). So no testdata example can cover
`commClause`, and the A1 contract lacks the channel/select shape
end-to-end (frontend emit → ingress acceptance → ESTree run vs native
go stdout). A send-form case is equally unexpressible: `case ch <- 1:`
chokes on the unlexed `<-`.
