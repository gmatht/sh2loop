## Second case: a COMBINED assignment `IFS=<value> NAME=(…)` loses the IFS assignment

**Repro** (`sh2perl/examples/064_07_complex_array_operations.sh`):

```sh
IFS=$'\n' sorted=($(sort <<<"${config[*]}"))
```

The emitted IR has only ONE statement for that line (`Assign{var:"sorted"}`);
the `IFS=$'\n'` prefix is gone.

```
otranspilerl-cli --target shir /tmp/ia.sh | jq '.stmts[0].body | length'
# 1        <- the IFS assignment is absent
```

**Also core, not backend:** the c renderer emits no `IFS` handling for it
either, so the value is lost for every backend.

**Why it matters here:** bash joins `${arr[*]}` with the FIRST CHARACTER of
`IFS`. With the assignment dropped, a file that sets `IFS=$'\n'` still joins
on a space, so `sort` receives ONE line instead of one per element and
064_07 prints `admin localhost 8080` where bash prints `8080 admin localhost`.

A minimal equivalent:

```sh
IFS=$'\n' x=($(echo a))
echo "[$x]"
```
