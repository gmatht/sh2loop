# py-sh-go: ESTree renderer cannot execute the A1 `Index` expr node (round-trip gap)

## NEED

The shared core must render the contract's expr `Index` node
(`{"type":"Index","var":<str>,"key":<expr>}` — the A1 representation of an
array element read) in the ESTree backend, so a frontend that emits it can
pass `debashc --shir-in-estree` end-to-end instead of panicking.

Today the node is accepted by the A1 deserializer and rendered by every
other backend (perl_backend.rs:367, go_backend.rs:733, rust_backend.rs:568,
zig_backend.rs:495 — the "Perl-only" guard label is stale), but
`expr_to_estree` in src/shir.rs has no arm for `IrExpr::Index` and falls
into `other => unreachable!("Perl-only IR expression reached the ESTree
renderer: {other:?}")` (shir.rs:31577). The ESTree backend is the
executed-stdout oracle for every frontend gate, so the contract's own
Index node is unusable by any frontend today.

## WHY

py-sh-go's gate is GREEN, but the coverage proxy (frontends/coverage/
coverage-gap.sh — the A1-node inventory over the testdata emits) reports
"A1 node Index" as an uncovered construct. The frontend supports array
indexing (t21/t55/t66) but hardwires every read to the `arrayIndex` CALL
node (main.go subscriptIR), and its arith-subscript path cannot produce
the arith Index either (a broken leftover: `a[1] * 2` panics the frontend,
`a[1] + 1` is diverted to string concat). The natural fix for the
frontend — emit the contract's rich `Index` node for `a[i]` reads — is
blocked on the core: the deserializer ACCEPTS the node (ingress passes),
but `--shir-in-estree` then crashes:

```
thread 'main' panicked at src/shir.rs:31577:18:
internal error: entered unreachable code: Perl-only IR expression reached
the ESTree renderer: Index { var: "a", key: Int(0) }
```

(exit 101 → the gate's ingress phase reports "emit is not valid A1 shIR").
So the construct is inexpressible end-to-end not because the subset
refuses it (array reads are a core subset feature) and not because the
contract lacks the node (schema.json defines it in both expr and arith
vocabularies) — but because the gate's execution backend cannot render it.

## MINIMAL-CORE-CHANGE

In `src/shir.rs`, `expr_to_estree` (starts ~line 29561), add one arm
BEFORE the `other => unreachable!` fallback (line 31577), mirroring the
existing `func == "arrayIndex"` Call arm (shir.rs:29862) and the
`ArithAst::Index` arm (shir.rs:8608, `Number(sh2.arrayIndex(var,key))||0`):

```rust
// A1 `Index` expr node (array element read — the contract's rich form
// of the `arrayIndex` call; the arith variant renders below at
// `ArithAst::Index`, and go/rust/zig/perl backends already render
// IrExpr::Index). The key is a full expr (Str/Int/...).
IrExpr::Index { var, key } => {
    let key_e = expr_to_estree(key);
    // optional: apply the same lifted-key inline as the
    // `arrayIndex` Call arm (array_index_key_expr for Str keys)
    sh2_call("arrayIndex", vec![str_lit(var), key_e]),
}
```

No other file changes: shir_json_in.rs (lines 881, 1161) and
shir_json.rs (lines 381, 467) already round-trip both Index variants.
Regression risk is nil: the arm only fires on the contract's Index node,
which no current corpus emits (bash parses `$arr[i]` to
Word::MapAccess → `arrayIndex` call, shir.rs:7173/7614).

## FAILING-CASE

Minimal valid A1 program (the deserializer accepts it; the ESTree
renderer panics). Reproduce: `debashc --shir-in-estree /tmp/index.json`:

```json
{"type":"Program","contract_version":1,"imports":[],"requires":[],
 "subs":[],"var_types":[{"name":"a","type":"Any"}],"stmt_lines":[],
 "stmts":[
  {"type":"Assign","targets":[{"var":"a","sigil":null,"indices":[]}],
   "expr":{"type":"Array","elems":[
     {"type":"Str","value":"10","style":"DoubleQuoted"},
     {"type":"Str","value":"20","style":"DoubleQuoted"}]}},
  {"type":"Expr","expr":{"type":"Index","var":"a",
    "key":{"type":"Int","value":0}}}
 ]}
```

Expected after the fix: the Index read renders as `sh2.arrayIndex("a", 0)`
and the emitted JS executes (the same read expressed as the
`{"type":"Call","func":"arrayIndex",...}` node already runs green today).
The Python source the py-sh-go frontend would lower to this shape:
`a = [10, 20]; print(a[0])`.
