# posix-sh-go: A1 node `Declare` still uncovered — re-escalation (companion of posix-sh-go-20260813-001245.md, still pending)

## NEED

The shared core's shell frontend must lower declaration builtins
(`local name=value` / `declare name=value` / `typeset name=value`, no
flags) to the A1 `IrStmt::Declare` node so `debashc --shir FILE --raw`
can emit `"type": "Declare"`. Today `stmt_for_command` (src/shir.rs:5185)
builds only `Assign` / `Expr(Call exec …)` shapes for the declare family,
and the ONLY `IrStmt::Declare` constructions in the tree are the
deserializer (`shir_json_in.rs:361`) and the perl-pipeline
(`generator/*`) — never the frontend lowering — so no `--shir` output
contains a Declare node and the A1-node coverage proxy
(`frontends/coverage/coverage-gap.sh`) reports `A1 node Declare` for
every shell frontend at once.

This re-escalates the gap previously filed as
`core-requests/posix-sh-go-20260813-001245.md` (identical NEED; the
estree worker may treat the two as ONE request, oldest first — it is
still pending, not in `core-requests/done/`, and the core is unchanged:
`grep 'IrStmt::Declare {' sh2perl/src/shir.rs` shows only match arms,
no construction in `stmt_for_command`). The gap detector re-surfaced it
despite the pending ledger because `coverage-gap.sh`'s exclusion
pattern-joins the refused and core-pending ledgers without a `|`
separator, so the first pending entry ("A1 node Declare") leaks past the
filter — the hook therefore re-asked this cycle.

The node itself is complete end-to-end — no contract change needed:
- schema: `frontends/shir-contract/schema.json` stmts.Declare
  (`vars: decl[]`, `init: expr|null`, `local: bool`; `Decl{name,sigil}`)
- serializer: `src/shir_json.rs:121` (`decl_json` at :367)
- deserializer: `src/shir_json_in.rs:350`
- estree renderer: `stmt_to_estree` Declare arm (src/shir.rs:14980) —
  `local: true` takes the exec-local lift (`let`/assignment for literal
  inits, runtime `builtin("local", …)` for dynamic inits, `builtin`
  setting `""` for bare `local v`); `local: false` with init renders the
  plain assignment
- js backend: `src/js_backend.rs:538` (vars hoisted as `let`)

## WHY

posix-sh-go gate is GREEN but the A1-node coverage proxy reports
`A1 node Declare` uncovered. A prior attempt
(`frontends/posix-sh-go/testdata/t82_declare.sh`, commit `1fcd199`)
emits only `Call`/`Str`/`Array`/`Expr` — byte-equal to the core, gate
green, and the gap detector still reports Declare, because the example
cannot contain a Declare node: the frontend is byte-locked to
`debashc --shir --raw`, which never emits one. Probing every declaration
form:

```
declare x=5     -> Assign        declare -i x=5 -> Expr(Call exec …)
local x=5       -> Assign        local -i x=5   -> Expr(Call exec …)
typeset x=5     -> Assign        readonly r=3   -> Expr(Call exec …)
readonly x=5    -> Assign        typeset -i t=7 -> Expr(Call exec …)
export x=5      -> Assign
```

This is NOT a by-design subset refusal: the posix-sh-go frontend parses
the declaration builtins fine (t82_declare.sh, t41_local_var.sh,
t45_env_set.sh all pass the gate) — the construct is expressible; what is
inexpressible is the **Declare emission shape**, which only the shared
core's lowering can provide.

## MINIMAL-CORE-CHANGE

Scope: `src/shir.rs` only — the `exec_stmt` / `Command::BuiltinCommand` /
`Command::Simple` arms of `stmt_for_command` (src/shir.rs:5185).

When the builtin name ∈ {`local`, `declare`, `typeset`} and the args are
`name=value` declaration forms (no flags), emit

```rust
IrStmt::Declare {
    vars: vec![Decl { name, sigil: None }],   // one Decl per name=value arg
    init: Some(<value expr>),                  // None for bare `local x`
    local: name == "local",
}
```

instead of `IrStmt::Assign` / `Expr(Call exec …)`. Concrete mapping:
- `local x=5` → `Declare { vars:[{name:"x"}], init:Str("5"), local:true }`
- `local x` → `Declare { vars:[{name:"x"}], init:null, local:true }`
- `local a=1 b=2` → one Declare, `vars` len 2, init None
  (multi-target declaration; per the `DeclareArray` precedent, a single
  stmt for the whole arg list)
- `declare x=5` / `typeset x=5` → same with `local:false`

Keep unchanged (the Declare node has no flags/attributes field, so these
would LOSE semantics — do not fold them in):
- flag forms (`declare -i x=5`, `local -i x=5`, `typeset -i t=7`) → stay
  `Expr(Call exec …)` (t82 pins this shape)
- `readonly` / `export` → stay `Assign`/`Call` (the exported/readonly
  attribute is not representable; the runtime `builtin` call carries it)
- the `name=value` standalone-assignment path (`export=foo` is a plain
  variable assignment, per the keyword-rewrite at
  src/parser/commands.rs:295) → untouched

The estree side needs no change: the Declare arm at stmt_to_estree
(~14980) already renders both `local` forms (exec-local lift preserves
scope semantics) and the plain-init form. Serializer/deserializer/schema
already exist.

Corpus constraint (the estree worker mediates): this changes `--shir`
output for declare-family files. The executed-stdout semantics are
preserved for the scoped forms (a Declare{local:true} with literal init
renders to the same native `let`/assignment the current Assign/Call forms
produce — stdout identical). Frontend byte-equality gates (posix-sh-go
and the other shell frontends) will show `DIFF` until each frontend
mirrors the new shape in the same window — the established pattern from
`core-requests/done/posix-sh-go-20260806-174619.md` ("expected, not a
regression"); the posix-sh-go mirror is `main.go`/`lowering.go`'s
declare-family arm (currently always `Assign`/`Call`, mirroring the core).

## FAILING-CASE

Minimal posix-sh-go (shell) snippet — the coverage example this request
unblocks (currently uncreatable):

```sh
local x=5
echo "$x"
```

Today `debashc --shir failing.sh --raw` emits — and the posix-sh-go
frontend must byte-match — no Declare anywhere:

```json
{"type":"Assign","targets":[{"var":"x","sigil":null,"indices":[]}],
 "expr":{"style":"DoubleQuoted","type":"Str","value":"5"}}
```

After the change the A1 must contain (the estree renderer already
consumes this shape):

```json
{"type":"Declare","vars":[{"name":"x","sigil":null}],
 "init":{"style":"DoubleQuoted","type":"Str","value":"5"},"local":true}
```

Repro of the gap itself (no core change needed to see it):
`bash frontends/coverage/coverage-gap.sh posix-sh-go` →
`A1 node Declare` (first line of the actionable list), with
`frontends/posix-sh-go/testdata/t82_declare.sh` present and the gate
green — the example cannot cover the node until this request lands.
