# py-sh-go: A1 contract has no comprehension node — the comp_if filter is inexpressible

## NEED
The A1 expr vocabulary must express Python comprehension **filters** —
grammars-v4 Python3 rule `comp_if` (`'if' test_nocond comp_iter?`), the
optional per-element filter of a comprehension inside `comp_iter`
(`comp_iter : comp_for | comp_if`). A list/set/dict comprehension with a
filter is an EXPRESSION that evaluates to a NEW collection containing
only the elements for which `test_nocond` holds, optionally followed by a
nested `comp_for`/`comp_if` (the recursive `comp_iter?`). The A1 expr
vocabulary (Int, Str, Var, Index, BinOp, Call, MethodCall, Ternary,
DefinedOr, Interpolate, Capture, Regex, Range, RawExpr, Arrow, Array,
Arith, Bool, Json, Ident, Object — per schema.json "exprs" /
shir_json.rs) has no node that carries iterable + loop var + element expr
+ filter predicate and evaluates to a fresh array/assoc:

- `Array` is a STATIC element list; the frontend lowers list literals via
  `Call("setArray"/"setArrayAppend", [name, Array(elems)])` with constant
  elements only.
- `For` is a statement, not an expression — nothing in the expr
  vocabulary runs a loop and yields a value.
- `arrayItems`/`listVar` return an EXISTING array; `Arrow` is a
  zero-parameter thunk used only for ESTree-path pipeline stages.

Proposed shape (identical to the stalled comp_iter request, which
subsumes this rule):

```json
{ "type": "ArrayComp", "var": "x", "iter": <expr>, "elem": <expr>, "cond": <expr|null> }
```

`cond` IS the comp_if clause: evaluated per element, non-matching items
are skipped. (Dict variant via a `kv`/`kind` field and the runtime's
assoc store; set form de-dupes.) A whitelisted helper-call form
`Call("arrayComp", [iter, var, Arrow([...elem-return stmts...]), cond])`
reusing the existing Arrow body-stmt shape is also acceptable.

## WHY
The coverage hook (rules-gap.sh) reports `comp_if` as a Python3 grammar
rule no testdata example exercises (`comp_iter`/`comp_for` are ledgered
core-pending — the same gap; `comp_if` is not, so it is still reported).
No example can be created: the hand-rolled parser in
frontends/py-sh-go/main.go has no comprehension arm — the `[` literal
parser in `parsePrimary` accepts only comma-separated elements
(`expectOp("]")` right after the first element), so `for`/`if` in
comp_iter position always fails loudly:

    $ printf 'x = [i for i in [1, 2, 3, 4] if i > 2]\nprint(x[0])\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: expected "]"
    exit=2

This is NOT a documented by-design subset refusal: py-sh-go has no
FRONTEND.md, the exclusion ledger (frontends/coverage/
refused-py-sh-go.txt) contains no comp_if/comp_iter/comp_for entry, and
PARSER_GAPS.md categorizes `comp_iter`/`comp_for`/`comp_if` as a
contract gap ("generators/async — coroutine semantics, no A1 channel",
category 1: no A1 node — not a subset decision). Every PART of a
filtered comprehension is already expressible — `for` statements over
ListE/Range (t20/t40/t71), list literals (t21/t56/t66), comparisons for
filters (t25/t26) — only the comprehension EXPRESSION node is missing.

Precedent: the identical comp_iter request
(core-requests/done/py-sh-go-comp-iter-20260813-200803.md) reached
done/ only as an auto-stall (3 untouched cycles; the 1-byte `.stall`
marker at 20:24) — the node was never implemented (no ArrayComp /
comprehension anywhere in sh2perl/src/, verified). This request
re-escalates the same gap for the `comp_if` alternative so the estree
worker can implement it.

## MINIMAL-CORE-CHANGE
1. src/ir.rs / src/shir.rs: add the comprehension expr variant, e.g.
   `IrExpr::ArrayComp { var: String, iter: Box<IrExpr>, elem: Box<IrExpr>, cond: Option<Box<IrExpr>> }` (cond = comp_if), serialized as the JSON shape above in src/shir_json.rs with an A3 purity verdict (Emulable — CPU-only array building; mirror `arrayItems`/`setArray` in src/shir_json.rs call_purity + the ingress callee gate).
2. src/estree.rs: render the node as a JS loop building the array —
   iterate `sh2.arrayItems(iter)` (or the range/array forms the runtime
   already iterates), evaluate `elem` per item into the var store, SKIP
   items failing `cond` (the comp_if filter) — so the executed-stdout
   oracle (native python3 vs the transpiled ESTree run) can match.
3. src/shir_json_in.rs: strict ingress accepts the new shape;
   frontends/shir-contract/schema.json gains it (workspace-side, keeps
   check_schema.py green).
4. Nested `comp_iter?` recursion after the filter
   (`[x for x in y if a if b]`, `[x for x in y if c for z in ...]`) and
   the dict/set forms reuse the same node (iter expr evaluates to the
   pair source; the frontend's For stmt already splits list elements for
   pair iteration; dict via the assoc-store convention, set de-dupes).

The frontend side (list/set/dict literal arms: after the first element,
detect `for`/`if` → parse comp_for/comp_if → emit the node; genexp
sole-arg form likewise) is py-sh-go's own fix and lands after the
contract has the node; the coverage worker retries the gap automatically
once this request completes (core-pending-py-sh-go.txt pruning).

## FAILING-CASE
Minimal Python programs (python3 runs both fine):

```python
x = [i for i in [1, 2, 3, 4] if i > 2]
print(x[0])
print(x[1])
```

stdout: `3`, `4` (x = [3, 4] — the comp_if filter).

```python
words = ["a", "bb", "ccc"]
long = [w for w in words if len(w) > 1]
print(long[0])
```

stdout: `bb`.

Today both exit 2 from `./py-sh-go --shir` with `parse: expected "]"`.
