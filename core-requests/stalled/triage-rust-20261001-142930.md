# triage: rust backend can't render what the c-sh-go frontend emits

## NEED
The rust renderer must handle this A1 (the estree reference renders it and
matches native).

## FAILING-CASE
frontend c-sh-go, example t36_dowhile_break.c (cross-product pair).

## EVIDENCE
estree matches native; rust differs

## OUTCOME: rejected: NOT core: the A1 is sound, the defect is in src/rust_backend.rs (the rust worker's file). The estree reference renders this A1 correctly and the sh render agrees with native, so shir.rs/ir.rs/estree.rs are not at fault. rustc rejects the output outright: `error: expected {:?}, found ;` at \`while i < 5; __SH_RC.store(...) {` -- a do-while/while test rendered with a stray `;` instead of a braced block. Handing to the rust backend worker.
Probed this pair directly (c-sh-go emit -> `--target rs` -> rustc):
  `error: expected '{', found ';'` -- the do-while/while TEST is rendered as
    `while i < 5; __SH_RC.store(if __b {0} else {1}, Ordering::SeqCst) {` -- a stray
    `;` where a braced block is required, so the file never compiles. The same shape
    also hoists the loop BODY out of the loop (the `i += 1` / `if (i==3) break` block
    is emitted before the `while`), so even past the syntax error the control flow
    would be wrong.
