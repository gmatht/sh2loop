# fish-sh-go: per-function `local` lift is stubbed — function-local decls leak over outer scope in the ESTree backend

## NEED

The A1→ESTree path must give `local` declarations function-local scope.
Today a `local NAME=VALUE` inside a function body lowers to a plain
module-binding write (`(NAME = value, sh2.lastExit = 0, true)` via
`try_native_declare_stmt`), and the runtime `builtins.local`
(sh2-namespace.mjs) is a plain store write with no scope stack and no
save/restore in `fnCall`. So the local's value leaks out of the
function and clobbers any same-named outer variable — the ESTree
runner's answer differs from bash/fish for an observable shadowing
pattern.

The scaffolding for the intended fix already exists in src/shir.rs but
is dead: `LOCAL_LIFT` (src/shir.rs:70) is never populated,
`FUNCTION_STACK` (src/shir.rs:74) is never pushed/popped, and
`with_func_lift` (src/shir.rs:1681) has no callers. The `LocalLift`
analysis in `src/shir_passes/analysis.rs` is the Stage-0 stub
("Stage 1: migrates the `local_lift_analysis` referenced in shir.rs").
The A1 contract already carries a `Declare { vars, init, local }`
statement (shir_json.rs:103 / shir_json_in.rs:210) — but the ESTree
renderer's `stmt_to_estree` match (src/shir.rs:9193) has no `Declare`
arm (it hits `other => unreachable!("Perl-only IR statement ...")`),
so frontends cannot express a local decl that way either.

## WHY

The fish-sh-go frontend gate failed on `t78_set_local.fish`
(74/75 stdout match):

```fish
function inner
    set -l v 1
    echo "inner=$v"
end
set v 2
inner
echo "outer=$v"
```

Native fish prints `inner=1` / `outer=2`; the transpiled run prints
`inner=1` / `outer=1` — the function-local `v=1` overwrites the
module `v=2`. The fish frontend side is DONE (this session): `set -l`
now emits the core-frontend-identical A1 shape, `exec local ["v=1"]`
(byte-identical to debashc's own bash `local v=1` emission — verified).
The residual DIFF is 100% the core's missing local scope. Note the
identical gap exists for the core's own bash frontend:

```bash
f() { local v=1; echo "inner=$v"; }
v=2
f
echo "outer=$v"
```

native bash → `inner=1`/`outer=2`; `debashc --shir-in-estree` +
estree-runner → `inner=1`/`outer=1`. The 517-example bash corpus never
observes the leak, so it has gone unnoticed; t78 is the first probe
that does.

## MINIMAL-CORE-CHANGE

Reimplement the per-function local lift described by the existing
comments at src/shir.rs:66-76 ("Per-function `local`-variable native
lift: function name → the set of local vars whose declarations (and
every later reference) lower to native `let` bindings inside the
function body ... first decl is a `let`, later ones are assignments")
and src/shir.rs:6471-6496 (the runtime's `local` is a plain store
write, so a lifted native binding re-initialized per call is exactly
the runtime model).

Concretely, all inside src/shir.rs + src/shir_passes/ (no contract
change; `local NAME=VALUE` exec calls are already what both the bash
frontend and the fish frontend emit):

1. **Analysis** (`LocalLift` in src/shir_passes/analysis.rs, or
   populate `LOCAL_LIFT` from shir.rs): for each `Function`, the set
   of names declared by `local`/`declare`/`typeset`/`readonly`
   PURE-VALUE execs (the `pure_value_declare` shape) inside the body,
   restricted to names that are safe to lift: never referenced outside
   the function, never read through runtime strings (the
   `string_ctx`/`excluded` walkers already mark such names
   store-bound — keep them out), no dynamic write anywhere, not
   escaped (the `escapes` set from the lifetime analysis), and no
   recursion/interleaved-call observation (the documented
   SH2_ASSUME_LOCAL_SCOPE assumption, src/shir.rs:6486-6496).
2. **Emission** (`stmt_to_estree`):
   - push/pop `FUNCTION_STACK` around function-body emission;
   - in the `Exec`/`try_native_declare_stmt` path for a lifted name,
     emit the FIRST decl in the body as a native
     `let NAME = value` (`Stmt::VariableDeclaration`, exactly the
     block-scope shadow the runtime model lacks) and later decls as
     plain assignments — `with_func_lift` (src/shir.rs:1681) already
     exists for this;
   - `getVar`/`Assign` on lifted names inside the body already go
     native via `is_lifted` → `is_local_lifted` (src/shir.rs:1661);
     reads outside the function must NOT see the lift (the
     FUNCTION_STACK guard already provides this).
3. **Optional but useful:** an arm for `IrStmt::Declare { local: true }`
   in `stmt_to_estree` mapping to the same first-decl-`let` shape, so
   frontends that use the contract's `Declare` node get scope too.

Verification: `f() { local v=1; echo "inner=$v"; }; v=2; f; echo
"outer=$v"` must print `inner=1`/`outer=2` through
`--shir-in-estree` + estree-runner; `./fail-estree` must stay at the
trusted baseline.


```sh
cd frontends/fish-sh-go
make build
./fish-sh-go --shir testdata/t78_set_local.fish --raw > /tmp/t78.json
../../sh2perl/target/debug/debashc --shir-in-estree /tmp/t78.json > /tmp/t78.e.json
node ../../harness/estree-runner.mjs /tmp/t78.e.json --source testdata/t78_set_local.fish
```
