# py-sh-go: A1 contract has no comprehension node — Python comp_iter is inexpressible

## NEED
The A1 expr vocabulary must express Python **comprehensions** —
grammars-v4 Python3 rules `comp_iter` (`comp_for | comp_if`), the
iterator tail of list/set/dict displays and generator expressions
(`listcomp`, `setcomp`, `dictcomp`, `genexp`, `testlist_comp`,
`dictorsetmaker`, and the `argument` rule's `test comp_for?` sole-arg
generator form). A comprehension is an EXPRESSION that evaluates to a
NEW collection: per-element mapping (`[f(x) for x in coll]`), optional
filtering (`comp_if`: `'if' test_nocond comp_iter?`), dict key/value
forms (`{k: v for ...}`), and nested iterators (the recursive
`comp_iter?`). The A1 expr vocabulary (Int, Str, Var, Index, BinOp,
Call, MethodCall, Ternary, DefinedOr, Interpolate, Capture, Regex,
Range, RawExpr, Arrow, Array, Arith, Bool, Json, Ident, Object — per
schema.json "exprs" / shir_json.rs) has no node that carries
iterable + loop var + element expr (+ optional filter) and evaluates to
a fresh array/assoc:

- `Array` is a STATIC element list; the frontend lowers list literals
  via `Call("setArray"/"setArrayAppend", [name, Array(elems)])` with
  constant elements only.
- `For` is a statement, not an expression — the frontend lowers
  statement loops to `{"type":"For","var":...,"iter":...,"body":...}`;
  nothing in the expr vocabulary runs a loop and yields a value.
- `arrayItems`/`listVar` return an EXISTING array; `Arrow` is a
  zero-parameter thunk used only for ESTree-path pipeline stages
  (`Call("pipeline", ...)`), with no callable return convention.

Proposed shape: a comprehension expr node, e.g.

```json
{ "type": "ArrayComp", "var": "x", "iter": <expr>, "elem": <expr>, "cond": <expr|null> }
```

(plus a dict variant `{..., "kv": true}` or a `kind` field for
list/set/dict — the runtime's assoc store / `declare -A` convention
covers the dict form), OR a whitelisted helper call
`Call("arrayComp", [iter, var, Arrow([...elem-return stmts...]), cond])`
reusing the existing Arrow body-stmt shape. Either way the ESTree
renderer lowers it to a JS loop (or `.map()`/`.filter()`) building the
array; the runtime already iterates arrays (`arrayItems`, forLoop) and
ranges, and the frontend's For stmt already iterates ListE (t20/t40)
and range (t71) — the same iteration semantics carry over.

## WHY
The coverage hook (rules-gap.sh) reports `comp_iter` as a Python3
grammar rule no testdata example exercises. The reason no example
exists: the frontend cannot express it — no lowering path. The
hand-rolled parser in frontends/py-sh-go/main.go has no comprehension
arm: the `[`/`{`/`(` literal parsers in `parsePrimary` accept only
comma-separated elements (`expectOp("]")`/`":"`/`)` right after the
first element), so `for`/`if` in comp_iter position always fails
loudly:

    $ printf 'x = [i for i in range(3)]\nprint(x)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: expected "]"
    exit=2
    $ printf 'd = {k: v for k, v in [("a", 1)]}\nprint(d)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: expected "}"
    exit=2
    $ printf 's = {x for x in [1, 2]}\nprint(s)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: expected ":"
    exit=2
    $ printf 'print(sum(x for x in [1, 2, 3]))\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: expected ")"
    exit=2

This is NOT a documented by-design subset refusal: py-sh-go has no
FRONTEND.md, and the exclusion ledger (frontends/coverage/
refused-py-sh-go.txt — 30 entries: async_funcdef, classdef, match_stmt,
yield_stmt, raise_stmt, ...) contains no comprehension/comp_iter/
comp_for entry (nor does bugs-py-sh-go.txt). Every PART of a
comprehension is already a supported construct — for loops (t20_for_list,
t40_nested_loop, t71_range_loop), list literals (t21/t56/t66), dict
literals (t73_dict), comparisons for comp_if filters (t25/t26) — only
the comprehension EXPRESSION node is missing. This follows the lambdef
(py-sh-go-lambdef-20260813-192707), star_expr
(py-sh-go-star-expr-20260813-193834) and sliceop
(py-sh-go-sliceop-20260813-194705) precedents: inexpressible because
the A1 contract has no node for it, not because the subset refuses it.
(The `comp_if` alternative's `test_nocond` sub-rule rides along on the
same node; test_nocond is separately core-pending via earlier
requests.)

## MINIMAL-CORE-CHANGE
1. src/ir.rs / src/shir.rs: add the comprehension expr variant (e.g.
   `IrExpr::ArrayComp { var: String, iter: Box<IrExpr>, elem: Box<IrExpr>, cond: Option<Box<IrExpr>> }`, or the `arrayComp` helper-call form reusing Arrow), serialized as the JSON shape above in src/shir_json.rs with an A3 purity verdict (Emulable — CPU-only array building; mirror `arrayItems`/`setArray` in src/shir_json.rs call_purity + the ingress callee gate).
2. src/estree.rs: render the node as a JS loop building the array —
   iterate `sh2.arrayItems(iter)` (or the range/array forms the
   runtime already iterates), evaluate `elem` per item into the var
   store, skip items failing `cond` — so the executed-stdout oracle
   (native python3 vs the transpiled ESTree run) can match; dict form
   builds the runtime's assoc object, set form de-dupes.
3. src/shir_json_in.rs: strict ingress accepts the new shape;
   frontends/shir-contract/schema.json gains it (workspace-side, keeps
   check_schema.py green).
4. Nested `comp_iter?` recursion and multi-var `exprlist` targets
   (`for x, y in pairs`) reuse the same node (iter expr evaluates to
   the pair source; the frontend's For stmt already splits list
   elements for pair iteration).

The frontend side (list/set/dict literal arms: after the first element,
detect `for`/`if` → parse comp_for/comp_if → emit the node; genexp
sole-arg form likewise) is py-sh-go's own fix and lands after the
contract has the node; the coverage worker retries the gap
automatically once this request completes (core-pending-py-sh-go.txt
pruning).

## FAILING-CASE
Minimal Python programs (python3 runs all three fine):

```python
x = [i * 2 for i in [1, 2, 3]]
print(x[1])
```

stdout: `4` (x = [2, 4, 6]).

```python
x = [i for i in [1, 2, 3, 4] if i > 2]
print(x[0])
print(x[1])
```

stdout: `3`, `4` (x = [3, 4] — the comp_if filter).

```python
d = {k: len(k) for k in ["a", "bb"]}
print(d["bb"])
```

stdout: `2` (dict comprehension keyed by string; the v1 dict subset
lowering `d["bb"]` already covers the read side — t73_dict).

Current behavior: `./py-sh-go --shir` fails with
`py-sh-go: parse: expected "]"` (listcomp), `"}"` (dictcomp/setcomp),
`":"` (setcomp), or `")"` (genexp), exit 2 — so no testdata example can
cover `comp_iter`, and the A1 contract is missing the comprehension
node end-to-end (frontend emit → ingress acceptance → ESTree run vs
native python3 stdout).
