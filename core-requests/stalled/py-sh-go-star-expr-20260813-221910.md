# py-sh-go: A1 contract has no starred-expression shape — Python star_expr is inexpressible

## NEED
The A1 expr vocabulary must express Python **starred expressions**
(grammars-v4 Python3 rule `star_expr`: `'*' expr`), which appear in
`testlist_star_expr` (assignment targets/RHS), `testlist_comp` (list
displays), `exprlist` (for-loop targets), and `dictorsetmaker` (set
displays). Two shapes are missing:

1. **Array-valued subrange expression** — so a starred assignment
   target (`x, *rest = a`) can bind "the rest of the array". The
   existing `param("slice", arr, off, len)` (bash `${arr[@]:off:len}`)
   joins to a **scalar string** except the whole-array `@`/`*` forms
   (src/shir.rs `exec_arg_is_array_valued`, line ~16941: only `@`/`*`
   offset forms are array-valued); there is no array-valued dynamic
   subrange usable as an `Array` element / `setArray` item.
2. **Splice marker on `Array` elements** (and, for the sibling
   `argument` rule's `'*' test` alternative, on `Call` args) — so
   `b = [*a]` / `[1, *a]` / `f(*a)` can splice an array's elements
   into a literal/call instead of nesting the array as one element.

The ESTree renderer already emits `[].concat(...)` for non-scalar
`setArray` items (src/estree.rs `is_scalar_array_item`, ~line 1691;
the runtime's setArray splices native-JS-array elements with
`out.push(...e)`) — so an array-valued slice call used as an `Array`
element would splice end-to-end once the runtime returns an array for
the offset form.

## WHY
The coverage hook (rules-gap.sh) reports `star_expr` as a Python3
grammar rule no testdata example exercises (verified 2026-08-13:
`bash frontends/coverage/rules-gap.sh py-sh-go` lists star_expr
first). The reason no example exists: the frontend cannot express it —
no lowering path. The hand-rolled parser in frontends/py-sh-go/main.go
has no `*` case: `parseUnary` handles only `-`/`+` (line ~1228),
`parsePrimary` has no `*` arm, and `parseExprStmt`'s target loop
accepts only `NAME (, NAME)*` (line ~900), so every star_expr form
fails loudly (verified against the built `./py-sh-go --shir`):

    $ printf 'a = [1, 2, 3]\nb = [*a]\nprint(len(b))\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: unexpected token "*"
    exit=2
    $ printf 'a = [1, 2, 3]\nx, *rest = a\nprint(x)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: bad assignment target
    exit=2
    $ printf 'def f(*a):\n    print(a)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: def f: bad param
    exit=2
    $ printf 'for x, *y in [[1, 2]]:\n    print(x)\n' | ./py-sh-go --shir /dev/stdin --raw
    py-sh-go: parse: for: expected in
    exit=2

This is NOT a documented by-design subset refusal: py-sh-go has no
FRONTEND.md, and the exclusion ledger (frontends/coverage/
refused-py-sh-go.txt) lists per-rule refusals precisely — it contains
`star_named_expression`/`star_named_expressions` (the DISTINCT match-
statement rules, refused via `match_stmt`) but NOT `star_expr`, and
PARSER_GAPS.md's py-sh-go table lists it among the requestable
A1-extension rows (no type system / fnCall positional model doesn't
splat). The four contexts the rule appears in are all supported
constructs — tuple assignment (t47_multi_assign), list literals
(t21/t56/t66), for loops (t20/t71), dict literals (t73) — only the
starred-expansion semantic is missing. The frontend's pattern is to
lower every supported Python construct onto its shIR counterpart
(if→If, while→While, for→For, dict→assoc setArray after core request
py-sh-go-20260813-145247); star_expr follows the lambdef precedent
(py-sh-go-lambdef-20260813-192707/220859): inexpressible because the
A1 contract has no node/field for it, not because the subset refuses
it.

Precedent: this exact request was filed before as
core-requests/done/py-sh-go-star-expr-20260813-193834.md, but it
auto-stalled (3 untouched cycles, `.stall` marker) and was archived
without the node landing — verified: no `Splice`/starred shape
anywhere in sh2perl/src/ today (grep over src/shir.rs, src/ir.rs,
src/shir_json.rs, src/shir_json_in.rs), and the frontends/shir-contract/
schema.json "exprs" vocabulary (Arith, Array, Arrow, BinOp, Bool, Call,
Capture, DefinedOr, Ident, Index, Int, Interpolate, Json, MethodCall,
Object, Range, RawExpr, Regex, Str, Ternary, Var) has no starred node.
The archive pruned core-pending-py-sh-go.txt, so rules-gap.sh
re-surfaced the gap; this request re-escalates it.

## MINIMAL-CORE-CHANGE
1. **Array-valued subrange**: extend the `param("slice", name, off[, len])`
   runtime contract so the offset form (start without/with length)
   returns a native JS **array** of the remaining elements when used in
   array/setArray position (whole-array `@`/`*` behavior unchanged;
   scalar-join stays for exec-arg string contexts), OR add a new
   whitelisted helper (e.g. `param("rest", name, start)`) returning an
   array. Follow the existing `arrayItems`/`listVar`/`split`/
   captureWords array-valued conventions. Purity/emulation tables in
   src/shir_json.rs (helper whitelist ~line 484) + the ingress callee
   gate must accept it.
2. **Splice marker**: add an optional marker on `Array` elements
   (e.g. `{"type":"Array","elements":[...],"splice":[i,...]}` or a
   `{"type":"Splice","expr":...}` element wrapper; keep existing emits
   byte-identical when absent) so `[*a]`/`[1, *a]` lower to a spliced
   literal; renderer + runner already concat-splice array-valued
   items (estree.rs `is_scalar_array_item`). For `Call` args (the
   sibling `argument` rule `'*' test`), the same marker on the `args`
   array covers `f(*a)`.
3. **Ingress + contract**: shir_json_in.rs deserializer accepts the new
   shape; frontends/shir-contract/schema.json gains it (workspace-side,
   keeps check_schema.py green).
4. **Starred targets**: the frontend lowers `x, *rest = a` as Assigns
   (`x = arrayIndex(a, 0)`; `rest = setArray` from the array-valued
   rest slice) — no new stmt node needed once (1) exists; the for-target
   form (`for x, *rest in ...`) uses the same split per iteration.

The frontend side (exprParser `*` case in unary/primary + starred
targets in parseExprStmt/parseFor → emit the shapes above) is
py-sh-go's own fix and lands after the contract has the shape; the
coverage worker retries the gap automatically once this request
completes (core-pending-py-sh-go.txt re-entry + pruning cycle).

## FAILING-CASE
Minimal Python programs (python3 runs both fine):

```python
a = [1, 2, 3]
x, *rest = a
print(x)
print(len(rest))
print(rest[1])
```

stdout: `1`, `2`, `3` (x=1, rest=[2,3], rest[1]=3).

```python
a = [1, 2]
b = [*a]
print(len(b))
```

stdout: `2` (b is a 2-element copy of a).

Current behavior: `./py-sh-go --shir` fails with
`py-sh-go: parse: unexpected token "*"` (list display) or
`py-sh-go: parse: bad assignment target` (starred target), exit 2 —
so no testdata example can cover `star_expr`, and the A1 contract is
missing the shape end-to-end (frontend emit → ingress acceptance →
ESTree run vs native python3 stdout).
