# fish-sh-go: the A1 `Regex` expr node is Perl-only in the ESTree renderer — fish `string match -r` (regex matching) is inexpressible end-to-end

## NEED

`expr_to_estree` in src/shir.rs must render `IrExpr::Regex { pattern, flags }`
instead of falling into the terminal
`other => unreachable!("Perl-only IR expression reached the ESTree renderer: {other:?}")`
(src/shir.rs:30020). The missing arm is exactly one line:

```rust
IrExpr::Regex { pattern, flags } => regex_lit_flags(pattern, flags),
```

`regex_lit_flags` already exists at src/estree.rs:2599 (`pub(crate)`) and
builds precisely the ESTree shape the bash `=~` / case-glob lowerings use —
a `Literal` with the `regex: { pattern, flags }` property. estree-gen.mjs
already prints that shape (`/pattern/flags`, regex-hygiene pass at
estree-gen.mjs:103-114) and the runner executes it as a native JS RegExp,
so NO runner change is needed: a rendered regex literal in expression
position already works (the bash `=~` family proves the whole pipeline;
the runtime's `evalTest` `=~` case is `new RegExp(r).test(l)` at
harness/sh2-namespace.mjs:7209).

No contract/schema change is needed: `"Regex"` is already in the A1
vocabulary (frontends/shir-contract/schema.json exprs; the coverage-gap
detector lists it as a gap precisely because the node round-trips) —
serialized by shir_json.rs:360, deserialized by shir_json_in.rs:837, and
rendered by the Perl backend (perl_backend.rs:416 → `/pattern/flags`).
Only the ESTree renderer lacks the arm, mirroring the
powershell-sh-go-20260813-160115 value-comparison BinOp request (same
terminal `unreachable!` arm; implemented by the estree worker).

## WHY

The coverage hook reports `A1 node Regex` — no fish-sh-go testdata example
exercises the node. The reason no example exists: the frontend cannot
express fish regex matching end-to-end, and the blocker is the shared core.

Fish's regex-matching construct is `string match -r PAT STR...`
(status-returning: prints the match and exits 0 if any STR matches;
verified natively on fish 3.7.0). This is a real, common fish idiom, and
the frontend already treats regex as in-scope: `string replace -r` (the
regex replace sibling) IS lowered (fish-sh-go.go:1849-1850). `string
match` is merely unlanded — the parser handles `if string match -r ...`
fine and today emits a generic `exec string match -r ...` call (no
Regex node). This is NOT a by-design subset refusal: FRONTEND.md
excludes nothing regex-related, the frontend never refuses the construct,
and the natural lowering emits the A1 `Regex` node.

But the gate cannot consume any such emit today:

1. Ingress acceptance (`make test` runs `debashc --shir-in-estree` on
   every emit) PANICS — exit 101 — on any valid-A1 program whose IR
   contains a Regex node:
   `internal error: entered unreachable code: Perl-only IR expression
   reached the ESTree renderer: Regex { pattern: "^[0-9]+$", flags: "" }`
   (src/shir.rs:30020, reproduced below).
2. The executed-stdout oracle (harness/frontend-stdout.sh) therefore
   cannot run a regex-matching program at all.

## MINIMAL-CORE-CHANGE

One arm in `expr_to_estree` (src/shir.rs, inserted before the terminal
`other => unreachable!` at line 30020):

```rust
IrExpr::Regex { pattern, flags } => regex_lit_flags(pattern, flags),
```

(`regex_lit_flags` is `pub(crate)` in src/estree.rs:2599, same crate —
no visibility change needed. It produces
`Expr::Literal { value: {}, raw: None, regex: Some(RegexLiteral { pattern, flags }) }`,
the exact shape the bash `=~` RHS lowerings already emit, so the
generated JS `/pattern/flags` executes natively.)

## FAILING-CASE

`frontends/fish-sh-go/testdata/` (no example can land while the arm is
missing). The construct the frontend would express:

```fish
set x "hello 42 world"
if string match -r '[0-9]+' $x
    echo matched
else
    echo no-match
end
```

Expected stdout (native fish 3.7.0, verified):

```
42
matched
```

Current behavior:

1. Frontend parses and emits (exit 0) but as a generic exec call — the
   A1 JSON contains no `"Regex"` node, so the construct is not
   expressible in the contract's regex vocabulary:
   ```
   ./fish-sh-go --shir t_regex.fish --raw
   # → Expr(exec string match -r '[0-9]+' getVar(x))  — no Regex node
   ```
2. Any A1 program that DOES carry the node fails ingress:
   ```
   printf '%s' '{"contract_version":1,"imports":[],"requires":[],"stmts":[{"expr":{"args":[{"type":"Regex","pattern":"^[0-9]+$","flags":""}],"func":"echo","purity":"PureCpu","type":"Call"},"type":"Expr"}],"subs":[],"type":"Program","var_types":[]}' > /tmp/regex-a1.json
   debashc --shir-in-estree /tmp/regex-a1.json
   # → exit 101: internal error: entered unreachable code:
   #   Perl-only IR expression reached the ESTree renderer:
   #   Regex { pattern: "^[0-9]+$", flags: "" }  (src/shir.rs:30020)
   ```

Once the arm lands, the fish-sh-go worker can lower `string match -r`
to an A1 form carrying the Regex node (its own design decision — e.g. a
test expression / call arg the runner's regex-literal support executes)
and land the testdata example that closes the gap.

## OUTCOME: implemented
The `IrExpr::Regex { pattern, flags } => regex_lit_flags(pattern, flags)` arm landed in `expr_to_estree` (commit f05a1c2; src/shir.rs:33294, before the terminal `other => unreachable!`). Verified this round: an A1 program carrying a `Regex` node ingresses via `debashc --shir-in-estree` with no panic (exit 0), and `[[ $x =~ ^[a-z]+[0-9]+$ ]]` renders `/pattern/flags` + executes natively. estree 546/546 at baseline. Fish/`string match -r` lowering + testdata example remain the fish-sh-go frontend worker's emit-side work.
