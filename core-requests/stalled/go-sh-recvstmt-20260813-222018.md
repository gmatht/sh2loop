# go-sh: A1 contract has no channel receive — Go recvStmt is inexpressible

## NEED
The A1 contract must gain a **channel receive** vocabulary so the go-sh
frontend can lower Go's receive statement (grammars-v4 golang rule
`recvStmt`:

    recvStmt
        : (expressionList ASSIGN | identifierList DECLARE_ASSIGN)? recvExpr = expression
        ;

i.e. `v := <-ch` / `v = <-ch` / bare `<-ch`). Concretely, alongside the
already-requested select/comm-clause shape (umbrella request:
`core-requests/go-sh-commclause-20260813-204112.md`, which names
`recvStmt` in its NEED but is ledgered only for the `commClause` gap —
this request is the ledger-able handle for `recvStmt` itself):

1. a channel value type + creator, following the A1's whitelisted-helper
   convention (`Call` with `purity:"Emulable"`), e.g.
   `Call{func:"sh2.makeChan"}` returning a runtime FIFO (the ESTree
   runtime can back it with an array);
2. `Call{func:"sh2.recv", args:[ch]}` — blocking receive, the target of
   `recvExpr`; the `identifierList DECLARE_ASSIGN` / `expressionList
   ASSIGN` prefix form additionally Assigns the received value to the
   target var(s) (e.g. `v := <-ch` lowers to
   `Assign{name:"v", value:Call{func:"sh2.recv", args:[ch]}}`);
3. a **`Select`** node (sibling of `Case`/`If` in src/ir.rs + the A1
   serialization in shir_json.rs / shir_json_in.rs) whose comm clauses
   carry `comm:"recv"` with the channel expr, an optional target var,
   and a body of statements — `{type:"Select", clauses:[{comm:"recv",
   target:"v", ch:{...}, body:[...]}, {comm:"default", body:[...]}]}` —
   which the ESTree renderer lowers to a round-robin non-blocking poll
   of the channel FIFOs (bash has no native select-on-channels; the
   runtime emulates the semantics). `recvStmt` appears in the grammar
   ONLY as a `commCase` clause (`CASE (sendStmt | recvStmt)`), so the
   `Select` node is the only context the recv form needs.

## WHY
The coverage hook (`rules-gap.sh go-sh`) reports `recvStmt` as a golang
grammar rule no testdata example exercises. No example can exist: the
frontend cannot express it — there is no lowering path and the A1 has no
target shape. The hand-rolled parser in frontends/go-sh/go-sh.go has no
`select` statement case in `parseStmt` (only if/for/switch/return/go/
var), the lexer has no `<-` operator (`multiOps` = `:= == != <= >= && ||
+= ++` only), and `chan`/`make(chan ...)` are not understood, so any
receive program fails loudly (exit 2):

    $ printf 'package main\nfunc main() {\n\tch := make(chan int)\n\tselect {\n\tcase v := <-ch:\n\t\tprintln(v)\n\tdefault:\n\t\tprintln("none")\n\t}\n}\n' \
      | ./go-sh --shir /dev/stdin --raw
    go-sh: line 3: unexpected token "int" after expression
    exit=2

    $ printf 'package main\nfunc main() {\n\tx := <-ch\n}\n' \
      | ./go-sh --shir /dev/stdin --raw
    go-sh: line 3: unexpected token "<" in expression
    exit=2

This is NOT a by-design subset refusal: go-sh's FRONTEND.md lists no
channel exclusion, and PARSER_GAPS.md classifies the whole cluster
(`selectStmt`/`commClause`/`commCase`/`recvStmt`/`sendStmt`/`goStmt`/
`channelType`) as category-1 A1-EXTENSION — "goroutines/channels/select
are process-model semantics; the A1's `Background` is shell
backgrounding, unrelated" — explicitly making Go's receive/select
*requestable* A1 extensions, not dead ends. The A1's `Background`
(fire-and-forget subshell + `wait`, used by `go func(){...}()` in
t44_background.go) is shell backgrounding and unrelated to channel
rendezvous, so no existing node/field can carry recv semantics. (The
worker ledger refused-go-sh.txt does contain `selectStmt`/`sendStmt`
from an earlier cycle — that is why rules-gap.sh surfaced `recvStmt`
instead — but `recvStmt` itself was never ledgered, and the ledger's
core-pending mechanism exists precisely to prune escalated gaps once the
contract has them, so the gap is retried.) This follows the py-sh-go
sliceop / lambdef / star-expr precedents: inexpressible because the A1
contract has no node/field, not because the subset refuses it
(PARSER_GAPS.md categories the whole cluster as category-1
A1-extension).

## MINIMAL-CORE-CHANGE
1. src/shir.rs / src/ir.rs: add the `Select` stmt node
   (`{type:"Select", clauses:[...]}` — clause = comm kind (`"recv"`),
   channel expr, optional target var, body), and whitelist
   `sh2.makeChan` / `sh2.recv` in the emulable-helper table alongside
   the existing `sh2.*`/`param(...)` helpers. No change to existing node
   shapes, so current emits stay byte-identical.
2. src/shir_json.rs / src/shir_json_in.rs: serialize/accept the new
   node + helpers in the strict ingress deserializer (mirror the
   `Case`/`Background` handling); frontends/shir-contract/schema.json
   gains them (workspace-side, keeps check_schema.py green).
3. src/estree.rs: render `Select` as a non-blocking round-robin poll
   over the channel FIFOs (recv: shift-or-block on empty; default: run
   when no clause is ready), and back `sh2.makeChan` with an array value
   so `recv`/`send`/`Background` interaction works.

The frontend side (lexer: `<-` operator; parser: `select { case v :=
<-ch: … default: … }` → `Select` with a recv clause; `v := <-ch` /
`<-ch` → Assign/expr with `sh2.recv`) is go-sh's own fix and lands after
the contract has the shape; the coverage worker retries the gap
automatically once this request completes. Overlaps the pending umbrella
request `go-sh-commclause-20260813-204112.md` (same `Select` node, plus
send/commClause/channelType) — mediation may implement both together;
this file exists so `recvStmt` gets its own ledger mapping and stops
re-surfacing in rules-gap.sh.

## FAILING-CASE
Minimal Go program (valid Go; `go run` blocks on the recv unless a
sender runs — with a default clause it prints `none` and exits 0):

```go
package main
func main() {
	ch := make(chan int)
	select {
	case v := <-ch:
		fmt.Println(v)
	default:
		fmt.Println("none")
	}
}
```

stdout: `none`.

Current behavior: `./go-sh --shir` fails at the channel creator
itself — `go-sh: line 3: unexpected token "int" after expression`
(exit 2) — and even with the make removed, the `select` keyword is
not a recognized statement start and the `<-` operator is not lexed
(`go-sh: line 3: unexpected token "<" in expression`, exit 2). So no
testdata example can cover `recvStmt`, and the A1 contract lacks the
channel-receive shape end-to-end (frontend emit → ingress acceptance →
ESTree run vs native go stdout). A bare form is equally unexpressible:
`x := <-ch` chokes on the unlexed `<-`.
