# posix-sh-go: WIP of estree-20260814-020001 (uncommitted M src/shir.rs) strips A1 `var_types` verdicts — vars read via mixed quoted Interpolates vanish from the contract output

## NEED

The in-flight implementation of core request `estree-20260814-020001-lift-interpolate-arg-desync`
(currently UNCOMMITTED in `src/shir.rs`, mtime 14:08:27) regresses the A1 contract:
`debashc --shir FILE --raw` now emits `var_types: []`-style verdicts for any program
whose var is read inside a MIXED quoted interpolate (`echo "x is $x"`, `echo "hello $NAME"`).
The committed core (HEAD) emits the full verdicts. The A2 `var_types` verdicts must keep
covering every assigned var; the 020001 lift-exclusion (marking such vars store-read) must
not remove verdicts from the A1 JSON that all frontends reproduce byte-for-byte.

## WHY

`analyze_var_types` (shir.rs:4247) computes `var_types` as the UNION of
`numeric_lift_vars` + `string_lift_vars`. The 020001 WIP adds an `IrExpr::Interpolate`
arm to BOTH walkers' string-context marking (`mark_str_args` in numeric_lift_vars,
`lift_mark_str_args` in string_lift_vars): a `getVar`/`$ref` inside an Interpolate inserts
the name into `string_ctx`. Both lifts' fixpoint loops then `continue` on
`string_ctx.contains(name)` — so a var read via a mixed quoted interpolate is excluded
from the NUMERIC lift AND the STRING lift, and `analyze_var_types` emits NO verdict for it.
Before the WIP, the same var was lifted (numeric if provably int, else string) and got a
verdict; the frontends (ports of the core frontend) were byte-identical.

Evidence (2026-08-14 14:10–14:15, this invocation):

| program | HEAD (committed) `var_types` | WIP (current binary) `var_types` |
|---|---|---|
| `x=42; echo "x is $x"` | `[{"name":"x","type":"Int"}]` | `[]` |
| `NAME=world; echo "hello $NAME"` | `[{"name":"NAME","type":"Str"}]` | `[]` |
| `x=42; echo $x` | `[{"name":"x","type":"Int"}]` | `[{"name":"x","type":"Int"}]` |
| `x=42; echo "$x"` | `[{"name":"x","type":"Int"}]` | `[{"name":"x","type":"Int"}]` |
| `x=42; [ "$x" = foo ]` | `[{"name":"x","type":"Int"}]` | `[{"name":"x","type":"Int"}]` |

(The single-var `"$x"` word lowers to a bare `getVar` call, not an Interpolate — only
MIXED interpolates (`lit` + `expr` parts) trigger the new marking. A program with no
Interpolate-read vars at all is unaffected — `var_types` stays populated, which is why
`t02_assign_str.sh` etc. still pass.)

## MINIMAL-CORE-CHANGE

Keep the 020001 lift-exclusion for the ESTree LOWERING (interpolate-read vars must stay
store-bound — that is the desync fix), but restore the A1 contract verdicts. Two
concrete options, in preference order:

1. **Decouple the A2 verdicts from liftability (restores byte-identity with HEAD).**
   `analyze_var_types` must see the PRE-020001 string_ctx (no Interpolate marking):
   thread a `mark_interpolate: bool` flag through `mark_str_args`/`lift_mark_str_args`
   (or the walkers), passing `false` from `analyze_var_types` and `true` from the
   lowering-side lift call sites. Verdict output then matches the committed contract
   exactly; no frontend change needed anywhere.
2. **Complete-verdict rule.** Make `analyze_var_types` emit a conservative `Str` verdict
   for every assigned name that neither lift lifted (the currently-dropped set), so the
   field stays complete. NOTE: this CHANGES the A1 vs HEAD for the affected names
   (`x=42; echo "x is $x"` would become `x:Str` instead of `x:Int`), so every frontend
   must re-sync its port — a bigger wave; only choose this if the typed lowering
   genuinely wants Str (store-bound) for these names.

If neither lands, the fallback that at least unblocks gates: do NOT leave the WIP in the
working tree while the gate's debashc is rebuilt from it — the stash path (corpus
regression) already reverts it; the regression is visible only because the binary was
built from uncommitted WIP (14:08:46) and `./fail-estree` currently runs against it.
