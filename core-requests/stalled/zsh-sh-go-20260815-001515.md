# zsh-sh-go: RE-OPEN — A1 contract still has no node/field for zsh parameter-expansion flag SEPARATORS (ts node `separator`)

Re-activates `core-requests/done/zsh-sh-go-20260814-193615.md` (the
`separator` node), which sits in `done/` but is UNIMPLEMENTED: verified
2026-08-15 against the current `frontends/zsh-sh-go/zsh-sh-go` +
`target/debug/debashc` — `arr=(a b c); echo "${(j:,:)arr}"` still lowers
to `param("", "(j:,:)arr")` (flag + separator absorbed into the variable
name) and the executed-stdout oracle prints "" vs native zsh's "a,b,c".
The estree poller does not re-read `done/`, so the gap would otherwise
go silent. Companion: `core-requests/zsh-sh-go-20260815-000728.md`
(pending; the `flag` node, same syntax family, one code change).

## NEED

The A1 contract needs a representation for the zsh parameter-expansion
flag SEPARATOR: the single character between `:`…`:` or `.`…`.` inside a
`(flags)` prefix, i.e. the `separator` alias node in the vendored
tree-sitter-zsh grammar (`src/grammar.json`, rule `flag`:
`( flag_name [:sep:] | [.sep.] )`; node-types.json lists `separator`
only as a child of `flag`, alongside `flag_name`). It appears in
exactly two syntactic slots, both currently mis-tokenized by the core's
bash-shaped parser:

- expansion body: `${(j:,:)arr}` (join with `,`), `${(s:,:)x}` (split on
  `,`), `${(p:sep:)x}` (print with separator) — the flag prefix is
  absorbed into the variable name → `param("", "(j:,:)arr")` →
  `getVar("(j:,:)arr")` → unset → empty;
- subscript search flags: `${arr[(i)pat]}` / `[(I)]` / `[(k)]` / `[(r)]`
  — same absorption into the subscript text.

## WHY

The zsh-sh-go coverage step (ts-node-gap.sh, tree-sitter node-type
truth) reports `ts node separator` uncovered, but NO testdata example
can pass the executed-stdout oracle: for any non-empty parameter the
native zsh output diverges. Re-verified end-to-end 2026-08-15 with the
current binaries:

```console
$ cat /tmp/zsep.zsh
arr=(a b c)
echo "${(j:,:)arr}"
$ zsh /tmp/zsep.zsh
a,b,c
$ frontends/zsh-sh-go/zsh-sh-go --shir /tmp/zsep.zsh --raw
# {"func":"param",...,"args":[{"value":""},{"value":"(j:,:)arr"}]}
# — flag+separator absorbed into the name; getVar returns ""
```

Only an UNSET/EMPTY parameter coincides (both sides empty) — a
degenerate corner that would enshrine the mis-tokenization as "covered"
(a passing test hiding a lowering gap, which the project forbids
blessing), not exercise the construct. The A1 `param` node has no
contract-defined slot for a flag/separator prefix, so the runner cannot
legitimately interpret `"(j:,:)arr"` as a name either.

## MINIMAL-CORE-CHANGE

Same change as `zsh-sh-go-20260815-000728.md` — in `src/parser/` (the
braced-expansion chain, `parse_variable_expansion` /
`parse_parameter_expansion_content`): recognize the zsh flag prefix
`(flag_name)` and its separator spellings `(flag_name:sep:)` /
`(flag_name.sep.)` immediately after `${` (and inside subscripts:
`${arr[(i)pat]}` keeps the flag in the subscript text), split it off
the variable name, and carry it as an extra `param` arg so the
serialized A1 round-trips it, e.g.:

    param("", "x", "f")           # ${(f)x}
    param("", "x", "s", ",")      # ${(s:,:)x}
    param("", "arr", "j", ",")    # ${(j:,:)arr}
    param("", "arr", "i", "pat")  # ${arr[(i)pat]}

(concrete arg layout open to the estree worker; must round-trip
shir_json.rs / shir_json_in.rs). Real bash rejects `${(...)` ("bad
substitution"), so no bash-corpus file can collide with the new shape.
Then map it in `src/estree.rs` to a runner helper in
harness/sh2-namespace.mjs (zsh mode) implementing at least `s:`, `j:`,
`p:` with the separator, plus the subscript search flags `i`/`I`/`k`/`r`
against the existing vars/arrays/assoc stores. The zsh-sh-go frontend
follows once the core emits the new shape (its byte-equality oracle
tracks the core; subscript spellings are already waiver-eligible via
harness/zsh-subscript.ere).
