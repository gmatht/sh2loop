# sh: parser drops the >| clobber flag (parse-redirect-clobber red)

## NEED
The parser must preserve the `RedirectOutClobber` operator through the
shIR so the renderers can distinguish `>` from `>|`.

## WHY
`parse-redirect-clobber.sh` is `set -C; : >| "$tmpf"` — with noclobber
set, plain `>` fails ("cannot create ... File exists") while `>|`
truncates. The sh backend renders POSIX sh where the difference is
observable (dash supports both `set -C` and `>|`). Currently the gate
is RED for this file: the render runs but exits 2.

## MINIMAL-CORE-CHANGE
In src/parser/redirects.rs, `parse_redirect_header` maps
`Token::RedirectOutClobber => RedirectOperator::Output` ("Use Output as
fallback") — the clobber bit is dropped at parse time. Add a
`RedirectOperator::ClobberOutput` variant (or a bool field on the
Redirect), carry it through to the A1 JSON (the redirect mode string:
`"clobber"` alongside `"w"`/`"a"`), and update shir.rs / shir_json_in.rs
to accept it. The estree backend can treat it as plain Output; only the
mode string needs to survive.

## FAILING-CASE
```sh
#!/bin/sh
set -C
tmpf=$(mktemp /tmp/clobber_test.XXXXXX)
: >| "$tmpf"
printf 'clobber file exists=%s\n' "$([ -f "$tmpf" ] && echo yes || echo no)"
rm -f "$tmpf"
```
The core's --shir emits `{"mode":"w",...}` for the `>|`; the sh backend
then renders `: >"$tmpf"` which fails under `set -C`.
