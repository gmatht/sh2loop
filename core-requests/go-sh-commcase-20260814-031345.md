# go-sh: A1 lacks a channel/select node — selectStmt/commClause/commCase inexpressible

## NEED
A shIR node for Go's `select` statement (ANTLR golang rules
`selectStmt`/`commClause`/`commCase` — the communication-case construct:
non-deterministic choice among channel send/receive clauses, plus the
`default` clause), and the channel value model it operates on. The
go-sh frontend can already lower `go func(){}()` (→ `Background`) and
`switch`/type-switch (→ `Case`), but it has no target for `select`: the
A1 has no channel type, no send/recv expression, and no
choice-among-clauses statement.

Minimal node cluster:

- `Select` stmt: `{ "type": "Select", "clauses": [ <clause>... ] }`
  where each clause is
  `{ "op": "recv"|"send", "channel": <expr>, "var": "<name>"?, "value": <expr>?, "body": [ <stmt>... ] }`
  (recv: `case v := <-ch:` → `var` bound to the received value; send:
  `case ch <- x:` → `value`; the `default` clause is `{ "op": "default", "body": [...] }`).
  Mirrors the existing `Case` node's clause/body shape so go-sh's
  switch lowering machinery extends naturally.
- Channel runtime seam: a `sh2.channel` builtin (make/send/recv) or a
  FIFO-file based emulation in the estree runtime, so the
  executed-stdout oracle can run a real select. A `default`-only select
  needs no runtime construct (lowers to its body as a plain block), but
  a select with channel clauses is dead code without the seam.

## WHY
The go-sh v2 subset (go-sh.go header, t81_channel_type.go) documents
that "sends/receives/select (sendStmt, recvStmt, selectStmt) stay
refused" — the frontend REFUSES, so no testdata example can exercise
the `commCase` grammar rule, and PARSER_GAPS.md records the whole
goroutines/channels/select cluster as category 1 (A1-EXTENSION): the
A1's `Background` is shell backgrounding, semantically unrelated to Go
channels. This is a genuine A1-contract gap, not a deliberate subset
refusal: if shIR had a channel/select node, go-sh could express it.
(A previous placeholder `core-requests/go-sh-commcase-20260813-225432.md.stall`
contains only the byte "2" and was never implemented; this is the
structured replacement.)

## MINIMAL-CORE-CHANGE
1. `src/shir.rs` + `src/shir_json.rs` (A1 contract): add
   `IrStmt::Select(clauses)` with the serialization shape above
   (`"type": "Select"`), alongside the existing `Case` node; add the
   channel expression forms (or model channels as strings holding a
   FIFO path, avoiding new expr nodes — the go-sh frontend then lowers
   `make(chan T)`/`<-ch`/`ch <- x` to `Call`s on a `sh2.channel`
   builtin, and `Select` stays the only new stmt node).
2. `src/estree.rs` + runtime: implement `sh2.channel` make/send/recv
   (e.g. FIFO-backed) and the `Select` execution semantics
   (blocking choice among ready clauses, `default` runs when none
   ready), so the executed-stdout oracle can verify.
3. `src/parser/` (shell side): no change required — `select` in shell
   is a different construct and already parses.

## FAILING-CASE
```go
package main

import "fmt"

func main() {
	ch := make(chan int)
	select {
	case v := <-ch:
		fmt.Println(v)
	default:
		fmt.Println("d")
	}
}
```
Current behavior (frontends/go-sh, `./go-sh --shir <file> --raw`):
`go-sh: line 4: unexpected token "int" after expression` (rc=2) — no
channel model. Even a default-only select refuses:
```go
select {
default:
	fmt.Println("d")
}
```
→ `go-sh: line 4: expected assignment operator, got "{"` — no `select`
keyword/token in the frontend at all.

## OUTCOME: implemented
The full core-side cluster landed in commit 2bbbffd (before this request was
filed): IrStmt::Select { clauses } with SelectClause{comm,target,ch,value,body}
(src/shir.rs), A1 serialization {"type":"Select","clauses":[...]} (shir_json.rs),
ingress with strict recv/send/default comm validation (shir_json_in.rs), the
estree lowering to `await sh2.select([{comm,target,ch,value,body}...])`
(shir.rs 16220), and the runtime seam sh2.makeChan/recv/send/select + FIFO
`chans` map (harness/sh2-namespace.mjs) — channel handles are store strings,
so `make(chan T)`/`<-ch`/`ch <- x` lower as Calls on the sh2.channel builtins
exactly per the request's minimal design. Verified end-to-end this round with
four hand-written A1 programs through the executed-stdout oracle: recv+default
(empty FIFO -> "d"), send+recv (-> "42", target bound), send-only (no output),
default-only (-> "d") — all matching Go native semantics. Added
shir_json_in select_ingress regression test (clause shapes + round-trip +
unknown-comm refusal) at commit 72fca51. Gates: estree 521/521, cargo test
--lib 267/0. Remaining work is the go-sh FRONTEND lowering (select grammar ->
the A1 Select/Call vocabulary), which is the go-sh worker's own scope.
