# perl: `ir_to_perl` panics on ESTree-path-only ShIR nodes (watchdog gate red on the main binary)

## NEED

`debashl::ir::ir_to_perl` (src/ir.rs, the shared-core Perl renderer used by the
`--shir-in-perl` arm of the MAIN checkout's debashc) must not panic on the
ESTree-path-only IR nodes the A1 serializer now emits. Today the
`ir_expr_to_perl` arms are `unreachable!("ESTree-path-only X reached the Perl
renderer")` for `Arrow`, `Array`, `Arith`, `Bool`, `Json`, `Ident`, `Object`
(src/ir.rs ~line 1105). The worktree renderer (branch `backend/perl`,
`src/perl_backend.rs`) handles the full vocabulary, but the watchdog gate
(`setup_backends.sh --backend-gate perl` with the 92e6548-era
`perl) g_flag="--shir-in-perl"` design, main binary) still dies on them.

MINIMAL-CORE-CHANGE: replace the seven `unreachable!()` arms with a
never-panicking fallback — e.g. render `# TODO(unsupported): <variant>` +
`0`/`''` (the C backend's `/* TODO */` convention), exactly like the
`other =>` arm of `c_backend.rs`. No semantics change for the nodes the
legacy renderer already handles; the corpus gate then counts those
examples as rendered (exit 0) instead of rc=101.

## WHY

`debashc --shir-in-perl -` on the current main binary exits 101 (panic)
for 154 of the 527 corpus examples (the last watchdog run:
`[perl] backend gate: 484/539 corpus render OK, 51 fail` — the count
varies with the estree WIP tree). The gate counts a panic as a render
failure; a TODO-marker fallback renders successfully (the scaffold gates
already accept TODO-marker output — "the output ALWAYS compiles").

## MINIMAL-CORE-CHANGE

In `src/ir.rs`, `fn ir_expr_to_perl`, replace:

```rust
IrExpr::Arrow(_) => unreachable!("ESTree-path-only Arrow reached the Perl renderer"),
IrExpr::Array(_) => unreachable!("ESTree-path-only Array reached the Perl renderer"),
IrExpr::Arith(_) => unreachable!("ESTree-path-only Arith reached the Perl renderer"),
IrExpr::Bool(_) => unreachable!("ESTree-path-only Bool reached the Perl renderer"),
IrExpr::Json(_) => unreachable!("ESTree-path-only Json reached the Perl renderer"),
IrExpr::Ident(_) => unreachable!("ESTree-path-only Ident reached the Perl renderer"),
IrExpr::Object(_) => unreachable!("ESTree-path-only Object reached the Perl renderer"),
```

with a single fallback arm that never panics (e.g. `"# TODO(unsupported)"`
marker text or `"0"`). Optionally: `IrStmt`'s neutral arms (`Case`,
`Redirect`, `Function`, `Subshell`, `Background`, `Block`, `Expr`) in
`emit_stmt` should also fall back to `# TODO` comments instead of
unreachable/blank output. Keep the existing lowable-subset behavior
byte-identical (the `fail` corpus must not regress).

## FAILING-CASE

```console
$ sh2perl/target/debug/debashc --shir sh2perl/examples/001_simple.sh --raw \
    | sh2perl/target/debug/debashc --shir-in-perl -
thread 'main' panicked at src/ir.rs:1107:29:
internal error: entered unreachable code: ESTree-path-only Array reached the Perl renderer
```

(`001_simple.sh` is `echo "Hello, World!"` — its ShIR is
`Expr(exec("echo", Array([...])))`; the `Array` word list is what panics.)
Every example whose ShIR contains `Array`/`Arrow`/`Arith`/`Bool`/`Json`/
`Ident`/`Object` (154 of 527) hits the same panic.
