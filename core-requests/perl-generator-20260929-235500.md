### CORRECTION 2 — defect B (`043_home.sh`) is NOT "arms below the return"

The prior request claimed `flat_operand`'s `~` / `~/` arms are unreachable for
`[ … ]` tokens because they sit below a `return`. They do not — `ir.rs:8057-8064`,
at the **top** of the function, above every early return. That diagnosis is
wrong, and acting on it would change nothing.

The actual defect: `[ … ]` operands go through `render_test_operand`
(`ir.rs:8580`), which handles `${…}`, `$((…))`, `$(…)` and `$name` but has
**no tilde arm at all** — so it falls through to the literal fallthrough and
emits `'~/Documents'` verbatim. The RHS gets expanded only because it contains
`$`. Generated for `043_home.sh`:

```perl
$CHILD_ERROR = ((($__nocasematch) ? lc('~/Documents') eq lc("$ENV{HOME}/Documents") : …)) ? 0 : 1;
```

bash prints `1` / `-` / `3`; the generator prints `-` / `-` / `-`.

**Fix shape:** add the `~` / `~/…` arms to `render_test_operand` (mirroring
`flat_operand:8057-8064`) *before* its literal fallthrough at `ir.rs:8648`.

There is a **second, independent** instance of the same asymmetry: the
no-whitespace `[[ ]]` path `render_flat_test` (`ir.rs:8100`) also emits the LHS
raw at `ir.rs:8134` (`nocase_str_eq(&lhs, …)`) while only the RHS goes through
`flat_operand`. Both sites want the same one-line shape.

### Verified trivial fix — `$!` must be empty, not `0` (`dollar-bang.sh`)

`ir.rs:1365` emits `our $__sh2_last_bg = 0;`; `ir.rs:3783` maps `"!"` to it.
bash: `$!` is **unset** when no background job has run, so it expands to the
empty string. `examples/dollar-bang.sh` is `echo "background: $!"`:

```
bash:    background: $          (cat -A: trailing space, empty)
perl:    background: 0
```

**Fix:** initialize to `''`, not `0`. One line, no risk, no interaction with
the estree arm.

**What landed this round** (sh2perl `3ba4c77fd`, gitlink `0433a651`):

1. **Defect B (tilde) — implemented, minus a stale sub-claim.** Added the
   `~` / `~/…` arms to `render_test_operand` before its literal
   fallthrough, gated on `was_quoted` (bash does not expand a quoted
   tilde). `043_home.sh` now prints `1` / `-` / `3`, byte-identical to
   bash. **The report's second site is already correct**: it claims
   `render_flat_test` "also emits the LHS raw at ir.rs:8134
   (`nocase_str_eq(&lhs, …)`)", but `ir.rs:8106` computes
   `let lhs = flat_operand(&s[..pos]);` — the LHS already goes through
   the function that has the tilde arms. No change was needed, and none
   was made. (The line number moved to 8106 partly *because* of this
   round's edit; at the reported tree it was 8101.)
   I did **not** port the `tokenize_test` quote-preservation change. It is
   only needed to make the `was_quoted` gate work on tokens the
   tokenizer strips to bare, and **no corpus example contains a quoted
   tilde inside a test** (`grep -rn '\[ *"~"' sh2perl/examples/` → 0 hits).
   Porting it would rewrite how every quoted `[ ]` operand is tokenized
   for zero corpus coverage. The gate is correct for the case that exists
   today; the tokenizer change is the follow-up that makes it robust, and
   it belongs with a test that needs it.

2. **Defect E (`$!`) — implemented.** `our $__sh2_last_bg = 0;` →
   `= '';`. bash leaves `$!` unset with no background job, and `0` is a
   value a pid cannot take. `dollar-bang.sh` went from `background: 0` to
   `background: `, byte-identical to bash under `cat -A`.
