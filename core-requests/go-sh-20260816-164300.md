# go-sh: dead-store DCE must count `param(op, name, …)` as a READ of `name`

## NEED

The dead-store elimination for the estree emission (stalled request
`estree-20260813-182435-dce-dead-vars`; the implementation in stash
`4b066f5`) must mark the variable named by a `param(...)` call as READ.
Today its `walk_expr` `IrExpr::Call` arm handles only the `":="` op (a
WRITE) and ignores every other op — so a store whose only read is a
`param` call is classified as dead and dropped, and the generated JS
references an undefined binding (`ReferenceError: s is not defined`).

Every `param` op READS its name argument (the second arg): `""` plain
read, `:-`, `:+`, `:?`, `len`, `#`, `slice`, `/`, `//`, `#`/`##`,
`%`/`%%`, `^`/`^^`, `,`/`,,`, `:=` (read AND write), etc. Over-marking
is the safe direction (the analysis's own comment).

## WHY

The go-sh frontend gate (93 Go-source corpus tests: `go-sh --shir
--raw` → `debashc --shir-in-estree` → `estree-runner.mjs`, oracle =
native `go run`) failed 5/93 with `js=MISMATCH`:

- t37_substring.go  `s := "hello"; fmt.Println(s[1:3])`
  → `param("slice","s","1","2")` — store to `s` dropped
- t38_strlen.go     `fmt.Println(len(s))` → `param("len","s")`
- t54_str_subst.go  `strings.ReplaceAll(s,"p","r")` → `param("//","s","p","r")`
- t64_prefix_suffix.go  `strings.TrimPrefix(x,"he")` … →
  `param("#","x","he")`, `param("%","x","lo")`, `param("##","x","*l")`,
  `param("%%","x","l*")` — store to `x` dropped
- t89_to_lower.go   `strings.ToLower(s)` → `param(",," "s")`

Each rendered to the correct native lowering (`String(s).slice(1,3)`,
`String(s).length`, `replaceAll`, `startsWith`/`endsWith` strips,
`toLowerCase`) but crashed at runtime with `ReferenceError: <var> is
not defined` because the DCE had removed the assignment.

NOT a frontend-emitted-A1 quirk: the core's OWN shell→estree pipeline
fails identically on the equivalent script — `s="hello"; echo ${s:1:2}`
→ `s is not defined` — and on the corpus example
`sh2perl/examples/bench-substr.sh` (`s=abcdefghi; echo "sub=${s:2:3}"`).
This regression is what the estree worker stashed at
2026-08-16 16:35 ("REGRESSION: estree failures 49 > trusted 0.
Stashing scoped changes." → commit `cc1c549` "On main: estree-loop
regression"). The current core (DCE absent) is green; this request
prevents the stalled DCE from re-breaking the go-sh gate (and
bench-substr) when it lands.

## MINIMAL-CORE-CHANGE

In the DCE implementation (`collect_dead_store_stmts` in
`src/shir.rs`, the `walk_expr` `IrExpr::Call` arm; in stash `4b066f5`
it was the `"param" =>` branch at ~line 31049), change:

```rust
"param" => {
    if let [IrExpr::Str(op, _), IrExpr::Str(n, _), ..] = args.as_slice() {
        if op == ":=" {
            mark_word(n, written);
        }
    }
}
```

to also record the read:

```rust
"param" => {
    // every op reads the variable; `${x:=d}` also writes it
    if let [IrExpr::Str(op, _), IrExpr::Str(n, _), ..] = args.as_slice() {
        mark_word(n, reads);
        if op == ":=" {
            mark_word(n, written);
        }
    }
}
```

`mark_word` already strips `=`/`[` suffixes and gates on
`lift_is_ident`, so array-slice names (`arr[2]`) and special names
(`#s`, `@`, `!arr`) are handled conservatively. No contract change, no
deserializer change. Verdict check: `sh2perl/examples/bench-substr.sh`
through `file --estree` + `estree-runner.mjs` must print `sub=cde`.

## FAILING-CASE

`frontends/go-sh/testdata/t37_substring.go` (minimal; also
`t38_strlen.go`, `t54_str_subst.go`, `t64_prefix_suffix.go`,
`t89_to_lower.go` under `frontends/go-sh/testdata/`):

```go
// t37_substring: substring extraction
s := "hello"
fmt.Println(s[1:3])
```

Oracle: `el`. Pipeline: `./frontends/go-sh/go-sh --shir <file> --raw |
./sh2perl/target/debug/debashc --shir-in-estree - | node
harness/estree-runner.mjs /dev/stdin --source <file>`.

Shell equivalent (also fails under the buggy DCE):

```sh
s="hello"
echo ${s:1:2}
```

expected `el`; the buggy DCE renders
`process.stdout.write(String(String(s).slice(1, 3)) + "\n")` and
crashes `ReferenceError: s is not defined` (the `s="hello"` store was
eliminated).
