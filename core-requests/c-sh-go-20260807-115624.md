# c-sh-go: IR growth Label/Goto + SHARED restructure_goto pass in shir_passes

## NEED
Two additive core changes so goto lowering is ONE shared implementation
every frontend and backend uses, not a per-frontend copy:
1. IR/A1 growth: `IrStmt::Label(String)` and `IrStmt::Goto(String)`
   stmt nodes, serialized in the A1 contract (shir_json.rs emit +
   shir_json_in.rs round-trip; contract_version stays 1 — additive,
   backends that never see them unaffected).
2. A shared pass `src/shir_passes/restructure.rs` implementing the
   `Transform` trait (`fn run(&mut IrProgram, &PassContext)`), registered
   in `build_canonical_pipeline()` — which every backend runs — AND in
   the A1-ingress pipeline (so `--shir-in-estree` restructures frontend
   A1 JSON containing Label/Goto before rendering).

## WHY
Shell (and the A1 IR) has no goto; the IR currently cannot even
represent one. C source with `goto`/labels therefore cannot be
transpiled at all today (c-sh-go refuses). The restructuring itself
(backward goto -> While/DoWhile, forward goto -> inverted-If, loop exit
-> break, nested exit -> flag vars, tangle/irreducible -> node split /
Case state machine, else Unsupported marker) is language-independent —
it operates on the CFG of Label/Goto stmts. Placing it in the shared
pipeline means: all 9 backends inherit it automatically (they consume
the post-transform IR), and any frontend that emits Label/Goto (c-sh-go
for C goto; future frontends for labeled-break-style constructs)
inherits it through the A1 ingress path. A per-frontend copy would be
duplicated across 7 Go frontends and re-verified 7 times.

## MINIMAL-CORE-CHANGE
- src/ir.rs: add `IrStmt::Label(String)` / `IrStmt::Goto(String)`
  (serialized as `{"type":"Label","name":...}` /
  `{"type":"Goto","name":...}`), and let them pass through the existing
  stmt walkers (they carry no expressions).
- src/shir.rs + shir_json.rs + shir_json_in.rs: round-trip the two new
  node kinds (additive; unknown-kind rejection preserved).
- src/shir_passes/restructure.rs: `Transform` impl. Build the CFG of the
  function body from labels/gotos; classify edges (DFS back edges ->
  loops, forward edges -> region jumps); emit:
    * backward post-test  -> DoWhile (body, cond, until=false)
    * backward pre-test   -> While
    * backward mid-test   -> While{true} + If{cond, break}
    * forward same-level  -> inverted If wrapping the skipped region
    * single-loop exit    -> Call("break")
    * nested-loop exit    -> Assign flag + break, flag read in each
                             enclosing While/DoWhile condition
    * tangle/irreducible  -> node split; else a Case-on-state-var state
                             machine inside While{true}; else an
                             `Unsupported` marker node (the stub gate
                             counts it -> failure-driven loop picks it up)
- register in `build_canonical_pipeline()` (and the A1-ingress
  pipeline). Placement relative to the existing transforms is the
  estree worker's call; verify `./fail-estree` stays at the trusted
  baseline (no corpus file contains goto today, so no regression
  expected) and add unit tests under shir_passes/.

## FAILING-CASE
frontends/c-sh-go/testdata/t27_goto.c (plus t30_goto_nested.c —
multi-level exit — and t31_goto_forward.c — cleanup jump, both added
with the roadmap ladder):

```c
#include <stdio.h>
int main(void) {
    int i = 0;
loop:
    i++;
    if (i < 3) goto loop;
    printf("%d\n", i);
    return 0;
}
```

Currently: `./c-sh-go --shir t27_goto.c --raw` refuses
(`lex: unexpected ":"`) -> exit 1. Expected once Label/Goto land: the
frontend parses labels/gotos and emits the two nodes; the shared pass
restructures to `i = 0; DoWhile(i < 3, [i++]); printf ...`; the
transpiled run prints `3` like gcc. The pass must ALSO be reachable
from `--shir-in-estree` so the frontend's A1 output is restructured the
same way the file pipeline is.
