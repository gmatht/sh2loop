# go-sh: A1 lacks a deferred-execution node — deferStmt inexpressible

## NEED

> CONVERTED (PLAN §11): filed as the first bundle at
> `core-requests/bundles/defer/` (spec + two lowering offers) — the
> marketplace node+transforms channel.

A shIR statement node for Go's `defer` statement (ANTLR golang rule
`deferStmt : DEFER expression` — `defer f(args)` schedules the call to
run when the enclosing function returns, LIFO across multiple defers,
and it runs even when the function exits via panic). The go-sh frontend
can already lower `go func(){}()` (→ `Background`) and function
decls/literals (→ `Function`), but it has no target for `defer`: the A1
contract has no node whose semantics are "run this at enclosing-scope
exit" — no Trap/Defer/AtExit node exists in `IrStmt` (ir.rs) or the A1
JSON vocabulary (shir_json.rs / shir_json_in.rs), and the core's shell
parser treats `trap` as a plain command word (parser/commands.rs "trap"
→ normal word, no special node), so the shell side offers no seam
either.

Minimal node shape (mirrors the existing `Background`/`Subshell`/`Block`
statement shape so go-sh's func-body lowering extends naturally):

- `Defer` stmt: `{ "type": "Defer", "body": [ <stmt>... ] }`
  — the body is the deferred call(s). Multiple defers in one function
  nest as enclosing `Defer` nodes, so LIFO falls out of the renderer's
  block structure (inner Defer runs first at exit). ESTree-path only
  (like the existing `Try` node): renderers that cannot express it
  refuse loudly; the shell-flavored renderers never see it.

## WHY
`deferStmt` is ledgered in frontends/coverage/refused-go-sh.txt but was
never a deliberate subset exclusion: the go-sh v2 subset header
(go-sh.go) documents what is refused and why, and `defer` is not among
them — it is simply unhandled, so the parser dies in `parseAssignStmt`
(`expected assignment operator, got "fmt"`, exit 2) when a file
contains `defer fmt.Println(...)`. The frontend's established pattern is
to lower every Go construct with a faithful A1 target (go → Background,
type switch → Case after core request go-sh-20260813-154009), and to
escalate constructs without one (select/commCase → core request
go-sh-commcase-20260814-031345.md, now done/). Defer is the same class:
it is inexpressible because the A1 CONTRACT lacks the node — if shIR
had a Defer node, go-sh could express it. No testdata example can
exercise the grammar rule until the contract has it.

## MINIMAL-CORE-CHANGE
1. `src/shir.rs` + `src/shir_json.rs` / `src/shir_json_in.rs` (A1
   contract): add `IrStmt::Defer { body: Vec<IrStmt> }` serialized as
   `{"type":"Defer","body":[<stmt>...]}`, deserialized alongside
   Background/Subshell/Block. No expression-node changes needed — the
   deferred call is an ordinary `Call`/`Expr` statement inside `body`.
2. `src/estree.rs` (+ runtime if needed): render `Defer` by wrapping
   the remainder of the enclosing function body in a
   `try { ... } finally { <deferred body> }` block — Go-faithful for
   normal returns AND panics (JS finally runs on throw), and nesting
   gives Go's LIFO order. The go-sh frontend then lowers
   `defer <call>` to `Defer{body:[<call>]}`.
3. `src/parser/` (shell side): no change required (a `Defer` node is
   never emitted by the shell pipeline).

## FAILING-CASE
`frontends/go-sh/testdata` has no defer example; the probe below is
currently refused:

```go
package main

import "fmt"

func main() {
	defer fmt.Println("done")
	fmt.Println("hi")
}
```

Native oracle (`go run`): prints `hi` then `done` (defer runs at
function exit). Current pipeline
(`./frontends/go-sh/go-sh --shir <file> --raw`) fails with
`go-sh: line 4: expected assignment operator, got "fmt"` (exit 2) —
`parseStmt` has no `defer` case. Once the contract has `Defer`, the
example `defer fmt.Println("done"); fmt.Println("hi")` should emit and
the executed-stdout oracle should match `hi` / `done`.
