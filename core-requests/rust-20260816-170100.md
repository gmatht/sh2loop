# rust: the backend gate's rust arm needs the perl/sh rc-equality + argv0 contract

## NEED

`setup_backends.sh --backend-gate rust` (the per-language gate the rust
worker loops on) must adopt, for the rust arm, the same verdict rules the
perl and sh arms already have:

1. **rc-equality instead of rc-0**: the rust arm currently collapses the
   translation's exit code to 0/1 (`rustc … && timeout 15 …bin && eq_exit=0`)
   and the verdict demands `eq_exit = 0 AND bash_rc = 0`. Perl/sh compare
   `eq_exit = bash_rc` (the gate's own comment: "the old rc=0-on-both-sides
   rule made them unpassable for every backend"). The rust arm needs the
   same `[ "$eq_exit" = "$bash_rc" ]` branch.
2. **argv0**: the rust arm runs the binary as `/tmp/eq_$$_bin` while the
   reference runs `bash "$f"` (the full source path). Perl gets
   `$0 = shift @ARGV` = the source path; sh gets `sh -c '. /dev/fd/3' "$f"`.
   The rust arm needs an argv0 equivalent (e.g. `rustc … -o /tmp/eq_$$_bin
   && (cd … && timeout 15 /tmp/eq_$$_bin "$f" …)` with the renderer reading
   `$0` from argv, or a `--source-path` env/arg the renderer maps to `$0`).

## WHY

With every renderer bug fixed (the rust gate went 609 → 623/638 this
session: fd-dup redirects, arith parse-fail/bad-substitution word
suppression, case `$(cmd)` patterns, `printf %q` + field-split args,
Int-var-string-value TLS, nested `$()` in `$(( ))`, `typeset -f/-F/-p`,
combined `-il/-iu` flags, PUA-marker raw bytes, fnmatch NUL truncation,
spawn stdout flush), the gate is at its irreducible floor: **8 fails, all
bash-side rc/argv0/environment artifacts no renderer can change**:

- `t83_exit.sh` (`exit 3`), `echo-with-escaped-backtick.sh` /
  `echo-with-escaped-backtick-and-quotes.sh` (`exit 1`),
  `parse-bracket-subshell-pipe.sh` (final `[[ … ]] && x=…` returns 1 by
  design), `063_04_complex_parameter_expansion.sh` (final echo's
  `${!prefix*[@]:0:3}` is a bad substitution → rc 1). The rust renderer
  already reproduces these exit codes exactly (verified: `eq_exit =
  bash_rc` on every one); the rc-0 rule still fails them.
- `057_case.sh` (prints `Usage: $0 …`), `qx-var-builtin-cd.sh`
  (`dirname "$0"`): the binary's `$0` is `/tmp/eq_$$_bin`, bash's is the
  source path. The renderer emits the runtime argv[0]; without gate argv0
  support the paths can never agree.
- `cat-dash-stdin.sh`: the root-owned `/tmp/out.txt` squatter makes
  bash's final `rm -f /tmp/out.txt` fail (rc 1). The sh backend
  conditionally allowlists this exact condition
  (`[ -e /tmp/out.txt ] && [ ! -w /tmp/out.txt ]`).

The rust renderer's stdout matches bash byte-for-byte on all 8 (verified
in the last gate run: "623 pass vs bash", 0 stubs emitted).

## MINIMAL-CORE-CHANGE

This is NOT a shared-core change — it is a gate-contract change in
`setup_backends.sh --backend-gate` (workspace root, owned by the harness
owner, not the estree core worker). The minimal diff mirrors the
documented perl/sh adoption:

- verdict: `{ { [ "$g_lang" = "perl" ] || [ "$g_lang" = "sh" ] || [ "$g_lang" = "rust" ]; } && [ "$eq_exit" = "$bash_rc" ]; }` — extend the equality branch to rust (the collapse-to-0/1 already makes a genuinely broken binary (compile fail, panic rc 101, timeout 124) distinguishable from a faithful nonzero-exit script).
- argv0: run the rust binary with the source path as argv[0] (perl's pattern: pass `"$f"` and let the renderer's `$0` read it).

## FAILING-CASE

`bash setup_backends.sh --backend-gate rust` → "623/638 corpus render OK,
8 fail (0 stubs, 8 equiv), 7 skip — equiv: 623 pass vs bash" with the
fails listed above. Repro per file: render → `rustc` → run → diff stdout
vs `bash "$f"` (stdout matches; the rc/argv0 comparison fails).
