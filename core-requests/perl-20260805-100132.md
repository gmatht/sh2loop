## WHY

- The worktree renderer path is green, so the perl WORKER is unblocked.
- But the main checkout's `debashc --shir-in-perl -` (the production binary,
  also what `--shir-in-estree` consumers may reach) still exits 101 on 154
  corpus examples — a latent crash in the shared core's Perl renderer.
- The `fail` corpus gate (workspace `./fail`, generated Perl vs bash stdout)
  uses the same `ir_to_perl` — a panic arm there is a correctness landmine for
  any future corpus addition that reaches `Array`/`Arrow`/`Arith`/`Bool`/
  `Json`/`Ident`/`Object` nodes.

## MINIMAL-CORE-CHANGE

In `src/ir.rs`, `fn ir_expr_to_perl`, replace the seven
`unreachable!("ESTree-path-only X reached the Perl renderer")` arms
(src/ir.rs ~lines 1106-1112) with a single never-panicking fallback that
emits a `# TODO(unsupported): <variant>` marker + a neutral value (`0` /
`''`), exactly like the `other =>` arm of `c_backend.rs`. Optionally do the
same for `IrStmt`'s neutral arms in `emit_stmt` (Case/Redirect/Function/
Subshell/Background/Block/Expr). Keep the lowable-subset behavior
byte-identical (the `fail` corpus must not regress).
