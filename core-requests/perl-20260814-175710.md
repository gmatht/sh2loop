# perl: A1 shIR emit must preserve invalid-UTF-8 bytes (utf8-non-utf8-content.sh)

## NEED
`debashc --shir <file> --raw` (the A1 emit path, `cli/src/cli_commands.rs::parse_file_to_shir`)
must read the source with the SAME marked-lossy decoding the estree and
legacy-perl paths use (`SharedUtils::bytes_to_marked_lossy`, PUA markers
U+E000+byte), instead of `String::from_utf8_lossy` (U+FFFD). The A1
contract is currently the ONLY path that destroys invalid bytes, so no
backend can reproduce bash's byte-exact pass-through.

## WHY
`sh2perl/examples/utf8-non-utf8-content.sh` contains an ISO-8859-1 byte
0xE9 inside a double-quoted echo. bash passes the raw byte through:

    $ bash utf8-non-utf8-content.sh | xxd
    ... 6163 63e9 6e74 ...   (acc<E9>nt)

The perl backend gate (`setup_backends.sh --backend-gate perl`) fails the
file: the A1 JSON carries U+FFFD (ef bf bd) because `parse_file_to_shir`
decodes lossily, and the perl renderer can only reproduce what the
contract carries. The estree path already passes this file — its JSON
preserves the byte as a `\u0001SH2BYTE\u0001E9\u0001` marker
(`src/estree.rs` RAW_BYTE_MAGIC), and the legacy perl path
(`parse_file_to_perl`) uses `bytes_to_marked_lossy`. Only the A1 shIR
emit is plain-lossy.

## MINIMAL-CORE-CHANGE
In `cli/src/cli_commands.rs::parse_file_to_shir`, replace the
`String::from_utf8_lossy(&bytes).into_owned()` read with
`SharedUtils::bytes_to_marked_lossy(&bytes)` — exactly what
`parse_file_to_perl` (the line above it) already does. No serializer or
deserializer change is needed: serde_json round-trips the PUA chars
(U+E000..U+E0FF are valid UTF-8), and `shir_json_in` passes them through
to the backends unchanged. Backends that care decode the marker
(U+E000+byte → `\xNN`); backends that don't currently fail the file
anyway (they emit the lossy U+FFFD today), so there is no regression.

The perl backend already has the decoder side (perl_backend.rs perl_str:
U+E000..U+E0FF → `\xNN` byte escape), verified byte-exact against bash.

## FAILING-CASE
```
$ printf 'echo "acc\351nt"\n' > /tmp/iso.sh
$ sh2perl/target/debug/debashc --shir /tmp/iso.sh --raw | grep -o 'acc.\{0,4\}nt' | xxd
... 6163 63ef bfbd 6e74     # U+FFFD — the byte 0xE9 is gone
# expected: the byte preserved (PUA marker U+E0E9 in the JSON string)
```

Note: the OTHER remaining perl-gate failures (t83_exit.sh, 057_case.sh,
echo-with-escaped-backtick*.sh, parse-bracket-subshell-pipe.sh,
063_04_complex_parameter_expansion.sh) exit non-zero BY DESIGN — the
gate's `bash "$f"` must return 0, so no renderer/core change can pass
them (fail-estree compares exit codes and passes them). qx-var-builtin-cd.sh
needs the source path injected as $0 (fail-estree rewrites argv0; the
backend gate does not) — a gate-side concern, not a core one.
