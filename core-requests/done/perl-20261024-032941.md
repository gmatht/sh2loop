# perl: copy-propagation folds across a store-writing builtin whose variable name is 1–2 letters

## NEED

`copy-propagation` must treat `unset NAME` / `read NAME` / `declare … NAME` as a
write to `NAME` **for every NAME**, including one- and two-letter names. Today it
treats a bare 1–2 letter word as a command-line *flag* and drops it, so the write
is invisible, the variable still looks "assigned exactly once", and the pass folds
a stale literal across the write.

Consequence in the A1 the gate consumes: `x=5; unset x; echo "$x"` exports as
`echo` of the literal `5`. bash prints an empty line. Every backend renders the
exported literal, so this is not perl-specific — the perl gate is simply the one
that catches it (`642/650 render OK, 1 fail (1 equiv)` on
`sh2perl/frontends/posix-sh-go/testdata/t70_unset.sh`).

## WHY

`src/transforms/copy_propagation.rs`, `classify_builtin_writes` (line ~408):

```rust
let s = s.trim_start_matches('-');
if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
    continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
}
```

The dash is stripped BEFORE the flag test, so the test no longer knows whether the
word ever *had* one. `x` is not a flag; it is a variable whose name happens to be
short. The same hole swallows `unset i`, `read n`, `declare -i i`, `mapfile -t a`
→ writes to `i`/`n`/`a` are not counted, `collect_defs` still sees a single def,
and `fold_expr` substitutes the old literal at every later read.

Evidence (all run at 2026-10-24 03:2x against the current core, `otranspilerl-cli`
built from `/mnt/wsl/projects/sh2loop/sh2perl`):

```
$ printf 'x=5\nunset x\necho "$x"\n' > /tmp/tc2.sh
$ otranspilerl-cli --target shir /tmp/tc2.sh | jq -r '.stmts[2].expr.args[1].elements[0]'
{"type":"Str","style":"DoubleQuoted","value":"5"}              # ← folded across the unset

$ printf 'foo=5\nunset foo\necho "$foo"\n' > /tmp/tf1.sh
$ otranspilerl-cli --target shir /tmp/tf1.sh | jq -r '.stmts[2].expr.args[1].elements[0]'
{"type":"Call","func":"getVar",…}                              # ← correct: 3-letter name not a "flag"

$ SH2_TRANSFORMS=copy-propagation otranspilerl-cli --target shir /tmp/tc2.sh  # still folds
$ SH2_TRANSFORMS=__none__           otranspilerl-cli --target shir /tmp/tc2.sh  # getVar — correct
```

So the fold is `copy-propagation` alone, and it is keyed on the *name length*, not
on the construct.

This is a plain soundness bug in an existing shared analysis — no new node, no
contract change, no transform offer.

## MINIMAL-CORE-CHANGE

One condition in `classify_builtin_writes` (and the twin `let`/`eval` arm below it,
which loops over the same `args`): only classify a word as a flag when it actually
carried a leading `-`.

```rust
 for a in args {
     if let IrExpr::Str(s, _) = a {
-        let s = s.trim_start_matches('-');
-        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
-            continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
+        let dashed = s.starts_with('-');
+        let s = s.trim_start_matches('-');
+        if s.is_empty() || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+            continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
         }
```

(`-A` in that comment is not ASCII-alphabetic anyway, so it never matched; `--`
long options and `-v` keep working.) A unit test beside the existing ones in the
module covers `x=5; unset x; echo "$x"` (must NOT fold) and `x=5; echo "$x"`
(must fold) so the next rewrite of the flag heuristic has to keep the distinction.

## OUTCOME: implemented

Landed in `sh2perl/src/transforms/copy_propagation.rs::classify_builtin_writes`: a word is treated as a command-line flag only when it actually carried a leading `-`, so a bare 1-2 letter NAME (`unset x`, `read ab`, `local n`) is recorded as a write and copy-propagation refuses the stale fold. Pinned by unit tests `unset_invalidates_single_def`, `read_invalidates_single_def`, `dashed_flag_is_still_skipped`, `folds_without_unset`.

Verification: `./fail-estree` -> PERL 562/562 passed, ESTREE 561/562. The single estree failure (`grep_p.sh`, "non-sh2 callee: min") reproduces identically with `SH2_TRANSFORMS=none` and the file contains no store-writing builtin, so it is pre-existing/WIP and unrelated. `cargo test --lib`: the 27 failures are identical before and after this hunk (pre-existing WIP); the 4 new tests pass.

Note: the fix landed in the live working tree, which is the tree `setup_backends.sh` and all gates build `otranspilerl-cli` from. The same file carries the in-flight `fold_param_const` WIP (+~640 uncommitted lines) plus 57 other dirty `src/` files, so a scoped commit is not isolable this round.
