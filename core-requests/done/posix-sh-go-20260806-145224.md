# posix-sh-go: unquoted expansions never word-split (for-iter, `set --`) — A1 drops the quoted/unquoted distinction

## NEED
The A1 contract must carry the **quoted vs unquoted** distinction for
expansion sites where bash field-splits, and the ESTree lowering +
runner must honor it. Today `for w in "$y"` and `for w in $y` are
**byte-identical** in A1 — both emit the For.iter element as
`Call{func:"getVar", args:[Str "y"]}` (see evidence below) — so the
ESTree backend lowers both to a native `ForOfStatement` over
`[].concat(y)` (one iteration) and the runner never splits. Same for
`set -- $y` → `exec set -- [getVar y]` → one positional `"a b c"`
instead of three.

## WHY
`frontends/posix-sh-go` gate: 56/56 testdata scripts are A1
byte-equal to the core frontend, but the executed-stdout comparison
(harness/frontend-stdout.sh: frontend A1 → `--shir-in-estree` → node
estree-runner.mjs vs native bash) fails 1/56:

    testdata/t04_params.sh:
      y="hello world"
      for w in $y; do echo "word=$w"; done
    bash:             word=hello / word=world
    core pipeline:    word=hello world   (single iteration)

Verified the CORE's own pipeline (`debashc --shir` → `--shir-in-estree`
→ runner) produces the same wrong output — the frontend is
byte-identical and cannot deviate (byte-equality oracle is the gate),
so this is a shared-core gap, not a frontend gap. Secondary
manifestation: `set -- $y` lowers to one positional arg
(`n=1 p1=a b c`) instead of three. (`echo $y` looks right only
accidentally — echo joins its args with spaces.)

## MINIMAL-CORE-CHANGE
No new IR node or deserializer work is needed — `Call` already
round-trips through shir_json.rs / shir_json_in.rs.

1. **Core frontend lowering** (src/shir.rs or the parser lowering that
   builds `IrStmt::For.iter` / exec-arg Arrays): emit a
   `Call{func:"split", args:[<expansion>]}` wrapper for **unquoted**
   expansions in a for-iter element (and, for completeness, unquoted
   expansions in command-arg Arrays — the `set -- $y` case). Quoted
   expansions keep the bare `getVar`. This mirrors how GLOB_MAGIC
   already tags unquoted glob words (shir.rs:3850) — the contract
   precedent for marking unquoted word positions.
2. **ESTree lowering** (`flatten_for_iter` / `expr_to_estree`): lower
   `split(x)` to `x.split(/\s+/)` (default-IFS whitespace splitting;
   filtering empty fields), so the native `ForOfStatement` iterates
   per field and the runner needs no new helper. `set --`'s arg list
   lowering should spread the split result into the positional
   assignment.
3. Optional (documentation only): note `split` as a reserved `Call`
   func in the A1 contract docs.

Scope note: the *estree worker* decides breadth — fixing for-iters is
sufficient for the failing gate (t04_params.sh); `set --` is the same
one-line pattern and should ride along if it doesn't regress
`./fail-estree`.
