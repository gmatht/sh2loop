## WHY

Independent trace of the failure mechanism, done without touching the core
(this pass reproduced and simulated it end-to-end):

1. `frontends/c-sh-go/c-sh-go --shir testdata/t20_switch.c --raw` emits
   valid A1 (ingress-accepted): `Assign x="2"`, `If(test "$x -eq 1")`,
   etc. — byte-identical in shape to what the core's own bash pipeline
   emits for `x=2; if [ "$x" -eq 1 ] ...` (verified: the core's own
   `--shir` of that bash program round-trips through `--shir-in-estree`
   to the SAME broken JS, so this is not frontend-emission-specific).
2. `--shir-in-estree` emits `x = 2;` (native lifted write) with NO
   `let x = 0;` declaration. `node harness/estree-runner.mjs` then dies:
   `ReferenceError: x is not defined` (ESM strict) → empty stdout → DIFF.
3. Mechanism (confirmed by re-implementing the walk in Python against the
   actual emitted body): in `drop_dead_top_decls`, `stmts_read(&body, "x",
   false)` iterates from body[0]; body[0] IS the leading `let x = 0`
   declaration. `stmt_read` on it reads nothing (init is a Literal), then
   the loop's `if stmt_declares(st, name) { sh = true; }` fires for the
   declaration ITSELF — every later top-level read/write of x (`x = 2`,
   `x === 2`) is treated as shadowed → `read` is empty → the declaration
   is dropped. The drop is therefore triggered by ANY lifted variable,
   not only the for-shadowing case the commit targeted.
4. A write counts as a read in `expr_read` (AssignmentExpression arm
   recurses into `left`), so once the self-shadow is fixed, `let x = 0;
   x = 2; ...` keeps the declaration — which is also REQUIRED for
   correctness: a native `x = 2` write without a binding throws the same
   ReferenceError even with zero later reads.

## MINIMAL-CORE-CHANGE

Exactly as specified in core-requests/c-sh-go-20260809-131354.md —
re-validated against all `stmts_read` call sites (estree.rs:4257
top-level entry from `drop_dead_top_decls`; 4292 BlockStatement arm;
4308 SwitchStatement arm):

```rust
fn stmts_read(stmts: &[Stmt], name: &str, shadowed: bool) -> bool {
    stmts_read_level(stmts, name, shadowed, true)
}
fn stmts_read_level(stmts: &[Stmt], name: &str, shadowed: bool, top: bool) -> bool {
    let mut sh = shadowed;
    for st in stmts {
        if stmt_read(st, name, sh) {
            return true;
        }
        // a `let x` in this block shadows the remainder of it — EXCEPT
        // the leading top-level declaration being analyzed (it IS the
        // binding under test; no second top-level `let x` can exist in
        // ESM). Nested scopes recurse with top=false.
        if stmt_declares(st, name) && !top {
            sh = true;
        }
    }
    false
}
```

with the BlockStatement and SwitchStatement arms of `stmt_read` calling
`stmts_read_level(body, name, shadowed, false)`. Behavior preserved for
the commit's original target: `let i = 0; for (let i = 1; i <= n; i++)
{...}` still drops the hoisted `let i = 0` (the ForStatement arm
shadow-scopes the body reads via `shadowed || declares`), while any
top-level read AFTER the loop (`echo $i`) now correctly keeps it — the
commit message claimed this worked, but it is also broken by the current
code.
