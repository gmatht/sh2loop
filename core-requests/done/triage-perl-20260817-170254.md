# triage: perl backend can't render what the go-sh frontend emits

## NEED
The perl renderer must handle this A1 (the estree reference renders it and
matches native).

## FAILING-CASE
frontend go-sh, example t83_type_args.go (cross-product pair).

## EVIDENCE
estree matches native; perl differs

## OUTCOME: implemented

Three Perl-renderer gaps (`sh2perl/src/ir.rs`), all visible in this pair's A1:

1. `rewrite_fn_calls` never descended into the ARGUMENTS of an `exec` whose
   command is not a program function, nor into `IrExpr::Arrow` (a capture
   body), nor into any expression-carrying statement other than `Expr`/`If`/
   loops. `echo "$(id 5)"` therefore kept a raw `exec("id")` and the capture
   rebuilt it as SHELL text — the generated program ran `/usr/bin/id 5` and
   printed `uid=5(games) …`. Every expression channel is now enumerated
   (Output, WriteFile, Assign, Declare, DeclareArray, Die, Warn, Exec,
   Return, Exit, SetChildError, Arrow).
2. A bare `return` (`Call{func:"return", args:[]}`) hit the unknown-op arm and
   emitted `die "sh2.* call `return` not yet supported"`, aborting the whole
   program. It now renders `return;` (with `$CHILD_ERROR = <n>` when a status
   word is given).
3. `strReplaceAll(s, old, neu)` — the A1 word-split op — reached the generic
   arm and emitted a call to an undefined sub. It now renders the runtime's
   split/join (empty `old` splits into characters, `\Q…\E` literal split, `-1`
   keeps trailing fields) and chomps a CAPTURE operand, because bash strips
   `$( )`'s trailing newlines before word splitting.

Verified: `harness/triage.sh go-sh t83_type_args.go perl` → PASS (`5`).
