# c: `copy-propagation` const-folds a var written by `unset x` — short names are mistaken for flags

## NEED
One shared-analysis fix, in `sh2perl/src/transforms/copy_propagation.rs`:
`classify_builtin_writes` must not treat a 1-2 letter VARIABLE NAME as a
command-line flag. It currently strips leading `-` and then skips any
result that is ≤2 alphabetic characters, so `unset x`, `read i`, `local n`,
`export S` register NO write site for `x`/`i`/`n`/`S`. `collect_defs` then
still sees those vars as "single top-level literal def" and
`fold_param_const` folds every `${x…}` read to the literal — even reads that
come AFTER the write.

This is the c backend gate's only EQUIV failure
(`642/650 pass, 1 fail — frontends/posix-sh-go/testdata/t70_unset.sh`).
No c-side lowering can repair it: the wrong value is already baked into the
A1 the renderer receives, so the fold has to be fixed where it happens.

## WHY
`collect_defs` requires `counts[v] == 1` plus a top-level literal def. The
`unset`/`read`/`declare` write is supposed to make that count 2. It does for
3+ letter names and does NOT for 1-2 letter names — an asymmetry that shows
up on the smallest possible repro, so it is the flag test, not the dataflow:

    $ printf 'x=5\nunset x\necho "${x:-gone}"\n'   | cli --target shir - | grep -c '"func":"param"'
    0                      # folded — WRONG (bash prints `gone`)
    $ printf 'xyz=5\nunset xyz\necho "${xyz:-gone}"\n' | cli --target shir - | grep -c '"func":"param"'
    1                      # not folded — correct

The same drop applies to `read x`, `local x`, `declare -r x`, `export X`:
any write builtin whose name is short leaves the var "single-def literal",
so it is also folded across the write.

## MINIMAL-CORE-CHANGE
`classify_builtin_writes` (currently line ~408; the file has uncommitted WIP,
so match on the text). Only skip a token that ACTUALLY looked like a flag —
i.e. the original string started with `-` (or `/` for `declare -a` style
path flags) BEFORE trimming:

```rust
        for a in args {
            if let IrExpr::Str(s, _) = a {
                // a flag is a token that ARRIVED with a dash: `-i`, `-r`,
                // `-n`. Trimming first and testing the remainder made every
                // short variable name (`unset x`, `read i`, `local n`) look
                // like one, so those writes never registered and the const
                // fold crossed them (`x=5; unset x; echo "${x:-gone}"`
                // folded to `5`).
                if s.starts_with('-') {
                    continue;
                }
                let name = s.split('=').next().unwrap_or(s);
                if !name.is_empty() {
                    ...
```

`analyze_var_const`'s `builtin_names` (shir.rs) already classifies the same
builtins without a flag-length heuristic — that is the behaviour wanted
here. No contract/node change, no transform offer.

## FAILING-CASE
Corpus cell: `sh2perl/frontends/posix-sh-go/testdata/t70_unset.sh`

    x=5
    unset x
    echo "${x:-gone}"

* bash: `gone`
* c gate: `5` (EQUIV fail; render/stub/static-analysis all clean)
* A1 (from the main-tree `otranspilerl-cli --target shir`): the echo
  argument is already `{"type":"Str","value":"5"}` instead of
  `{"func":"param","args":["",":-","x","gone"]}`

Reproduce the fold in isolation (no backend involved):

    SH2_TRANSFORMS=copy-propagation otranspilerl-cli --target shir t70_unset.sh \
      | grep -c '"func":"param"'      # 0 = folded

and c's gate verdict on the single cell:

    bash sh2perl/backends/c/harness/c_gate_local.sh -v \
      sh2perl/frontends/posix-sh-go/testdata/t70_unset.sh

Expected after the fix: `1 pass, 0 fail`, and the corpus gate returns to
100% of rendered cells (643/650 rendered, 0 fail, 7 skip).

## OUTCOME: implemented

Landed in `sh2perl/src/transforms/copy_propagation.rs::classify_builtin_writes`: a word is treated as a command-line flag only when it actually carried a leading `-`, so a bare 1-2 letter NAME (`unset x`, `read ab`, `local n`) is recorded as a write and copy-propagation refuses the stale fold. Pinned by unit tests `unset_invalidates_single_def`, `read_invalidates_single_def`, `dashed_flag_is_still_skipped`, `folds_without_unset`.

Verification: `./fail-estree` -> PERL 562/562 passed, ESTREE 561/562. The single estree failure (`grep_p.sh`, "non-sh2 callee: min") reproduces identically with `SH2_TRANSFORMS=none` and the file contains no store-writing builtin, so it is pre-existing/WIP and unrelated. `cargo test --lib`: the 27 failures are identical before and after this hunk (pre-existing WIP); the 4 new tests pass.

Note: the fix landed in the live working tree, which is the tree `setup_backends.sh` and all gates build `otranspilerl-cli` from. The same file carries the in-flight `fold_param_const` WIP (+~640 uncommitted lines) plus 57 other dirty `src/` files, so a scoped commit is not isolable this round.
