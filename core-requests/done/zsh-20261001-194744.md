    [2026-10-01T19:47:44] zsh TRAPPED — sleeping until estree wakes (marker core-requests/sleeping-zsh)

So the worker is not in a build loop at all. It is in the **trap sleep**: parked on
`core-requests/sleeping-zsh` (still present, written 19:47), waited out the bounded
`$WORKER_TRAP_SLEEP_MAX_S`, and exited on purpose so its supervisor would restart it and
re-gate. That is the documented, correct behaviour for a parked worker — not a failure.

`Finished dev profile in 34.97s`, 0 errors (50 warnings). The zsh worker had already
