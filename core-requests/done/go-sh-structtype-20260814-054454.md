# go-sh: A1 contract has no struct/member-access vocabulary — Go structType is inexpressible

## NEED
The A1 contract must give the go-sh frontend a way to lower Go's struct
type literal (grammars-v4 golang rule `structType`:

    structType
        : STRUCT L_CURLY (fieldDecl eos)* R_CURLY
        ;

i.e. `struct { X int }` / `struct{}`) and the composite-literal /
member-access forms built on it — `s := struct{ X int }{X: 5}`,
`s.X` reads, `s.X = 7` writes. Today no A1 node/field represents a
struct value or a member access: the A1 store is a flat runtime
string/array model (shell-shaped) whose only composite keying is the
var-name string (indexed assigns lower `a[1]` → `Assign{var:"a[1]"}`,
t37/t66) and by-name assoc arrays (t54 maps, `assocSet`/`assocGet` —
literal keys only). Member offsets/layout and field reads are absent,
so a faithful struct emit has no target shape. `structType` is a
grammar-rule coverage gap for go-sh (unexercised in all 88 testdata
examples; `frontends/coverage/rules-gap.sh go-sh` lists it).

## WHY
The coverage hook (`rules-gap.sh go-sh`) reports `structType` as a
golang grammar rule no testdata example exercises. No example can
exist today:

1. **The parser has no struct path.** `struct` is not a recognized
   statement or top-level keyword in the hand-rolled parser
   (frontends/go-sh/go-sh.go): `parseStmt`'s switch is only
   if/for/switch/return/go/var, `parseTopLevel` only special-cases
   `func`, and `parseVarDecl`'s optional-type loop consumes only
   `pkg.Ident` / plain idents / `[]T` / `*T`. Every struct program
   fails loud (exit 2) at the `{`/field token:

       $ ./go-sh --shir i.go --raw
       go-sh: line 6: expected assignment operator, got "int"
       exit=2

   (for `var s struct{} = nil`: `go-sh: line 6: expected assignment
   operator, got "{"`, exit 2). Note the t82 func-type var decl
   (`var f func(int) int = nil`) only "works" because the leftover
   `func(...)` is silently swallowed as a skipped top-level method
   decl — an accident with no struct analog, since `struct` is not a
   top-level keyword.

2. **The type-position erasure idiom (t80-t82) cannot apply.** The
   subset accepts `*T`/`chan T`/`func(...) T` in var-decl type
   position and erases them, but that pattern only produces
   *diagnostic* examples via the nil-check — `var p *int = nil;
   if p == nil {...}` — and Go structs are **not nilable**:
   `var s struct{} = nil` and `s == nil` are Go compile errors, so no
   native program can exercise a struct type that way. The only
   struct programs that compile natively are the diagnostic
   construction/member-access forms, which need member semantics the
   A1 lacks.

3. **The emitting form is a silent mis-lowering, not expression.**
   `s := struct{}{}` exits 0 but emits `Assign s = Call{getVar
   "struct"}` — the literal is dropped and `struct` is guessed to be
   a variable (Refuse > guess: "never a silent mis-lowering"). It
   must not be blessed as a coverage example; with the value unused it
   additionally fails the executed-stdout oracle natively (Go:
   "declared and not used").

This is NOT a by-design subset refusal: PARSER_GAPS.md's audit table
classifies `structType`/`fieldDecl`/`embeddedField` as **category-1
A1-EXTENSION** — "struct layout + member access need member offsets
the pointer/array model doesn't carry" — explicitly making Go structs
*requestable* A1 extensions, not dead ends (contrast `pointerType` /
`breakStmt`, category 2 = frontend-implementable with today's nodes).
The worker ledger refused-go-sh.txt does contain `fieldDecl`/
`embeddedField` from an earlier cycle — that is why rules-gap.sh
surfaced `structType` instead — but `structType` itself was never
ledgered, and the core-pending mechanism exists precisely to prune
escalated gaps once the contract has them (the recvStmt/commCase
precedents argued the identical point for channels/select). This
follows the py-sh-go sliceop/lambdef/star-expr and go-sh
recvStmt/commCase/typeArgs precedents: inexpressible because the A1
contract has no node/field, not because the subset refuses it.

## MINIMAL-CORE-CHANGE
The smallest change that would let the frontend express structType:

1. **Member-access keys on the existing var model** (mirrors the
   indexed-var precedent `a[1]` → `Assign{var:"a[1]"}`): struct
   member reads/writes lower to dotted var names — `s.X` →
   `getVar("s.X")`, `s.X = 7` → `Assign{var:"s.X", value:"7"}`, and
   `s := struct{ X int }{X: 5}` → one `Assign{var:"s.X", value:"5"}`
   per field. Contract side: validate/accept dotted member keys in
   the strict ingress deserializer (shir_json.rs / shir_json_in.rs)
   and document them in frontends/shir-contract/schema.json (keeps
   check_schema.py green) alongside the existing `a[1]`-style keys.
2. **Renderer side** (src/estree.rs / harness/estree-runner.mjs):
   render dotted member vars **bracketed** (`${s.X}`) — the bare
   `$s.X` form would expand `$s` and append `.X`, splitting the
   member. This is the only behavioral change to existing nodes, so
   current emits stay byte-identical.
3. Fuller variant (if value-level semantics are wanted later): struct
   values in the store + whitelisted `Call{func:"sh2.structGet",
   args:[structExpr, "X"]}` / `Call{func:"sh2.structSet", ...}`
   helpers (the A1's whitelisted-helper convention, like
   `sh2.makeChan`/`sh2.recv`), letting structs flow through
   expressions and function args. The minimal variant (1)+(2)
   suffices for the corpus's member-access forms; the estree worker
   mediates.

The frontend side (parse `structType` in type position; composite
literal + member access lowering; keep struct nil-check/equality/
value-passing Refuse > guess) is go-sh's own fix and lands after the
contract has the shape; the coverage worker retries the gap
automatically once this request completes.

## FAILING-CASE
Minimal Go program (valid; compiles and runs natively):

```go
package main

import "fmt"

func main() {
	s := struct{ X int }{X: 5}
	fmt.Println(s.X)
}
```

Native stdout: `5`.

Current behavior: `./go-sh --shir` refuses before lowering —
`go-sh: line 6: expected assignment operator, got "int"` (exit 2).
The other structural forms fail the same way:
- `var s struct{} = nil` → `go-sh: line 6: expected assignment
  operator, got "{"` (exit 2);
- `var s struct{ X int } = struct{ X int }{X: 5}` → same, `got "{"`;
- `s := struct{}{}` → exits 0 but silently mis-lowers to
  `Assign s = getVar("struct")` (the literal is dropped; must not be
  blessed — Refuse > guess forbids the guess, and the oracle would
  DIFF natively: Go rejects the unused `s` with "declared and not
  used" while the transpiled side prints).

So no testdata example can cover `structType`, and the A1 contract
lacks the struct/member-access shape end-to-end (frontend emit →
ingress acceptance → ESTree run vs native go stdout).

## OUTCOME: implemented

Core side (submodule 3cb121d): A1 dotted member keys (`s.X`) are accepted
store-name strings. The estree lift analyses (numeric_lift_vars /
string_lift_vars / local_lift_analysis) now refuse non-ident names, so a
dotted member assign lowers to `sh2.setVar("s.X", …)` and a member read
to `sh2.getVar("s.X")` — the runtime store keyed by the member name,
exactly the indexed-var (`a[1]`) precedent. Previously the numeric lift
turned `Assign{var:"s.X"}` into a native `let s.X = 0` binding (invalid
JS, SyntaxError at run). Runtime side (harness/sh2-namespace.mjs,
committed 10f281ea): expandWord's braced-name regexes accept dots, so
member refs in runtime-expanded text must/can render `${s.X}` (bare
`$s.X` stays split — bash-faithful). Contract side:
frontends/shir-contract/schema.json documents the dotted member-key
convention on assign_target.var. Verified: failing case end-to-end
(A1 ingress → estree → runner prints the member value), estree 521/521,
perl 325, cargo test --lib 276/0, check_ast 22/0.
