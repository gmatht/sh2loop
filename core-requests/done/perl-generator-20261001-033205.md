# perl-generator: `render_param`'s `"/"` arm shadows the correct one, so `${var/pat/rep}` never substitutes

Filed by the `perl-generator` worker. Gate: `./fail` (otranspilerl-cli `--target pl`
→ Perl → run vs bash, byte-for-byte stdout + exit code + side effects).
Baseline at filing: **503 passed, 54 failed out of 557**.

## The bug

`sh2perl/src/ir.rs::render_param` matches the substitution ops with **two**
arms whose patterns overlap:

```rust
// ir.rs:4421-4438
// Substitution: / first, // all.
"/" => format!(
    "(({} =~ s/{}/{}/r))",
    var,
    glob_to_regex(&val),          // <-- val / repl: already-rendered Perl LITERALS
    repl.trim_matches('\\')
),
"//" | "/" => {                    // <-- unreachable for op "/"
    let pat = args.get(2).and_then(call_arg_str).unwrap_or_default();  // raw text
    let rep = args.get(3).and_then(call_arg_str).unwrap_or_default();
    let g = if op == "//" { "g" } else { "" };
    format!(
        "(({} =~ s/{}/{}/{g}r))",
        var,
        glob_to_regex(&pat),       // <-- correct: raw pattern text
        rep.trim_matches('\\')
    ),
}
```

`val` and `repl` are computed once at the top of `render_param` via
`param_value`, which calls `render_str_literal` on the operand. So the FIRST
arm feeds a *rendered Perl string literal* into a `s///` as its pattern and
replacement. A quoted operand reaches the regex as a literal run of quote
characters:

```
   s=abc:def:ghi; echo "${s/abc/XYZ}"
   emits:  print("front=" . ((($s =~ s/"abc"/"XYZ"/r)), "\n");
```

`"abc"` is a pattern matching the text `abc` *surrounded by quote characters*,
which never occurs — so the substitution is a **silent no-op** and the
original string is printed unchanged.

`"/"` is matched first, so the correct `//" | "/"` arm never runs for a single
substitution. Its `"/"` alternative is dead code.

## Corpus impact (all `[perl] — stdout mismatch`)

| example | bash | generated Perl |
|---|---|---|
| `bench-strsubst.sh` | `front=XYZ:def:ghi` | `front=abc:def:ghi` |
| `bench-strsubst.sh` | `back=abc:def:XYZ` | `back=abc:def:ghi` |
| `062_hard_to_lex.sh` | substitutes | no-op |

A full-corpus census of the emitted shape finds exactly 3 occurrences:

```
$ for f in sh2perl/examples/*.sh; do otranspilerl-cli --target pl "$f"; done \
    | grep -oE 's/"[^"]*"/[^/]*/r' | sort | uniq -c
      1 s/"one"/"1"/r
      1 s/"ghi"/"XYZ"/r
      1 s/"abc"/"XYZ"/r
```

## The fix

**Delete the first arm.** The second arm already handles `"/"` correctly —
it reads the raw operand text with `call_arg_str` and sets `g = ""` when
`op == "/"`, which is precisely single-substitution semantics. Deleting the
shadowed arm is a pure deletion: no other arm, and no other backend's
behaviour, changes.

Equivalently, if the first arm is kept for some reason, it must use
`call_arg_str` on args 2 and 3 like its twin — but the two arms are otherwise
identical, so the arm is redundant.

## Why this cannot be fixed in the generator

`perl_generator_fixed.rs` is the one file the perl-generator worker owns, and
it wraps `shir_to_perl`. The defect is a **structural decision the renderer
makes about which arm to take** — the IR is already correct:

```
PG_DUMP_IR for bench-strsubst.sh:
  Call { func: "param", args: [
      Str("/", DoubleQuoted),
      Str("s",  DoubleQuoted),
      Str("abc", DoubleQuoted),   <-- already unquoted; correct in the IR
      Str("XYZ", DoubleQuoted),
  ] }
```

`fix_param_pattern_operands` (Fix 13 in `perl_generator_fixed.rs`) already
exists to strip operand quoting for exactly this family of ops, and it
correctly **declines here** — there is nothing to unquote. The re-quoting
happens *downstream*, inside the shared renderer, so no pre-pass can prevent
it and no post-pass can distinguish it from a legitimately quoted pattern.

A post-pass text rewrite *would* work mechanically (unwrap `"` around the
operands of an `s///`), but it would be a guess at renderer intent, and this
is a dead-arm deletion — the right fix is unambiguously the one-line removal.

## OUTCOME: rejected: already fixed in the shared core — verified end-to-end, so the proposed one-arm deletion has nothing left to delete. The shadowing arm is GONE: src/ir.rs:4454 now carries the comment "Substitution: / first, // all" followed by "BOTH arms read the RAW operand text with `call_arg_str`. A second `\"/\"` arm used to be matched FIRST, fed by `val`/`repl` (the results of `param_value`, which runs `render_str_literal` over a `Str` and so RE-QUOTES it)" — i.e. the file documents the exact defect this request describes, in the past tense, as the reason both arms now read raw text. VERIFIED by execution, not by reading: `s=abc:def:ghi; echo "front=${s/abc/XYZ}"; echo "back=${s//ghi/XYZ}"` now emits `s/abc/XYZ/r` and `s/ghi/XYZ/gr` (the request's broken output was `s/"abc"/"XYZ"/r`), and running the generated Perl gives `front=XYZ:def:ghi` / `back=abc:def:XYZ` — byte-identical to bash on both lines. Rejecting rather than re-deleting an arm that no longer exists; the file's census claim (3 corpus-wide occurrences) is likewise moot since the quoted pattern shape no longer occurs.
