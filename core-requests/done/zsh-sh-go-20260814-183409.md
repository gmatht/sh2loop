# zsh-sh-go: A1 contract has no node/field for zsh parameter-expansion flags (`${(flags)var}`)

## NEED
The A1 contract needs a representation for zsh parameter-expansion flags:
`${(f)var}` (split on newlines), `${(s:sep:)var}` (split on a separator),
`${(j:sep:)arr}` (join), `${(U)var}` / `${(L)var}` (case map), the
introspection flags (`${(k)var}`, `${(t)var}`, ...), and the SUBSCRIPT
search flags `${arr[(i)pat]}` / `${arr[(I)pat]}` / `${arr[(k)pat]}` /
`${arr[(r)pat]}`. Today the core's bash-shaped tokenizer absorbs the
`(flags)` prefix into the variable name: `${(f)x}` lowers to
`param("", "(f)x")` — a getVar of a name no real zsh variable can have —
so the flag semantics are dropped and the expansion always reads as
unset/empty. The tree-sitter-zsh `flag` node (flag_name + optional
separator) is exactly this syntax; the zsh-sh-go frontend's
byte-equality oracle is pinned to the core's tokenization, so neither
side can emit anything better until the core recognizes the prefix.

## WHY
The zsh-sh-go coverage step (ts-node-gap.sh, tree-sitter node-type
truth) reports `ts node flag` uncovered, but NO testdata example can be
created that passes the gate: for any set/non-empty parameter the
executed-stdout oracle diverges. Verified end-to-end:

    x=$'a\nb\nc'; echo "${(f)x}"
      native zsh 5.9   -> "a b c"   (3 words; the (f) flag split on \n)
      transpiled A1    -> ""        (param("", "(f)x") -> getVar -> unset)

    a=(x y z); echo "${a[(i)y]}"
      native zsh 5.9   -> "2"       (1-based index of the matching element)
      transpiled A1    -> ""        (param("", "a[(i)y]") -> getVar -> unset)

Only an UNSET/EMPTY parameter happens to coincide (both sides empty) —
a degenerate corner that would enshrine the mis-tokenization as
"covered" behavior (a passing test that hides a lowering gap, which the
project forbids blessing), not exercise the construct. The A1 param node
already carries runner-side conventions for zsh-only name shapes
(`getVar("#name")` length, `param("slice", name, "u"|"l", "")` case mods)
precisely because the contract defines those shapes' slots; a `(flags)`
name prefix has no contract-defined slot, so the runner cannot
legitimately interpret it.

## MINIMAL-CORE-CHANGE
In `src/parser/` (the braced-expansion chain, `parse_variable_expansion`
/ `parse_parameter_expansion_content`): recognize the zsh flag prefix
`(flag_name)` — and `(flag_name:sep:)` / `(flag_name.sep.)` — immediately
after `${` (also inside subscripts: `${arr[(i)pat]}` keeps the flag in
the subscript text, e.g. `arrayIndex`/param search form), split it off
the variable name, and carry it as an extra `param` arg so the
serialized A1 round-trips it, e.g.:

    param("", "x", "f")          # ${(f)x}
    param("", "x", "s", ",")     # ${(s:,:)x}
    param("", "arr", "i", "pat") # ${arr[(i)pat]}

(concrete arg layout open to the estree worker; must round-trip
shir_json.rs / shir_json_in.rs). The bash corpus cannot collide: real
bash rejects `${(...)` ("bad substitution"), so no corpus file produces
the new shape today. Then map it in `src/estree.rs` to a runner helper
(`sh2.getVar(name, {flags})` or a dedicated `sh2.paramFlags(...)` in
harness/sh2-namespace.mjs, zsh mode), implementing at least the common
flags (f, s:, j:, U/L, k, t, i/I) against the existing vars/arrays/
assoc stores. The zsh-sh-go frontend follows once the core emits the new
shape (its byte-equality oracle tracks the core; the subscript spellings
are already waiver-eligible via harness/zsh-subscript.ere).

## FAILING-CASE
```zsh
# /tmp/zflag.zsh — both flag spellings fail the executed-stdout oracle
x=$'a\nb\nc'
echo "${(f)x}"
a=(x y z)
echo "${a[(i)y]}"
```
```console
$ zsh /tmp/zflag.zsh
a b c
2
$ frontends/zsh-sh-go/zsh-sh-go --shir /tmp/zflag.zsh --raw
# {"func":"param",...,"args":[{"value":""},{"value":"(f)x"}]} and
# {"func":"param",...,"args":[{"value":""},{"value":"a[(i)y]"}]} — flags
# absorbed into the name; getVar returns "" for both
$ debashc --shir-in-estree ... | node harness/estree-runner.mjs ...
# prints two EMPTY lines — flag semantics lost
```

## OUTCOME: implemented — verified 2026-08-15 against HEAD+this round: `${(flags)var}` / `${(f:sep:)var}` / `${arr[(i)pat]}` parse to `param("", name, flags[, sep])` (ZshFlags operator), runner zshParamFlags covers t/f/s/j/U/L/k/i/I, and THIS round fixed the two remaining estree-path joins (array-returning f/s/k flags: join-identity fold keeps `join(param)` for templates; exec_arg_is_array_valued keeps the bare call for unquoted words) — all request failing cases now print native-zsh bytes end-to-end (zflag/zsep/zf2 MATCH). Estree corpus stays at the 545/546 baseline; PERL count unchanged.
