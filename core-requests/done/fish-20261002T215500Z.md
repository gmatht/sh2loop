# fish backend — core request: `if (( ... ))` mis-emitted as a bogus `let` call

- filed: 2026-10-02T21:55Z
- from: `backend/fish` worktree (`/home/llm/sh2loop/sh2perl/backends/fish`, branch `backend/fish`)
- kind: **bug in an existing shared emit path** (not a missing node) → legacy `.md` per `core-requests/README.md` §"Legacy .md requests"

## NEED

The shIR **emit** path (`otranspilerl --target shir`) mis-parses the bash
arithmetic-command form `if (( EXPR )); then …; fi`. It emits a fabricated
`builtin let` call whose argument is the condition flattened into one opaque
`SingleQuoted` string, instead of an arithmetic node.

## WHY

`(( … ))` in `if`/`while` condition position is common in the corpus (81
files contain `((`), and 8 of them are affected. The corrupted node is not
recoverable downstream, so **every** backend that ingests shIR JSON is
handed a construct that no renderer can lower:

- the fish renderer sees a `Call{func:"builtin", args:["let", ["$n == 5"]]}`
  and must guess, so it emits a `math "…"` call whose body still contains
  `string match -qr -- '^-?[0-9]+$'`, i.e. a literal `$` inside a fish
  double-quoted string → `$' is not a valid variable in fish` → the whole
  file fails `fish -n` (20 of the fish gate's PARSE failures trace back to
  this);
- the arithmetic is silently lost even where the file happens to parse.

The IR is not lost in the tree: the same in-process parser feeding the C
backend produces correct code for the identical source, so the arithmetic
node exists and is reachable — only the **shIR JSON serialization** loses it.

## MINIMAL-CORE-CHANGE

In the shIR emit path (the `stmt`/`expr` lowering that turns a parsed
`(( … ))` arithmetic command into a contract node), stop collapsing the
`if`/`while` condition into `Call{func:"builtin", args:["let", …]}` with the
expression as one `SingleQuoted` string. Emit the arithmetic node the parser
already built — the one the C backend consumes — so the JSON carries real
structure (operator, operands, var types) instead of an opaque literal.

Concretely, for `if (( $n == 5 ))`:

```json
"cond": { "type": "Arith", "ast": { "op": "Eq", "lhs": {"type":"Var","name":"n"}, "rhs": {"type":"Int","value":5} } }
```

instead of:

```json
"cond": { "type": "Call", "func": "builtin",
          "args": [ {"type":"Str","style":"DoubleQuoted","value":"let"},
                    {"type":"Array","elements":[{"type":"Str","style":"SingleQuoted","value":"$n == 5"}]} ] }
```

`while (( i < 3 )); do …; done` is affected identically and should be fixed
by the same change. No new contract node is required if `Arith` already
exists in the contract — please confirm and, if it does, fix only the emit
path; if the arithmetic context is genuinely absent, use a `contract-gen`
spec instead of an `.md`.

## FAILING-CASE

```sh
printf 'n=5\nif (( $n == 5 )); then echo equal; fi\n' > /tmp/t5.sh
otranspilerl --target shir /tmp/t5.sh | jq '.stmts[1].cond'
```

current (broken):

```json
{"type":"Call","func":"builtin","purity":"Emulable",
 "args":[{"type":"Str","style":"DoubleQuoted","value":"let"},
         {"type":"Array","elements":[{"type":"Str","style":"SingleQuoted","value":"$n == 5"}]}]}
```

expected: an arithmetic condition node (see MINIMAL-CORE-CHANGE).

Corpus blast radius (measured, `--target shir` on `examples/*.sh` +
`frontends/*/testdata/*.sh`):

- files containing `((`: **81**
- of those, emitted with the bogus `let`: **8**

Affected fish gate buckets today: 20 PARSE + a share of the 148 OUT
divergences. Once the emit is fixed, the fish renderer should be able to
lower these natively (`math` already handles the expression); no fish-side
change is required for the construct itself.

## OUTCOME: implemented — the shIR emit for `if (( $n == 5 ))` now produces a real Arith condition node (`{"type":"Bin","lhs":{"type":"Var","name":"n"},"op":"==","rhs":{"type":"Num","value":5}}`) instead of the fabricated `builtin let`. Verified via `--target shir`.
