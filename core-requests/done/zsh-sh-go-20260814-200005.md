# zsh-sh-go: A1 has no correct lowering for the translated string `$"..."` (ts node `translated_string`) — the core's DollarDoubleQuotedString arm leaks the quotes

The zsh-sh-go coverage sweep (tree-sitter node-type truth) reports the
tree-sitter-zsh `translated_string` node (`$` + `string`, grammar rule
`translated_string`: `"$"` followed by a double-quoted `string`) as
uncovered by testdata, and NO example can pass the zsh gate: the shared
core's `DollarDoubleQuotedString` token is mis-lowered, the zsh
frontend cannot byte-match it, and the core's own emit is wrong for
bash too.

## NEED

The shared core must lower `$"..."` (the bash/zsh translated string,
lexer token `DollarDoubleQuotedString`, regex `\$"([^"\\]|\\.)*"` in
src/lexer.rs) into an A1 shape that (a) round-trips shir_json.rs /
shir_json_in.rs, (b) the zsh frontend can emit byte-identically, and
(c) the estree runner evaluates to the value native zsh 5.9 produces.

Root cause, pinpointed: `parse_string_interpolation`
(src/parser/words.rs) strips the outer quotes only when the token text
starts with `"`:

    let content = if string_content.starts_with('"') && string_content.ends_with('"') {
        &string_content[1..string_content.len() - 1]
    } else { &string_content };

The `DollarDoubleQuotedString` token text is `$"hello"` — it starts
with `$`, so NOTHING is stripped and the raw `$"hello"` (quotes and
dollar included) becomes one Literal part:
`Interpolate[lit "$\"hello\""]`. The `DollarSingleQuotedString` sibling
has a dedicated correct path (`parse_ansic_quoted_string`); the DQ
variant has no equivalent.

## WHY

For `echo $"hello"` the three sides disagree, and the gate needs the
frontend emit to equal the core emit (byte-equality, `make test`
phase 1) AND the transpiled stdout to equal native zsh (phase 2):

    echo $"hello"
      native zsh 5.9          -> "$hello"   (literal $ + DQ content;
                                              this zsh build has no
                                              gettext translation)
      frontend emit (today)   -> Str "$hello"   -> estree prints "$hello"   (stdout-correct!)
      core emit (today)       -> Interpolate[lit "$\"hello\""] -> estree prints
                                 $"hello"   (quotes leaked; wrong for bash
                                 too — bash prints "hello" for $"hello")

So the executed-stdout oracle is already satisfiable with the
frontend's EXISTING lowering (`$` literal + DQ content — verified
end-to-end through `--shir-in-estree` + harness/estree-runner.mjs),
but the byte-equality phase DIFFs in every context (word position,
assignment `x=$"y"`, adjacent fragments `echo pre$"mid"post`,
interpolated content `echo $"$x"` → core emits
`Interpolate[lit "$\"", getVar(x), lit "\""]`). The array-subscript
waiver (harness/zsh-subscript.ere) does not match `$"`, so no example
can ride it. The frontend does not refuse the construct (FRONTEND.md
lists no exclusion); it is inexpressible purely because the core's A1
output for `$"` cannot be byte-matched.

No bash-corpus regression risk: `grep '\$"'` over sh2perl/examples/
hits only `$` before a CLOSING quote inside DQ strings (`echo "the
price is $"`, `grep "\.txt$"`), never the `$"`-opens-a-string
construct — so changing the `DollarDoubleQuotedString` lowering cannot
affect `./fail` or the ESTree corpus.

## MINIMAL-CORE-CHANGE

In `parse_string_interpolation` (src/parser/words.rs), handle the
`DollarDoubleQuotedString` spelling: when the token text starts with
`$"`, strip the `$"` prefix AND the closing `"` before
`unescape_interpolation_content` / `scan_interpolation_parts`, and
represent the construct so the estree runner can tell the languages
apart. Two candidate shapes (concrete arg layout open to the estree
worker; must round-trip shir_json.rs / shir_json_in.rs):

- (a) minimal, gate-unblocking: emit the content parts prefixed by a
  literal `$` part — `Interpolate[lit "$", <content parts>]`,
  collapsing to `Str "$hello"` for plain content. This byte-matches
  the zsh frontend's current emit (`Str "$hello"`,
  `Interpolate[lit "$", getVar(x)]` — verified) with NO frontend
  change, and the runner already prints `$hello` for it (zsh-correct).
  Cost: the core's bash semantics for `$"..."` become `$hello` rather
  than bash's `hello` (zero corpus impact today, as above).
- (b) semantically clean for bash: a dedicated node/field carrying the
  translated content (e.g. a `translate(...)` func or `LocaleString`
  node with the interpolated content as its value), dispatched
  per-language in harness/sh2-namespace.mjs like the existing
  `_setLang("zsh")` split no-op: bash mode → content (`hello`), zsh
  mode → `$` + content (`$hello`). Requires the zsh frontend to follow
  the new shape (its byte-equality oracle tracks the core).

Either way the FAILING-CASE below must print `$hello` / `$world` via
`--shir-in-estree` + harness/estree-runner.mjs, and the zsh frontend's
emit must equal the core's byte-for-byte.

## FAILING-CASE

```zsh
# /tmp/zts.zsh — translated string, plain and interpolated
echo $"hello"
x=world
echo $"$x"
```
```console
$ zsh /tmp/zts.zsh
$hello
$world
$ frontends/zsh-sh-go/zsh-sh-go --shir /tmp/zts.zsh --raw
# emits Str "$hello" and Interpolate[lit "$", getVar(x)] — stdout-correct
# (verified via --shir-in-estree + estree-runner.mjs: "$hello" / "$world"),
# but byte-DIFF against the core, so `make test` fails at phase 1
$ debashc --shir /tmp/zts.zsh --raw
# Interpolate[lit "$\"hello\""] / Interpolate[lit "$\"", getVar(x), lit "\""]
# — quotes leaked; estree prints $"hello" / $"world" (wrong for bash too)
$ cd frontends/zsh-sh-go && make test
# DIFF t94_translated_string.zsh (frontend != core — the gap the worker fixes)
```
