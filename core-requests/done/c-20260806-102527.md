# c: `--shir --raw` stack-overflows on nested command substitution (var_lengths regression on main)

## NEED
`debashc <file> --shir --raw` must not stack-overflow on the corpus.
The C backend gate (`setup_backends.sh --backend-gate c`) emits shIR via
the SHARED main-core binary; the overflow aborts the gate (rc=134) on
`examples/000__04a_basic_command_substitution.sh`, so the C gate cannot
reach its valgrind/equivalence stages.

## WHY
Introduced by fbedac4 (analyze_string_lengths / var_lengths). The
worktree core at 2b85785 (pre-fbedac4) emits the same file fine (rc=0);
the main core (fbedac4) overflows:

    DEBUG: String interpolation parsed command 'date +%Y' as 1 commands
    DEBUG: String interpolation parsed command 'basename $(pwd)' as 1 commands
    thread 'main' (83114) has overflowed its stack
    fatal runtime error: stack overflow, aborting   (rc=134)

Reproduce: `sh2perl/target/debug/debashc --shir sh2perl/examples/000__04a_basic_command_substitution.sh --raw`
The file nests `$(...)` captures several levels deep (`date +%Y` inside
`basename $(pwd)` etc.); the recursion is `expr_len` ->
`capture_bound` -> `capture_stages` -> nested `Capture`/`Arrow`/`Interpolate`.

## MINIMAL-CORE-CHANGE
In `shir::analyze_string_lengths` (src/shir.rs ~line 1726), bound the
analysis recursion depth (e.g. a depth parameter on expr_len /
capture_bound / capture_stages, returning None past a cap like 256) or
convert the capture-walk to an explicit stack. A conservative `None`
(unbounded) verdict is contract-safe — the annotations are additive and
backends ignore them.

## FAILING-CASE
`sh2perl/examples/000__04a_basic_command_substitution.sh` — minimal shape:
    p=$(pwd)
    b=$(basename "$(pwd)")
    echo "$(basename "$(date +%Y)")"
