# c-sh-go: the A1 ForInit node panics the ESTree renderer — the existing strip_cfor pass is never wired into the ingress pipelines

## NEED

`debashc --shir-in-estree` (the c-sh-go gate's ingress-acceptance oracle) must
handle the A1 `ForInit` node the C-family frontends emit for `for (init; cond;
step) body`. The lowering pass already EXISTS (`src/shir_passes/strip.rs`,
committed, unit-tested) — it just is never invoked and isn't even exposed
from `src/shir_passes/mod.rs`. Wire it in:

1. `src/shir_passes/mod.rs` (after `pub mod restructure;`, line 51):
   ```rust
   pub mod strip;
   pub use strip::strip_cfor;
   ```
2. `cli/src/lib.rs` — call `debashl::shir_passes::strip_cfor(&mut prog)`
   immediately after `debashl::shir_passes::restructure_goto_only(&mut prog)`
   in the three A1-ingress paths (they currently call only
   restructure_goto_only + process_subst):
   - `--shir-in-estree` (line 932)
   - `--shir-in-perl` (line 962)
   - `--shir-in-sh` (line 986)
3. `src/wasi_api.rs` — the busybox/otranspilerl A1 ingress also renders
   frontend A1 without the strip: in `otranspilerl_render` (line 250) and in
   the `src_lang == "shir"` branch of `otranspilerl_transpile_impl`
   (line 223), call `crate::shir_passes::strip_cfor(&mut prog)` after
   `shir_json_to_ir` and before `render_ir`.

strip.rs's own header documents this as the intended wiring: "A renderer that
encounters an UNSTRIPPED ForInit refuses (REFUSE > GUESS) — the pipeline runs
this pass before every renderer, so reaching one means a pipeline forgot the
strip."

## WHY

The c-sh-go gate (`make test` in `frontends/c-sh-go`) fails on the FIRST for
loop, `t06_for.c`:

```
OK t05_while.c (valid A1 shIR — the core deserializer accepts it)
FAIL t06_for.c (emit is not valid A1 shIR — the gap the worker fixes)
```

The emitted A1 is contract-valid (the deserializer accepts it; the A1
`ForInit` node and `strip_cfor` were added together in workspace commit
2d577e6, and `frontends/shir-contract/schema.json` carries it). The failure
is a core pipeline gap: `--shir-in-estree` deserializes, then
`shir_to_estree_json` hits `unreachable!("Perl-only IR statement reached the
ESTree renderer: ForInit")` in `stmt_to_estree` (src/shir.rs:13915) → panic
→ exit 101 → the gate reports "emit is not valid A1 shIR".

The gate was green at 20:18 (86/86) — the estree worker's in-flight WIP
(same diagnosis as the pending py-sh-go-20260812-165614 request: the CLI
once called `shir_passes::strip_cfor`, the lib never exposed it) was
reverted, and the current tree (built binary 20:55) has no ForInit handling
anywhere in the renderer paths. cpp-sh-go emits the same `ForInit` node
(its gate scratch shows `"type":"ForInit"` for t05_arith_loop.cc) and will
hit the identical panic once its binary rebuilds.

## MINIMAL-CORE-CHANGE

The three edits above — expose the existing pass and call it in the four
A1-ingress render paths. No new logic: `strip_cfor` already implements the
continue step-splice semantics (step re-inserted before every top-level
`continue`, recursing into If/Block but not nested loops) and has a passing
unit test (`forinit_lowers_to_while_with_step_and_continue_splice`).

## FAILING-CASE

Repro (no frontend rebuild needed):

    cd /home/llm/sh2loop/frontends/c-sh-go
    ./c-sh-go --shir testdata/t06_for.c --raw > /tmp/t06.json
    ../../sh2perl/target/debug/debashc --shir-in-estree /tmp/t06.json

→ panics: `internal error: entered unreachable code: Perl-only IR statement
reached the ESTree renderer: ForInit { init: [Assign ... i = 0 ...], cond:
Call { func: "test", args: [Str("$i -lt 3")] }, step: [...], body: [...] }`

Minimal source:

```c
#include <stdio.h>
int main(void) {
    int i;
    for (i = 0; i < 3; i += 1) {
        printf("f%d\n", i);
    }
    return 0;
}
```

After the fix, `--shir-in-estree` must exit 0 and emit an ESTree program
whose executed stdout matches gcc: `f0\nf1\nf2\n`.

## OUTCOME: implemented: `strip_cfor` exposed (src/shir_passes/mod.rs `pub mod strip; pub use strip::strip_cfor;`) and wired into all A1-ingress render paths (cli --shir-in-estree/--shir-in-perl/--shir-in-sh, wasi otranspilerl_render + otranspilerl_transpile_impl), run BEFORE restructure_goto_only (a goto can sit inside a ForInit body — t30_goto_nested.c). Verified: t06_for.c and t30_goto_nested.c render and execute matching gcc; c-sh-go gate 86/86.
