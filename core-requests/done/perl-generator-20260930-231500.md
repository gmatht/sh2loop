# perl-generator: shared-core renderer drops process-substitution consumers and mis-renders `${var+word}` / `@`-slices

Filed by: the Perl GENERATOR worker (`sh2perl/src/perl_generator_fixed.rs` is
mine; `ir.rs` is not). Measured with the strict gate `./fail` at **56 failures
/ 555** on 2026-09-30, CLI `fa509352`, submodule `c32ad5b5d`.

Each item below is a defect in the SHARED CORE (`sh2perl/src/ir.rs`), verified
by dumping the IR (`PG_DUMP_IR=1`) and the rendered Perl

In every case the **IR is correct** and the renderer loses the information, so

## 1. A materialised `<(…)` CONSUMER is silently dropped (HIGH — silent wrong output)

### Minimal repro (2 lines, no corpus entry needed)

```bash
printf '#!/bin/bash\ndiff <(echo one) <(echo two)\necho "exit: $?"\n' > /tmp/ps.sh
otranspilerl-cli --target pl /tmp/ps.sh
```

bash prints `1c1 / < one / --- / > two / exit: 1`. The generated Perl prints
**only** `exit: 1` — the `diff` is gone entirely, and the `$?` is reported by
the trailing `rm -f` bookkeeping rather than by the diff.

### The IR is right

`transforms::process_subst` materialises the block as:

```
Block[
  Assign(__ps_tmp0, capture(mktemp)),
  Redirect([Output "one"], fd 1 -> __ps_tmp0),
  Assign(__ps_tmp1, capture(mktemp)),
  Redirect([Output "two"], fd 1 -> __ps_tmp1),
  Expr(Call{func:"builtin", args:["diff", Array([Var __ps_tmp0, Var __ps_tmp1])]}),
  Exec(rm -f __ps_tmp0 __ps_tmp1),
]
```

The consumer `diff __ps_tmp0 __ps_tmp1` is present and correct.

### Where it is lost

`ir.rs:2355` `IrStmt::Block(stmts)` renders a block as a **flat sequence of
statements**, so the two `Assign`/`Redirect` producer pairs and the trailing
`rm` are each emitted in full (the temp files are created, written, unlinked)
while the consumer between them is never emitted. `procsub_materialization_to_cmd`
(`ir.rs:5549`, wired at `ir.rs:5685` under `expr_to_cmd`'s `"and"` arm) is the
existing helper that DOES know how to rebuild the consumer — but it is only
reached on the **pipeline-stage** path. A procsub used in a plain statement
position (`diff <(a) <(b)`, `head <(cmd)`, `mapfile < <(cmd)`) never hits it.

A plain `diff FILE FILE` with real files renders correctly (it hits
`pipeline_native::native_exec_stmt`), which is why this only shows up with
procsub args: the native leaf declines, the uu-ffi seam is skipped, and
`build_shell_cmd` walks the block, dropping the consumer.

### Suggested fix

In the perl renderer's `Block` arm, detect a procsub materialisation block
(presence of `Assign(__ps_tmp*, capture(mktemp))` + `Redirect` to that tmp +
a trailing `rm -f __ps_tmp*`) and re-enter it through the existing
`procsub_materialization_to_cmd`, which already reconstructs
`diff <(echo one) <(echo two)` correctly. That helper is the natural
single point of repair and is shared with the other backends.

### Corpus examples it owns

- `process-substitution.sh` — output entirely missing (`diff <(echo one) <(echo two)`)
- `096_head_procsub.sh` — `head <(while true; …)` hangs: the producer runs
  unbounded with its stdout to a temp file nobody drains, so the gate hits
  `timeout` (rc=124) where bash exits 0
- `012_process_substitution.sh`, `042_process_substitution_advanced.sh` pass
  today only by accident (their consumers are no-ops on empty input)

## 2. `${var+word}` / `${var-word}` — the "is it set" test (MEDIUM)

`examples/variable-plus-operator.sh`:

```bash
if test -n "${MYVAR+set}"; then echo "MYVAR is set"; fi
```

`MYVAR` is never assigned, so bash expands `${MYVAR+set}` to the EMPTY string,
`test -n ""` is false, and **nothing** is printed. The generated Perl prints
`MYVAR is set`.

The IR carries `Call{func:"param", args:["", "MYVAR+set"]}` — note the name
still carries the `+set` suffix, i.e. the op was never separated out.
`render_param` (`ir.rs:4266`) has arms for `-`, `:-`, `=`, `:=`, `#`, `%`,
`^^`, `,,`, `slice`, `/`… but **no arm for `+`/`+:` (or `-` used as the
"is set" test)**, so the expansion falls through to a default that returns the
word unconditionally.

Bash's four forms: `${v+w}` (set→w), `${v:-w}` (set **and non-empty**→w),
`${v+w}` vs `${v-w}` differ only on "set but empty". The `-` arm currently
implements the `:-` (non-empty) semantics, which is right for `:-` and wrong
for `-`.

### Corpus example

- `variable-plus-operator.sh`

## 3. `@`-slice reads `@ARGV` while the rest of the program reads the rewritten argument array (MEDIUM — latent inconsistency)

`render_param`'s `"slice"` arm (`ir.rs:4429`) emits
`join(' ', @ARGV[$start..$#ARGV])` for `${@:off:len}`. But this module's Fix 2
(`rewrite_positional_params`, `perl_generator_fixed.rs:758`) deliberately
binds a function's positional parameters into `@__sh_args` precisely because
`do FILE` empties `@ARGV`. So a `${@:N}` slice inside a function reads the
empty script-level `@ARGV` while every other `$1`/`$@` read in the same body
reads `@__sh_args` — the two disagree.

`examples/parse-at-slice-param.sh` is a top-level case and shows a related
off-by-one: bash's `set -- "$1" "$tempfile" "${@:3}"` then `${@:1}` yields
`[A  C D]` (bash drops the first word of the list because the script is run
with `$1` already consumed); the Perl side yields one extra leading field.

**Ownership question for the core:** should the `@`-slice arm be routed
through the same parameter-rewriting the generator does, i.e. is the
"positional parameters live in `@__sh_args`" convention meant to be a core
concern rather than a generator-level text fix? Right now the two layers each
know half the rule.

## 4. `printf '%q'` is a bashism Perl's printf does not implement (SMALL but user-visible)

`examples/parse-dollar-single-quote.sh` runs `printf '%q' "$IFS"` with
`IFS=$'\n\t'`. bash's `%q` is an **extension** that shell-quotes its argument
(`$'\n\t'`); Perl's `printf` has no `%q` and emits the two characters `%q`.

The generated Perl here is `printf("%q", "\n\t")` — the IR is right (the parser
decoded `$'\n\t'` to a real `"\n\t"`), the renderer just doesn't know `%q` is
bash-only. Any `%q` in a format string needs a shell-quoting helper; the
generator can lower it post-hoc, but the correct place is the shared `printf`
format arm next to the `\n`/`\t` escape decoding already there.

### Corpus example

- `parse-dollar-single-quote.sh`
