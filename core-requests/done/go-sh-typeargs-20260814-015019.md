# go-sh: generic instantiation (`typeArgs`) — the A1 has no type system or compile-time substitution for Go generics

## NEED
The A1 shIR must give the go-sh frontend a way to lower Go generic type
instantiation — ANTLR rule `typeArgs` (`Name[TypeList]`: `f[int](x)`,
`Box[int]{...}`, `var x Box[int]`, `x.(Box[int])`, `*Box[int]`) —
faithfully. Today no A1 node/field can represent a generic declaration
or its call-site instantiation: the A1 store is an untyped runtime
string/array model (shell-shaped), with no type parameters, no type
arguments, and no compile-time phase. `typeArgs` is a grammar-rule
coverage gap for go-sh (unexercised in all 83 testdata examples;
`frontends/coverage/rules-gap.sh go-sh` lists it); the frontend parser
fails loud on every typeArgs context before lowering can be attempted.

## WHY
Go generics are a compile-time feature: `f[int](x)` instantiates the
generic function `f` with the type argument `int`; the argument is
erased at runtime, but the instantiation must be resolved (call-site
substitution / monomorphization) before the generic body can be
lowered. The go-sh frontend's philosophy is Refuse > guess: with
today's nodes the only "lowering" would be dropping `[int]` and hoping
the body is type-independent — a silent mis-lowering the moment the
body uses `T` in a type-dependent way (`var z T` needs T's zero value;
arithmetic/comparison on `T` differs per concrete type). A faithful
emit requires the A1 to either carry the generic structure (so the
transpiler can substitute) or define an erasure contract the frontend
can rely on. Without that, the go-sh parser must keep refusing the
construct (PARSER_GAPS.md, go-sh table, category 1: "the type system +
generics: the A1 store has no types; type decls have no runtime
semantics, generics need call-site substitution").

The sibling generics rules (`typeDecl`/`typeSpec`/`aliasDecl`/`typeDef`/
`typeParameters`/`typeParameterDecl`/`typeElement`/`typeTerm`) are
already ledgered in `frontends/coverage/refused-go-sh.txt` pending this
same mechanism; `typeArgs` itself is the one open gap of the cluster.

## MINIMAL-CORE-CHANGE
The smallest change that would let the frontend express typeArgs:

1. A **type-argument carrier** on the A1 call model: an optional
   `typeArgs: [Str]` field on `Call` (and a `typeParams: [Str]` on
   `Function` for the declaration side), serialized in the A1 JSON
   contract (shir_json.rs / shir_json_in.rs) and accepted by the
   deserializer's ingress gate — the frontend then parses
   `Name[TypeList]` and emits the type-argument list verbatim instead
   of refusing.
2. A **documented erasure contract** for the runtime: the ESTree
   renderer drops `typeArgs` when emitting (type arguments have no
   runtime form in the string store), and generic declarations whose
   bodies are type-independent lower as ordinary `Function`; the
   frontend keeps refusing only type-DEPENDENT bodies where erasure
   would change behavior (`var z T`, `T`-typed arithmetic/comparison).

Minimal variant if a full substitution mechanism is too invasive: the
`typeArgs` field with **no-op runtime semantics** (dropped in
rendering) plus a frontend-side rule that only type-independent generic
bodies are lowered — the type-INDEPENDENT subset of Go generics
(identity/wrapper functions like `func id[T any](x T) T { return x }`,
boxed literals) becomes expressible end-to-end.

## FAILING-CASE
frontends/go-sh/testdata has no typeArgs example; the minimal Go
program the frontend currently REFUSES (parse error, exit 2):

    package main

    import "fmt"

    func id[T any](x T) T { return x }

    func main() {
        fmt.Println(id[int](5))
    }

Current frontend behavior:

    $ ./go-sh --shir t.go --raw
    go-sh: line 8: unsupported call "" in word position (v2)
    exit=2

The other three typeArgs contexts refuse the same way (all fail-loud,
exit 2):
- `b := Box[int]{v: 7}` → `go-sh: line 4: index key must be a number literal (v2)`
- `var x Box[int]` → `go-sh: line 6: expected number token, got "int"`
- `if v, ok := x.(Box[int]); ok { ... }` → `go-sh: line 7: expected "{", got ","`

Native Go stdout: `5`. A faithful transpiled output must produce the
same for any type-independent generic body — impossible without the A1
type-argument representation + erasure contract above.

typeArgs on Call + typeParams on Function accepted by the A1 deserializer (validated as string arrays) with the documented ERASURE contract (dropped at ingress — no runtime form; the frontend only lowers type-independent bodies). Verified: valid ingress rc=0, non-string entry refuses, re-serialized A1 carries no typeArgs/typeParams.
