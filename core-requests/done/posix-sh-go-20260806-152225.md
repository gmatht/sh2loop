## NEED
The A1 contract must carry the **quoted vs unquoted** distinction for
expansion sites where bash field-splits, and the ESTree lowering +
runner must honor it. Today `for w in "$y"` and `for w in $y` are
**byte-identical** in A1 — both emit the For.iter element as
`Call{func:"getVar", args:[Str "y"]}` — so the ESTree backend lowers
both to a native `ForOfStatement` over `[].concat(y)` (one iteration)
and the runner never splits.

## WHY
`frontends/posix-sh-go` gate (run via `make test`): all 56 testdata
scripts are A1 **byte-equal** to the core frontend (`debashc --shir
--raw`), so the frontend cannot deviate; but the executed-stdout
comparison (harness/frontend-stdout.sh: frontend A1 →
`debashc --shir-in-estree` → node harness/estree-runner.mjs vs native
bash) fails 1/56:

    testdata/t04_params.sh:
      y="hello world"
      for w in $y; do echo "word=$w"; done
    bash:             word=hello / word=world
    core pipeline:    word=hello world   (single iteration)

Verified the CORE's own pipeline (`debashc --shir` → `--shir-in-estree`
→ runner) produces the identical wrong output from the core's own A1 —
a pure shared-core gap, not a frontend gap. (`echo $y` looks right
only accidentally — echo joins its args with spaces.)

## MINIMAL-CORE-CHANGE
No new IR node or deserializer work — `Call` already round-trips
through shir_json.rs / shir_json_in.rs. Concrete sites:

1. **Core frontend lowering** — `for_items_ir`/`for_item_ir`
   (src/shir.rs:3898 / 4969): the `Word::Variable` and
   `Word::StringInterpolation` arms go through `word_ir` →
   `arg_word_ir` (src/shir.rs:3979), which emits a bare `getVar`
   ignoring the word's quote annotation (the `Word` ann / quote
   marker, the same info GLOB_MAGIC already consumes at
   src/shir.rs:3981-3989 for unquoted glob words — the contract
   precedent for tagging unquoted word positions). Emit
   `Call{func:"split", args:[<expansion>]}` for **unquoted**
   expansions in a for-iter element; quoted expansions keep the bare
   `getVar`. (Same pattern, optional breadth: unquoted expansions in
   exec-arg Arrays — the `set -- $y` case, `exec_args_ir`.)
2. **ESTree lowering** (src/estree.rs, the `For.iter` → ForOfStatement
   path): lower `split(x)` to `x.split(/\s+/)` (default-IFS whitespace
   splitting, filtering empty fields), so the native `ForOfStatement`
   iterates per field and the runner needs no new helper.
3. Optional (documentation only): note `split` as a reserved `Call`
   func in the A1 contract docs.

Scope note: fixing for-iters is sufficient for the failing gate
(t04_params.sh); the `set --` case is the same one-line pattern and
should ride along only if it doesn't regress `./fail-estree`.
