# sh: process substitution <(...) is silently dropped — emit process-in + a temp-file materialization transform

## NEED
1. The sh backend's core (the `backend/sh` branch's `src/shir.rs`,
   `redirect_to_ir`) must map process substitution to the process-in /
   process-out redirect modes like main does, instead of `("unsupported", 0)`
   (worktree lags core-request `perl-shir-20260806-1930`, which landed on main).
2. A SHARED IR transform (`src/transforms/process_subst.rs`, registered in
   `transforms.rs`) that lowers `process-in`/`process-out` redirects into a
   temp-file materialization: run the producer, capture its stdout to a
   mktemp file, pass the path in place of the argument / as the redirect
   target, clean up after. POSIX sh has NO `<(...)`, so the lowering MUST be
   statement-level (producer-write before the exec, cleanup after) — a
   per-command redirect-string patch cannot express it.
3. Stopgap until then: `sh_backend.rs`'s `redirect_to_sh` treats
   `"unsupported" => Ok(String::new())` (silently drops the redirect) —
   refuse loudly (`Err`) instead. Same for the estree/perl paths' unknown
   modes if any.

## WHY
The chimera gate (bash-free sandbox: BSD shell + busybox) caught it:
`019_grep_regex.sh` line 22 `grep -f <(echo -e "error\nwarning")` renders as
bare `grep -f` — the process-substitution argument vanishes, and every grep
errors (`option requires an argument -- 'f'`). Root cause chain:
- worktree `redirect_to_ir` → mode `"unsupported"` (main has process-in;
  the branch core is behind)
- `redirect_to_sh` drops `"unsupported"` redirects silently — a
  refuse-loudly violation; the corrupted command is emitted as if valid.
The estree path already works (inline AST pre-pass `transform_cmd` in
estree.rs: `<()` → here-string of the producer's captured stdout + a
`\u{1}SH2PS\u{1}` magic argument the runtime materializes to a temp file;
012/040/042 all pass the estree gate). The perl path shells out to bash and
appends ` <(cmd)` (bash expands natively) — only viable because perl still
needs bash. The sh backend targets bash-free POSIX, so it needs the
materialization IN the emitted sh.

## MINIMAL-CORE-CHANGE
1. `src/shir.rs` `redirect_to_ir`: `ProcessSubstitutionInput(cmd)` →
   `("process-in", 0)` with target = `command_to_shell_text(cmd)`;
   `ProcessSubstitutionOutput(cmd)` → `("process-out", 1)` (mirror main).
2. `src/transforms/process_subst.rs`: for each `IrStmt::Exec` with a
   `process-in`/`process-out` redirect, rewrite to a `Block`:
   `tmp=$(mktemp)`; producer(s) write the temp file(s); the exec's arg /
   redirect target becomes the tmp path; `rm -f` the temp after. Producer
   stdout must be captured at IR level (the target already carries the
   producer's shell text; wrap in a capture and materialize). Register in
   `transforms.rs` (env-gated like `seq_range_for`). The estree backend
   keeps its pre-IR pass (or consumes the transform instead — its choice).
3. `backends/sh/src/sh_backend.rs`: unknown/unsupported redirect modes →
   `Err(...)` (refuse loudly), never `Ok("")`.

## FAILING-CASE
```sh
echo -e "error\nwarning" | grep -f <(echo -e "error\nwarning")
```
`debashc --shir --raw` (backend/sh build) shows the redirect as
`{"fd":0,"mode":"unsupported",...}`; `--shir-in-sh` emits `grep -f` with no
argument (fails under dash, busybox, and GNU grep alike). Expected: a
materialized POSIX form (producer → tmp file, `grep -f <tmp>`, cleanup) that
prints the two matching lines under any sh.

## OUTCOME: implemented — (1) redirect_to_ir maps ProcessSubstitutionInput/Output → process-in/process-out in the shared core AND the sh worktree (mirror); (2) src/transforms/process_subst.rs registered in transforms.rs (serves the --shir export and the A1 ingress — frontend-emitted process-in/out materializes to mktemp files; the estree file pipeline rewrites <() pre-IR in estree.rs transform_cmd); (3) this round the main-mirror sh renderer's legacy "unsupported" redirect arm now refuses loudly (Err) instead of silently dropping (the 019_grep_regex `grep -f <(...)` corrupted-command case). 019_grep_regex.sh passes perl + estree gates. The sh worktree's own copy of the arm remains the sh worker's (unreachable there — the transform runs at its ingress).
