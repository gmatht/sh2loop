# triage: perl backend can't render what the fish-sh-go frontend emits

## NEED
The perl renderer must handle this A1 (the estree reference renders it and
matches native).

## FAILING-CASE
frontend fish-sh-go, example t59_until.fish (cross-product pair).

## EVIDENCE
estree matches native; perl differs

## OUTCOME: implemented

`sh2perl/src/ir.rs`, condition-position external command: the rebuilt shell
text keeps `$name` references verbatim (`safe_perl_q_string` escapes them so
PERL does not interpolate), but the `bash -c` child was given no environment,
so `$i` resolved to the empty string. `while not test $i -ge 3` therefore ran
`test -ge 3` — `test: -ge: unary operator expected`, status 1 forever — and
the loop never terminated (measured: 7,605 lines printed, gate timeout).

The cond arm now emits the same `var_exports_str` prelude the statement seam
(`emit_shell_cmd`) already used, wrapped in a `do {}` so it stays an
expression. Verified: `harness/triage.sh fish-sh-go t59_until.fish perl` →
PASS (`u0`/`u1`/`u2`). (`sh_cmd_value_expr` was deliberately NOT used here:
it emits `__sh_q(...)`, which the external-command preamble only includes when
a `__sh_uu_*`/`__sh_pipe_*` entry marker is present — the cond seam has none,
so that would have been a reference to an undefined sub.)
