# c: `unset <short-name>` does not invalidate the const/copy fold

## NEED

`copy_propagation`'s write classifier must treat a 1–2 character lowercase
identifier as a VARIABLE, not a builtin flag. As written it skips the name,
so a var destroyed by `unset`/`read`/`declare` keeps its single-def literal
and every later read is folded to the dead value.

## WHY

`src/transforms/copy_propagation.rs:408-425` (`classify_builtin_writes`):

```rust
for a in args {
    if let IrExpr::Str(s, _) = a {
        let s = s.trim_start_matches('-');
        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
            continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
        }
        ...
```

The flag test does not require a **leading dash** — it only strips one. So
the operand `x` of `unset x` satisfies
`all(alphabetic) && len <= 2` and is skipped as if it were `-x`. The write
site is never recorded, `counts[x]` stays 1, and `collect_defs` returns
`x` as a foldable single-def literal.

This is backend-independent: the fold happens in the shIR→shIR channel, so
EVERY backend emits the dead value. The c gate's only remaining red cell is
exactly this (`frontends/posix-sh-go/testdata/t70_unset.sh`), and no
renderer can recover it because the `param(":-", …)` node is already gone
from the A1.

## MINIMAL-CORE-CHANGE

Require the dash, i.e. classify a word as a flag only when it actually
started with `-`:

```rust
let was_flag = s.starts_with('-');
let s = s.trim_start_matches('-');
if s.is_empty() || (was_flag && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
    continue;
}
```

(Equivalently: test `a`'s leading `-` before stripping.) `unset x`,
`read ab`, `declare -r x` then record `x`/`ab` as a non-top write site and
the fold refuses, which is the pass's documented contract ("no
runtime-store … writes").

Beware the same "short flag" heuristic elsewhere in the corpus of
classifiers — this one is the site that produces the wrong A1.

## FAILING-CASE

```
x=5
unset x
echo "${x:-gone}"
```
bash prints `gone`.

Every backend prints `5`, because `--target shir` already emits
`builtin("echo", ["5"])` — the param expansion is folded away before any
renderer sees it.

Reproduce the fold directly:

```

          {"elements":[{"style":"DoubleQuoted","structural":false,"type":"Str","value":"5"}],
           "type":"Array"}],...}}
```

Name-length matrix (shIR after `--target shir`, `bash` reference `gone`):

| var    | shIR     | verdict |
|--------|----------|---------|
| `x`    | `"5"`    | WRONG   |
| `ab`   | `"5"`    | WRONG   |

The 2-char cutoff in the matrix is the bug, not the `unset` handling: the
`unset` arm is present and correct for names of length ≥ 3.

## ADDENDUM (c worker, 2026-10-24T09:2xZ) — the stale literal is not `unset`-specific

Still reproducing on the current tree; this remains the ONE failing cell of the
c backend gate (`642 pass, 1 fail (equiv=1), 7 skip` — `t70_unset.sh`).
Two pieces of new evidence that widen the fix's scope. Both were measured on

every backend for the same reason.

### 1. Three more writers leave the folded literal in place

```
$ bash -c 'x=5; read x <<< "hi";        echo "$x"'   -> hi      shIR: Str("5")   WRONG
$ bash -c 'x=5; printf -v x %s hi;      echo "$x"'   -> hi      shIR: Str("5")   WRONG
$ bash -c 'x=5; unset x; echo "${x:=gone}"; echo "$x"' -> gone gone
                                                     shIR: 2nd echo Str("5") WRONG
```

- `read x` and `unset x` are the same defect: the name is dropped by
  `classify_builtin_writes` because the flag test runs on the
  dash-STRIPPED word (`copy_propagation.rs`, the
  `s.trim_start_matches('-')` + `ascii_alphabetic() && len <= 2` guard).
- `printf -v NAME` is not in that builtin list AT ALL, so the write never
  registers for any name length. Suggested arm: for `printf`, when an
  argument is `-v`, the NEXT argument is the written name (and `printf -v
  'a[2]'` writes the array element).
- `x=5; f() { x=9; }; f; echo "$x"` is already correct (not folded) — a
  function body's assignment is seen — so the invalidation machinery exists;
  only the builtin-write classifier needs the names.

### 2. Minimal patch shape for the flag test

The guard must key on whether the word ACTUALLY carried a dash, not on the
word's length after the dashes are gone:

```rust
// copy_propagation.rs: classify_builtin_writes
for a in args {
    if let IrExpr::Str(s, _) = a {
        let raw = s.trim();
        if raw.starts_with('-') {
            continue; // a real flag word (-i, -r, -A, -u, -n, ...)
        }
        let name = raw.split('=').next().unwrap_or(raw);
        if name.is_empty() { continue; }
        site(counts, values, name, &IrExpr::Str(s.clone(), ..), false);
    }
}
```

A bare 1–2 letter name (`x`, `i`, `n`, `ab`) is then recorded as a write and
`collect_defs` stops seeing a single-def literal, so `fold_param_const` keeps
the `param(":-", …)` node. The matrix in the message above (length ≤ 2 is
wrong, ≥ 3 is correct) is exactly this guard, which also confirms that
`unset` handling itself is already right for longer names.

The c renderer needs NO change for this. Verified with the transform off:

```
$ SH2_TRANSFORMS=none otranspilerl-cli --target shir t70_unset.sh \
    | shir_render --target=c - > t70.c && cc t70.c -o t70 && ./t70
gone
```

i.e. the renderer's `unset` lowering already clears the slot and the `${x:-gone}`
arm is already emitted (`docs/c-backend-limitations.md` §15 documents only the
remaining `${v+w}`-after-`unset` approximation), so the cell turns green as soon
as the fold stops happening.
