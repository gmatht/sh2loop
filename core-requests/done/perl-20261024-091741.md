The hole is the 1–2 letter branch, and it is name-length keyed, not
construct keyed — 3-letter names are already correct:

```
x=1;read x;echo "$x"        -> 1        (bash: empty — write invisible)
y=2;unset y;echo "$y"       -> 2        (bash: empty)
foo=3;unset foo;echo "$foo" -> getVar    (correct)
```

Current source (`fn classify_builtin_writes`):

```rust
let s = s.trim_start_matches('-');
if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
    continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
}
```

The dash is stripped BEFORE the flag test, so `x` (which never had one) is
discarded as if it were `-x`; the `unset`/`read` write never reaches
`counts`/`values`, `collect_defs` still sees a single def, and `fold_expr`
substitutes the stale literal at every later read.

## MINIMAL-CORE-CHANGE

```rust
 for a in args {
     if let IrExpr::Str(s, _) = a {
-        let s = s.trim_start_matches('-');
-        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
-            continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
+        let dashed = s.starts_with('-');
+        let s = s.trim_start_matches('-');
+        if s.is_empty() || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+            continue; // a flag like -i/-r/-u/-n/-t/-p/-f/-F
+        }
```

Apply the same `dashed` guard to the twin `let`/`eval` arm below it, which
loops the same `args`. `-A` in the old comment is not ASCII-alphabetic and
never matched; `--` long options and `-v` keep working.

Unit test beside the existing ones in the module: `x=5; unset x; echo "$x"`
must NOT fold, `x=5; echo "$x"` must fold.

## OUTCOME: implemented
