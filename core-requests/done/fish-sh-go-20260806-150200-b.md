# fish-sh-go: gate still red on t78_set_local — function-local scope absent from A1→ESTree (re-filed; original: fish-sh-go-20260806-145000.md)

## NEED

The A1→ESTree path must give `local` declarations function-local scope.
`local NAME=VALUE` inside a function body today lowers to a plain
module-binding write (`(NAME = value, sh2.lastExit = 0, true)` via
`try_native_declare_stmt`, src/shir.rs ~10314) and the runtime
`builtins.local` (harness/sh2-namespace.mjs ~2690) is a flat store
write — no scope stack, no save/restore in `fnCall`/`callDirect`. The
local's value leaks out of the function and clobbers any same-named
outer variable, so the ESTree runner disagrees with bash/fish on an
observable shadowing pattern.

Original filing `core-requests/fish-sh-go-20260806-145000.md` (still
pending, unimplemented) carries the full design. Re-filed because the
fish-sh-go gate failed on the same case again on 2026-08-06T14:57:23
(74/75 stdout match, only t78 DIFF), and to add the byte-identity
verification below.

## WHY

Gate failure `frontends/fish-sh-go/testdata/t78_set_local.fish`
(native fish `inner=1`/`outer=2` vs transpiled `inner=1`/`outer=1`):

```fish
function inner
    set -l v 1
    echo "inner=$v"
end
set v 2
inner
echo "outer=$v"
```

The fish frontend side is DONE and contract-verified this session:
`set -l v 1` emits `{"func":"exec","args":["local",["v=1"]]}` inside
the Function node — BYTE-IDENTICAL to `debashc --shir`'s emission for
bash `local v=1` (compared both JSON outputs field by field; the
zsh-sh-go frontend emits the same shape for `local y=5`). So the emit
is exactly what the core's own bash frontend produces, and the
residual DIFF is 100% the core's missing local scope:

```bash
f() { local v=1; echo "inner=$v"; }
v=2
f
echo "outer=$v"
```

native bash → `inner=1`/`outer=2`; `debashc --shir --raw | debashc
--shir-in-estree` + estree-runner → `inner=1`/`outer=1`. The 517-example
bash corpus and the zsh frontend's t41 only ever READ locals inside the
declaring function (never shadow an outer var), so the leak went
unnoticed; t78 is the first probe that observes it. No harness-side
fix is possible: the local write bypasses the runtime entirely (it is a
native `v = 1` AssignmentExpression in the generated JS), so
estree-runner.mjs / sh2-namespace.mjs cannot intercept it.

## MINIMAL-CORE-CHANGE

All inside src/shir.rs + src/shir_passes/ (no A1 contract change —
`exec local NAME=VALUE` is already what the bash, fish and zsh
frontends emit):

1. **Analysis**: for each `Function`, the set of names declared by
   `local`/`declare`/`typeset`/`readonly` PURE-VALUE execs (the
   `pure_value_declare` shape) inside the body, restricted to names
   safe to lift: never referenced outside the function, never read
   through runtime strings (keep `string_ctx`/`excluded`-marked names
   store-bound), no dynamic write anywhere, not escaped, no
   recursion/interleaved-call observation (the documented
   SH2_ASSUME_LOCAL_SCOPE assumption). Populate `LOCAL_LIFT`
   (src/shir.rs:70, currently never written) or finish the `LocalLift`
   stub in src/shir_passes/analysis.rs.
2. **Emission**: push/pop `FUNCTION_STACK` (src/shir.rs:74) around
   function-body emission; for a lifted name, emit the FIRST decl in
   the body as a native `let NAME = value` (`Stmt::VariableDeclaration`
   — the block-scope shadow the runtime model lacks) and later decls
   as plain assignments. `with_func_lift` (src/shir.rs:1681) already
   exists but has no callers.
3. **Optional**: an `IrStmt::Declare { local: true }` arm in
   `stmt_to_estree` (src/shir.rs:9193 — currently
   `unreachable!("Perl-only IR statement ...")`) mapping to the same
   first-decl-`let` shape, so frontends using the contract's `Declare`
   node get scope too.
