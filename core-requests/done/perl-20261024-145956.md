# perl: `copy-propagation` folds across bare 1–2 letter names — proven by disabling the pass, plus a second damage class (`read`)

Type: shared-analysis BUG in an existing pass (`src/transforms/copy_propagation.rs`,
`classify_builtin_writes`). No new node, no contract change, no transform offer.

Requested by: perl backend worker (`backends/perl`, branch `backend/perl`).

Chain: 10th file for one bug. All predecessors are still correct and still unfixed —
`perl-20261023-.*`, `perl-20261024-032941/052500/071410/073500/100429/112200/122935/125504/142109.md`,
`c-20261023-210500-unset-const-fold.md`.

**What is new here, and why it is worth a look over the nine before it:**

1. The pass is identified by *ablation*, not by reading the code — disabling
   `copy-propagation` alone restores the correct `param` node (measured below).
2. A **second damage class**: `read NAME`'s write is dropped the same way, so
   `x=1; read x; echo "$x"` folds `$x` to `"1"`. `read` is far more common in
   real scripts than `unset`; earlier files reported `unset` only.
3. The plain-read form is damaged too, not just `${x:-…}`.
4. The patch is anchored to the current text on **both** the working tree
   (line 410) and `main` (line 370) so it applies whichever revision lands.
5. The perl side is re-measured today: the metric's call-site count is **0**, so
   this cell is the only thing between the perl backend and a green gate.

## NEED

`classify_builtin_writes` must count a **bare** variable name as a write for
`unset|read|readarray|mapfile|export|readonly|local|typeset|declare`, including
one- and two-letter names.

### Proof: the pass, by ablation

```
$ ALL=$(sed -n 's/^ *("\([a-z0-9-]*\)", *[a-zA-Z_]*::[a-zA-Z_.]*).*/\1/p' \
          sh2perl/src/transforms.rs | paste -sd, -)      # 55 registered names
$ NOCP=$(printf '%s' "$ALL" | tr ',' '\n' | grep -vx copy-propagation | paste -sd, -)

$ otranspilerl-cli --target shir /tmp/t.sh          # all transforms
  echo "5"                                    <- folded, wrong

$ SH2_TRANSFORMS="$NOCP" otranspilerl-cli --target shir /tmp/t.sh
  echo param(":-", x, "gone")                 <- correct; var_lifetimes/stmt_lines intact
```

So it is `copy-propagation` and nothing else. (Note the fold also drops the
third `stmt_lines` entry, which is how a renderer would otherwise notice.)

### Mechanism

In the `typeset|declare|local|export|readonly|read|readarray|mapfile|unset` arm,
a leading `-` is stripped **before** the "is this a flag?" test, so a bare `x`
is indistinguishable from `-x` and is dropped before it can be counted as a
write. The write invisible, `x` still looks "assigned exactly once", and the
pass substitutes the stale literal at the later read.

## MEASURED BLAST RADIUS (current tree, 2026-10-24)

Name length decides whether the write survives:

```
x    = 5; unset x; echo "${x:-gone}"   -> Str("5")        FOLDED (wrong)
xy   = 5; unset xy; echo "${xy:-gone}" -> Str("5")        FOLDED (wrong)
x    = 5; unset x; echo "$x"           -> Str("5")        FOLDED (wrong)  [plain read]
xyz  = 5; unset xyz; echo "${xyz:-gone}" -> param(:-,…)   correct
abc  = 5; unset abc; echo "$abc"       -> getVar("abc")   correct
```

Second class — the write is lost, so a later read folds to the stale value:

```
x  = 1; read x;  echo "$x"             -> Str("1")        FOLDED (wrong)
xx = 1; read xx; echo "$xx"            -> Str("1")        FOLDED (wrong)
xyz= 1; read xyz;echo "$xyz"           -> getVar("xyz")   correct
```

Only bare names are hit: the flag test runs on the whole argument, so
`declare xx=1` (contains `=`) is already counted correctly. Affected builtins are
therefore exactly those that take a **bare** name: `unset`, `read`,
`readarray`, `mapfile`, `export`, `readonly`, `local`, `typeset`.

## MINIMAL-CORE-CHANGE

Identical text at `src/transforms/copy_propagation.rs:410` (working tree) and
`:370` (`main`):

```rust
             if let IrExpr::Str(s, _) = a {
-                let s = s.trim_start_matches('-');
-                if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+                let dashed = s.starts_with('-');
+                let s = s.trim_start_matches('-');
+                if s.is_empty()
+                    || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2)
+                {
                     continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
                 }
```

`-A` still matches (`dashed` true, `"A"` alphabetic, len 1) so no flag behaviour
changes; `--x` still takes the flag arm; a bare `x` is now counted. `read -r line`
still skips `-r` and now counts `line` — which is the fix.

**Non-regression argument.** `site()` is called with `top = false` from this arm,
and `collect_defs` refuses any def whose `top` is false
(`if !*top { return None; }`). A builtin write is therefore a *count only* — it
can never become a foldable literal value. That is already why
`unset foo; echo "$foo"` renders `getVar("foo")` today (count 1, `top=false`, no
fold). Counting `unset x` only moves `x` from count 1 to 2 — precisely the
"assigned more than once" disqualified state. No new fold can appear; the change
can only *remove* folds. The worst case is a pessimised fold for a name that is
only a word argument (`read -p prompt var` counts `prompt`), which is safe.

Tests — the module's helpers (`assign`, `getvar`, `str_lit`, `int_lit`,
`expr_stmt`) are present at lines 1131–1158 and `transform` is
`pub fn transform(stmts: &mut Vec<IrStmt>) -> bool` (line 78), so these compile
as-is:

```rust
    /// `x=5; unset x; echo $x` — the builtin write disqualifies the fold.
    /// Pinned with a 1-letter name: `classify_builtin_writes` read a bare
    /// `x` as the flag `-x` and dropped the write.
    #[test]
    fn unset_invalidates_single_def() {
        let unset_x = IrStmt::Expr(IrExpr::Call {
            func: "builtin".to_string(),
            args: vec![str_lit("unset"), IrExpr::Array(vec![str_lit("x")])],
        });
        let mut stmts = vec![assign("x", int_lit(5)), unset_x, expr_stmt(getvar("x"))];
        assert!(!transform(&mut stmts));
        assert_eq!(stmts[2], expr_stmt(getvar("x")));
    }

    /// `x=1; read x; echo $x` — same hole, the class earlier files missed.
    #[test]
    fn read_invalidates_single_def() {

            func: "builtin".to_string(),

        });

        assert!(!transform(&mut stmts));
        assert_eq!(stmts[2], expr_stmt(getvar("x")));

    /// control: without the builtin the same program still folds.
```

## OUTCOME: implemented

Pinned by unit tests `unset_invalidates_single_def`, `read_invalidates_single_def`, `dashed_flag_is_still_skipped`, `folds_without_unset`.
