# perl: copy-propagation still folds across `unset NAME` for 1–2 letter names — the perl gate's only red cell

Type: shared-analysis bug (no new node, no contract change, no transform offer)
Requested by: perl backend worker (backends/perl, branch `backend/perl`)
Status: third filing. `perl-20261024-032941.md` and `perl-20261024-052500.md`
(and `c-20261023-210500-unset-const-fold.md`) are still open and still accurate.
Re-verified against the current core at 2026-10-24T07:14Z.

## NEED

`src/transforms/copy_propagation.rs` → `classify_builtin_writes`: only treat a
word as a command-line FLAG when it actually carried a leading `-`. Today a bare
1–2 letter variable name (`x`, `i`, `n`, `v`, `ab`, `fd`) is discarded as a flag,
so `unset x` / `read x` / `declare -i x` / `mapfile -t a` never count as a write
to that name.

## WHY

The write is invisible to `collect_defs`, the variable still looks
"assigned exactly once", and `fold_expr` substitutes the stale literal into every
later read — including the `${x:-gone}` expansion (`fold_param_const`'s
`(":-", 3) if !text.is_empty()` arm). The A1 export has already lost the
expansion, so NO renderer can repair it: every backend prints the stale literal.

The corpus threshold is name length, not construct. Measured on the current core
(`SH2_TRANSFORMS=copy-propagation otranspilerl-cli --target shir`):

```
x    = 5; unset x;    echo "${x:-gone}"    -> Str("5")        # folded — wrong
ab   = 5; unset ab;   echo "${ab:-gone}"   -> Str("5")        # folded — wrong
abc  = 5; unset abc;  echo "${abc:-gone}"  -> param(":-",…)   # correct
abcd = 5; unset abcd; echo "${abcd:-gone}" -> param(":-",…)   # correct
```

The heuristic strips the dash BEFORE testing for a flag, so it can no longer tell
`-i` from a variable named `i`:

```rust
let s = s.trim_start_matches('-');
if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
    continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
}
```

The twin `let` arm further down loops over the same `args` and has the same hole.

## MINIMAL-CORE-CHANGE

```rust
 for a in args {
     if let IrExpr::Str(s, _) = a {
-        let s = s.trim_start_matches('-');
-        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+        let dashed = s.starts_with('-');
+        let s = s.trim_start_matches('-');
+        if s.is_empty() || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
             continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
         }
```

`-A` never matched the predicate anyway (not ASCII-alphabetic); long options and
`-v` keep working. A unit test beside the existing ones should pin both sides:
`x=5; unset x; echo "$x"` must NOT fold, `x=5; echo "$x"` must fold.

## OUTCOME: implemented
