## NEED

A word in a store-writing builtin's argument list (`unset`/`read`/`declare`/
`local`/`export`/`readonly`/`mapfile`/`readarray`) must only be treated as a
command-line FLAG when it actually carried a leading `-`. The dash is stripped
BEFORE the flag test, so a bare 1–2 letter VARIABLE NAME (`x`, `i`, `n`, `ab`)
is indistinguishable from `-i` and the write is never recorded. The name then
still looks "assigned exactly once", `collect_defs` returns it as a foldable
single-def literal, and `fold_param_const`'s `(":-", 3)` arm substitutes the
stale literal into `${x:-gone}` — across the `unset`.

The A1 has already lost the expansion, so NO backend can repair it: the perl,
c, rust, python, sh and estree renders of `t70_unset.sh` all emit the literal.
