## ROOT CAUSE A (flagship, one-line class, fd-blind redirect emission)
`sh2perl/src/ir.rs:2439-2476` — the `Some(r) if matches!(r.mode, "w"|"wc"|"a"|"r+")`
arm of the non-command-inner redirect emitter hard-codes **STDOUT**:

```rust
"open(my {fh}, '>&', \\*STDOUT) or die \"Cannot dup stdout: $!\\n\";\n"
"close(STDOUT); open(STDOUT, {}, {}) or die ...
"select({sel}); open(STDOUT, '>&', {fh}) ...
```

`IrRedirect` already carries `fd: Option<i32>` (`ir.rs:568`) and
`shir.rs::redirect_to_ir` populates it faithfully — `2>/dev/null` arrives as
`fd: Some(2)`, `>/file` as `fd: Some(1)`. The emitter never reads `r.fd`, so a
**stderr** redirect is emitted as a **stdout** redirect.

Proof (minimal repro, `sync-direct-call-await.sh`):
```
g() { echo hi 2>/dev/null; }
```
emits `close(STDOUT); open(STDOUT, '>', "/dev/null")` and then `print "hi\n"`
into it — stdout becomes empty, where bash prints `hi`. The correct emission
dups/restores **STDERR** and leaves the print target alone.

This is the class named in the task's own RECIPE as a common cause
("exit-code propagation, trailing whitespace/final newline, CRLF echo") —
the fd dimension is the one it missed.

**The fix is verified by A/B**, not inferred. Hand-written faithful fd=2
emission reproduces bash exactly:
```perl
open(my $save, '>&', \*STDERR); close(STDERR); open(STDERR,'>','/dev/null');
print "hi\n";
open(STDERR, '>&', $save); close($save);
```
```
bash : [hi]     # the real example
perl : [hi]     # the faithful fd=2 emission  -> MATCH
```
whereas the current generated `close(STDOUT); open(STDOUT,'>','/dev/null')`
yields `[]`. The one-line fd select is therefore the whole fix for this class.

## ROOT CAUSE B (nested parameter expansion is not recursive)
`ir.rs:4487-4606` renders `${var:-default}` via a `defined && length ? … :
substr(...)` ternary, but a NESTED expansion is spliced in raw, unlowered.
`063_04` source: `${var:-${default:-${fallback:-$(echo "computed")}}}`

emits literally:
```perl
substr($default, -${fallback, -$(echo "computed")})
```
`${fallback, ...}` is a Perl **hash slice** — it runs, yields `''`, and the
whole `echo` is silently swallowed. bash prints `computed`. The same
non-recursion loses `${index}` inside `${array[${index}]:-...}` (→ `${index}`
is a Perl deref of an empty scalar) and drops `${!prefix*[@]}` to bare
`keys %prefix` on its own line, emitting an extra line.

## WHY THIS IS NOT FIXABLE IN `perl_generator_fixed.rs`
The owned module is an **IR pre-pass + textual post-pass** around
`shir_to_perl` (`perl_generator_fixed.rs:63` `fix_cmd_capture_split`,
plus `fix_sub_params`/`fix_case_pattern_tail`). It cannot fix any of the
above, because:
- A, C, D are **emission decisions the shared renderer makes** (which handle
  to dup, which fd, how to recurse into a nested expansion). Correcting them
  would mean rewriting the renderer.
- A pre-pass *can* rewrite IR, but A's defect is that the renderer ignores a
  field that is already correct — there is nothing malformed in the IR to
  repair. A text post-pass would have to match `close(STDOUT); open(STDOUT, …)`
  and infer the original fd, which is unrecoverable from the emitted text.
- The module has **zero** `IrRedirect`/fd coverage today (`grep -c IrRedirect`
  = 0), and adding it would be a fork of the shared emitter, not a fix.

## MINIMAL-CORE-CHANGE (what the core should do)
1. `ir.rs` redirect emitter: read `r.fd` and pick STDERR for `fd == Some(2)`
   (dup/restore `\*STDERR`, `local *STDERR` for the `select` idiom) — one
   `if` at `ir.rs:2439`.
2. `ir.rs` param-expansion renderer: recurse into a nested `${…}` default
   instead of splicing it raw, so `${fallback:-$(…)}` lowers through the
   existing `$(…)` capture.
3. Triage C/D as ordinary renderer bugs; the fd fix alone clears
   `sync-direct-call-await` and unblocks several of the 16 zero-output cases.
