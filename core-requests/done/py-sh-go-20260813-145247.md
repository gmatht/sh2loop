# py-sh-go: ESTree Try lowering runs `else` AFTER `finally` (Python order is else-then-finally)

## NEED
The shared-core ESTree lowering of `IrStmt::Try` must preserve Python's
suite order when BOTH an `else` body and a `finally` body are present:
Python executes try-body → else → finally on the no-exception path, but
`stmt_to_estree` (src/shir.rs, the `IrStmt::Try` arm's `else_body`
branch) emits the else suite as a post-try `if (__sh2else)` block AFTER
the `TryStatement` — and the JS finalizer runs at the end of that
statement, i.e. BEFORE the else. The executed stdout comes out
try → finally → else instead of try → else → finally.

## WHY
The py-sh-go frontend now lowers Python `try_stmt` (grammars-v4 rule)
to the A1 `Try` node (core request py-sh-go-20260813, landed f25fc79)
and its coverage example t78_try_except.py passes — but only because the
example uses try/except/finally WITHOUT `else` (that combination is
order-correct). The full `try/except/else/finally` shape emits wrong
output, so no testdata example can cover the complete rule:

    python3:   in try / no error / final / after
    ESTree:    in try / final / no error / after

The `else`-with-`finally` combination is expressible in the A1 contract
and valid Python; the defect is purely the renderer's statement order.
The core's own Try unit tests (src/shir_json_in.rs round-trip,
src/shir.rs:30816 bare-try render) never execute the else+finally path.

## MINIMAL-CORE-CHANGE
In src/shir.rs `stmt_to_estree`, the `IrStmt::Try` arm's final else
branch (`else_body` non-empty, flag `__sh2else`): when `finalizer` is
also present, wrap the inner statement so the else runs inside the
finalizer's scope but outside the catch:

    let inner = TryStatement { block: try_body(+flag=true), handler,
                               finalizer: None };
    let body = [ inner, IfStatement(flag, else-suite) ];
    → TryStatement { block: BlockStatement(body), handler: None,
                     finalizer: Some(finalizer) }

Ordering then matches Python on all paths: no-exception → body, else,
finally; caught → body(raise), ladder, finally (else skipped via flag);
else-body exceptions are still NOT caught by this statement's arms (the
else sits outside the inner try/catch) and still pass through the outer
finalizer. When `finalizer` is None the current post-try shape is
already correct and unchanged.

## FAILING-CASE
Minimal Python program (python3 runs it fine):

```python
try:
    print("in try")
except:
    print("caught")
else:
    print("no error")
finally:
    print("final")
print("after")
```

Expected stdout (python3): `in try / no error / final / after`.
Current transpiled ESTree stdout: `in try / final / no error / after`
(the finalizer runs before the post-try else block) — the
executed-stdout oracle fails. Reproduce: emit via
`frontends/py-sh-go/py-sh-go --shir <file> --raw`, then
`debashc --shir-in-estree <a1.json>` and run the resulting ESTree under
`harness/estree-runner.mjs`.
