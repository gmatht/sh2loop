# py-sh-go: star_expr still inexpressible — array-valued subrange LANDED, but the Array/Call splice marker never did; frontend lowering path also absent

## NEED
The A1 contract must express Python **starred expressions** (grammars-v4
Python3 rule `star_expr`: `'*' expr`, the ANTLR-coverage hook still
reports it uncovered in py-sh-go testdata). Two shapes were requested
by the completed requests `core-requests/done/py-sh-go-star-expr-20260813-193834.md`
and `core-requests/done/py-sh-go-star-expr-20260813-221910.md`:

1. **Array-valued subrange** — `x, *rest = a` binds "the rest of the
   array". **STATUS: LANDED.** `src/shir.rs` `exec_arg_is_array_valued`
   (~line 17045) now treats the offset slice forms as array-valued:
   a `[@]`/`[*]`-suffixed name (`${arr[@]:off[:len]}`) or a plain name
   with a numeric offset (runtime arrays-map branch returns
   `[...slice]` when the name IS an array; the arg flattener splices
   arrays and keeps strings as one word). Verified present in the
   current tree; the comment cites "core request py-sh-go-star-expr".
2. **Splice marker on `Array` elements and `Call` args** — so
   `b = [*a]` / `[1, *a]` (list-display positions of `star_expr`
   inside `testlist_comp`) and `f(*a)` (the sibling `argument` rule's
   `'*' test` alternative) splice an array's elements into a literal /
   call instead of nesting the array as ONE element. **STATUS: NEVER
   LANDED.** No `Splice` node, no optional marker on
   `{"type":"Array","elements":[...]}` (shir_json.rs ~line 394 emits
   exactly `elements` and nothing else), no `param("rest")` /
   `param("star")` helper. `grep -rn "Splice" src/ir.rs src/estree.rs
   src/shir_json.rs` finds only an unrelated comment in ir.rs.

Also still missing (frontend-side, py-sh-go's own fix once the
contract shape exists): the lowering path in frontends/py-sh-go/main.go
— `parseUnary` handles only `-`/`+`, `parsePrimary` has no `*` arm,
`parseExprStmt`'s target loop accepts only `NAME (, NAME)*`, and
`parseFor`'s target likewise, so every star_expr form fails loudly.
With item 1 landed, the starred-ASSIGNMENT form (`x, *rest = a` →
`x = arrayIndex(a, 0)`; `rest` = setArray from the array-valued rest
slice) needs no further core change — only the frontend parser. The
contract gap that REMAINS is item 2, the splice shape.

## WHY
The coverage hook (`frontends/coverage/rules-gap.sh py-sh-go`) still
reports `star_expr` as a Python3 grammar rule with no testdata example,
and `frontends/coverage/core-pending-py-sh-go.txt` still lists
`star_expr` as core-pending. No example can be created: the frontend
REFUSES every star_expr form today (verified against the built
`./py-sh-go --shir`, exit 2):

    $ printf 'a = [1, 2, 3]\nb = [*a]\nprint(len(b))\n' | ./py-sh-go --shir /dev/stdin
    py-sh-go: parse: unexpected token "*"
    $ printf 'a = [1, 2, 3]\nx, *rest = a\nprint(x)\n' | ./py-sh-go --shir /dev/stdin
    py-sh-go: parse: bad assignment target
    $ printf 'for a, *b in c:\n  pass\n' | ./py-sh-go --shir /dev/stdin
    py-sh-go: parse: for: expected in

This is NOT a by-design subset refusal: py-sh-go has no FRONTEND.md and
the exclusion ledger `frontends/coverage/refused-py-sh-go.txt` lists
the DISTINCT match-statement rules `star_named_expressions` /
`star_named_expression` but NOT `star_expr`. All four contexts are
supported constructs — tuple assignment (t47_multi_assign), list
literals (t21/t56/t66), for loops (t20/t71), dict/set displays
(t73) — only the starred-expansion semantic is missing. The two prior
requests in `done/` (193834, 221910) reached the same verdict and were
accepted; item 1 was implemented, item 2 was not (and the frontend
emit arm the requests deferred never landed either — same pattern as
the sliceop deferral in `py-sh-go-sliceop-20260814-001712.md`).

## MINIMAL-CORE-CHANGE
1. **Splice marker on `Array` elements** (the still-missing half):
   extend the `Array` expr node with an optional splice marker —
   e.g. `{"type":"Array","elements":[...],"splice":[i,...]}` (indices
   whose elements are spliced, not nested) or a
   `{"type":"Splice","expr":...}` element wrapper. Keep existing emits
   byte-identical when absent. The ESTree renderer already
   concat-splices non-scalar `setArray` items
   (src/estree.rs `is_scalar_array_item` ~line 1691), and the runner's
   setArray does `out.push(...e)` for native-JS-array elements — so an
   array-valued `param("slice", name, off)` (now array-valued per item
   1) or `arrayIndex` used as a marked element splices end-to-end.
2. **Call-arg splice** (the `argument` rule's `'*' test`): the same
   marker on the `args` array of the `Call` node covers `f(*a)` — or,
   if the marker covers both, state so in the contract.
3. **Ingress + contract**: shir_json_in.rs deserializer accepts the new
   shape; frontends/shir-contract/schema.json gains it (workspace-side,
   keeps check_schema.py green).

The frontend-side lowering (exprParser `*` case + starred targets in
parseExprStmt/parseFor + starred list-display/call args → emit the
shapes above) is py-sh-go's own fix and lands after the contract has
the shape; the coverage worker retries the gap automatically once this
request completes (core-pending-py-sh-go.txt pruning cycle).

## FAILING-CASE
Minimal Python programs (python3 runs both fine):

```python
a = [1, 2, 3]
x, *rest = a
print(x)
print(len(rest))
print(rest[1])
```

stdout: `1`, `2`, `3` (x=1, rest=[2,3], rest[1]=3) — needs only the
frontend lowering now (item 1 landed).

```python
a = [1, 2]
b = [*a]
print(len(b))
```

stdout: `2` (b is a 2-element copy of a) — needs the splice marker
(item 2, STILL MISSING from the contract).

```python
a = [3, 4]
print(max(1, *a))
```

stdout: `4` — needs the Call-arg splice.

Current behavior: `./py-sh-go --shir` fails with
`py-sh-go: parse: unexpected token "*"` (list display) or
`py-sh-go: parse: bad assignment target` (starred target), exit 2 —
so no testdata example can cover `star_expr`, and the contract half
that remains missing is the Array/Call splice shape (item 2).

Item 2 (the missing contract half) landed: IrExpr::Splice node (shir_json.rs/shir_json_in.rs `{"type":"Splice","expr":...}`) + estree renderer emitting a JS SpreadElement in Array elements and Call args (`[...x]` / `f(...x)`) — verified end-to-end: `b=[*a]` with arrayIndex("a","@") renders and the runner prints the spliced elements. Item 1 (array-valued subrange) was already in the tree. Frontend-side lowering remains py-sh-go's follow-on.
