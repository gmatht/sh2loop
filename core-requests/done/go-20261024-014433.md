# go: main `sh2perl` tree does not compile — half-applied RegSub→Substitute migration

## NEED
The go worker's gate fails at its FIRST step (`core build`), before any corpus
file is rendered. The command is the gate's own (`setup_backends.sh:1499`):

    harness/build-lock.sh --role backend -- \
      cargo build --manifest-path otranspilerl/Cargo.toml --bin otranspilerl-cli

which compiles the MAIN tree `/mnt/wsl/projects/sh2loop/sh2perl`. That tree is
currently broken by two UNCOMMITTED working-tree changes, so the failure is not
in `backends/go` at all (see FAILING-CASE: the go worktree builds clean).

This request is not a shIR contract change and no transform is offered — it is
a "finish or revert the in-flight core edit" repair for the core owner.

## WHY
`git -C sh2perl status --short` at 2026-10-24 01:42:

    M src/render_ext_expr/handlers/all_nodes.rs
    M src/transforms/copy_propagation.rs
    M src/shir_nodes/reg_sub.node
    ?? src/shir_nodes/substitute.node
    M src/shir_nodes/*.node            (28 node decls, `spec:` lines)

Two independent compile errors, both introduced by that WIP — HEAD is clean for
both lines of evidence:

    $ git show HEAD:src/render_ext_expr/handlers/all_nodes.rs | grep -n "pub fn reg_sub"
    200:pub fn reg_sub(node: &RegSub, ctx: &ExprRenderCtx) -> Option<String>
    $ git show HEAD:src/transforms/copy_propagation.rs | grep -n "IrExpr::Ext"
    (no match — the arm is new in the WIP)

### Error 1 — `all_nodes::reg_sub` was deleted, its generated handler still calls it

    error[E0425]: cannot find function `reg_sub` in module `super::all_nodes`
     --> /mnt/wsl/projects/sh2loop/sh2perl/src/render_ext_expr/handlers/reg_sub.rs:7:23
      |

The WIP rewrote the function in `all_nodes.rs` as
`pub fn substitute(node: &Substitute, ctx: &ExprRenderCtx)` and moved the node
declaration to the new `src/shir_nodes/substitute.node`, but

so `build.rs` still generates `mod reg_sub;` + the `reg_sub.rs` delegating
handler against the `RegSub` struct.

### Error 2 — `copy_propagation::fold_expr`'s new `IrExpr::Ext` arm yields `bool`

    error[E0308]: mismatched types
       --> /mnt/wsl/projects/sh2loop/sh2perl/src/transforms/copy_propagation.rs:830:13
        |
    830 |             c
        |             ^ expected `()`, found `bool`

Every `match e` arm in `fold_expr` is a statement (`()`); the new `Ext` arm ends
with a bare `c` expression. The local `let mut c = fold_expr(&mut text, …)`
(line 819) also SHADOWS the function's accumulator `c`, so even once it parses
the Ext arm's fold result would never reach the returned value.

## MINIMAL-CORE-CHANGE
Two independent, mechanical fixes; either order compiles.

1. `src/transforms/copy_propagation.rs`, `IrExpr::Ext(n)` arm — rename the local
   and OR it into the outer accumulator instead of yielding it:

       - let mut c = fold_expr(&mut text, defs, resolved, foldable);
       - c |= fold_expr(&mut pattern, defs, resolved, foldable);
       + let mut inner = fold_expr(&mut text, defs, resolved, foldable);
       + inner |= fold_expr(&mut pattern, defs, resolved, foldable);
         ...
       - if c {
       + if inner {
             *e = IrExpr::Ext(Box::new(AffixStrip { text, pattern, prefix }));
         }
       - c
       + c |= inner;

2. Finish (or revert) the node rename. Preferred, since `substitute.node` already
   describes the new meaning: delete `src/shir_nodes/reg_sub.node`, keep
   `src/shir_nodes/substitute.node`, and let `build.rs` regenerate
   `src/render_ext_expr/handlers/mod.rs` + `handlers/reg_sub.rs` (the generated
   `all_nodes.rs` entry point is then `substitute`). If the migration is meant
   to stay reversible, the alternative is a one-line shim in `all_nodes.rs`:

       pub fn reg_sub(node: &RegSub, ctx: &ExprRenderCtx) -> Option<String> { … }

   Note the generated `handlers/mod.rs` still lists `pub(crate) mod reg_sub;` —
   it is `@generated`, so it must be regenerated rather than hand-edited.

Backend consumers of the rename (informational, NOT a core change): the go
backend currently renders `RegSub` as `/* TODO: RegSub Go */` (an expression
position emitting a comment). Once `Substitute` lands, go should gain a real arm
(`regexp.MustCompile(...).ReplaceAllString(...)` per line, per the node's own
`Backends:` note) instead of inheriting the TODO.
