# py-sh-go: A1 Pipeline statement exists in the contract but the ESTree renderer has no arm — top-level pipelines are inexpressible through the gate

## NEED

The shared core must render the A1 **`Pipeline`** statement node in the
ESTree renderer. The node is already part of the A1 contract:

- `frontends/shir-contract/schema.json` `"Pipeline"` with fields
  `stages` (`stmt[][]`), `last_output`, `capture`, `cmd_str`, `purity`;
- the emitter (`sh2perl/src/shir_json.rs:257`) serializes
  `IrStmt::Pipeline { stages, last_output, capture, cmd_str }` to
  `{"type":"Pipeline","stages":[...],"last_output":...,"capture":...,"cmd_str":...,"purity":"Spawn"}`;
- the deserializer (`sh2perl/src/shir_json_in.rs:536`) round-trips the
  node (ingress acceptance passes).

The ESTree renderer `stmt_to_estree` (`sh2perl/src/shir.rs:15447`) has
NO arm for `IrStmt::Pipeline` — it falls into the catch-all
`unreachable!("Perl-only IR statement reached the ESTree renderer")`
(verified panic at src/shir.rs:17915, exit 101). The Perl backend
renders the node (src/ir.rs:2003) and the shIR-level analysis passes
handle it; only the ESTree statement path is missing.

The runtime machinery ALREADY exists: `$(a | b)` command substitution
lowers to the EXPRESSION form `Call("pipeline", [Array([Arrow, ...])])`,
which `expr_to_estree` renders to `sh2.pipeline([...])` /
`sh2.pipelineSync([...])` (src/shir.rs:31671-31715, including the
sync-twin verdict for provably await-free stages), and
`harness/sh2-namespace.mjs` implements both (`pipeline()` at
sh2-namespace.mjs:1678, `pipelineSync()` at ~1714, with fd-target
swaps, string-stage collapse and PIPESTATUS). So a top-level pipeline
needs only the statement arm lowering its stages the same way.

## WHY

The coverage hook (`frontends/coverage/worker-coverage-step.sh` →
`coverage-gap.sh`, the A1-node proxy for py-sh-go's hand-rolled parser)
reports `A1 node Pipeline` as a construct no testdata example exercises
(verified 2026-08-14: `bash frontends/coverage/coverage-gap.sh py-sh-go`
lists `A1 node Pipeline` first). The reason no example exists: the
frontend cannot express it through the gate, and this is NOT a by-design
subset refusal:

- Python subprocess pipelines are a real idiom in the subset's spirit —
  `subprocess` is supported (`subprocess.Popen` → Background, t44;
  `subprocess.run` capture, t33/t34) and the frontend has no FRONTEND.md;
  the exclusion ledger (`frontends/coverage/refused-py-sh-go.txt`, 70
  Python-grammar-rule entries) contains no Pipeline entry.
- No lowering path emits the node: `os.system("echo hi | grep hi")`
  word-splits the string and passes `"|"` as a literal ARGUMENT
  (verified — the emit is `exec echo [hi, |, grep, hi]`, not a
  Pipeline); `subprocess.Popen(..., stdout=subprocess.PIPE)` /
  `stdin=p1.stdout` pipe kwargs are silently DROPPED by `procArgs`
  (verified — two standalone Background execs, pipe semantics lost);
  the full Popen-chain idiom (`p2.communicate()[0]`) REFUSES
  ("subscript target must be a variable").
- Even with a frontend lowering path, a testdata example that DID emit
  a `Pipeline` node would fail the gate deterministically: `make test`'s
  executed-stdout oracle (`harness/frontend-stdout.sh` →
  `debashc --shir-in-estree` → `harness/estree-runner.mjs`) panics on
  the node before the runner ever sees it.

Precedent: the `MethodCall` request
(`core-requests/py-sh-go-20260814-152409-methodcall.md`) followed the
same pattern — contract has the node, deserializer accepts it, only the
renderer arm is missing → escalate; the frontend-side emit decision
lands after the arm exists and the coverage worker retries the gap
automatically (core-pending-py-sh-go.txt re-entry + pruning cycle).

## MINIMAL-CORE-CHANGE

One arm in `stmt_to_estree` (`sh2perl/src/shir.rs`, ~line 15447) for
`IrStmt::Pipeline { stages, .. }`, reusing the existing expression-form
machinery at shir.rs:31671-31715:

- render each stage (`Vec<IrStmt>`) as an async `Arrow` exactly the way
  the `$(a | b)` expression form builds stage arrows (the last stage
  must be an arrow so its output writes through the current fd-1 sink —
  `pipeline`/`pipelineSync` restore `fdTargets[1] = saved[1]` after the
  loop);
- wrap the stage array in `sh2.pipeline([...])`, or
  `sh2.pipelineSync([...])` when every stage is provably await-free
  (the same `expr_has_await` + `sync_arrow_flip_deep` verdict the
  expression arm applies);
- return it as an `ExpressionStatement` (the `$(...)` form's call is
  already awaited/self-contained; the statement form mirrors it).

No contract change (schema.json / shir_json.rs / shir_json_in.rs already
round-trip the node — verified), no harness change (estree-runner.mjs
dispatches to `sh2.*`; `pipeline`/`pipelineSync` already implement the
semantics). Regression surface: the bash corpus's top-level `a | b`
statements currently produce `IrStmt::Pipeline` only in the shIR the
Perl backend consumes — the ESTree gate (`./fail-estree`) never sees
the statement form today, so the new arm is dead for the existing
corpus and safe by construction; the frontend fleet's executed-stdout
gates then accept the node end-to-end.

The frontend side (a `procArgs`/`assignOne` path that recognizes the
Popen pipe idiom — `stdout=subprocess.PIPE` fed to a later Popen's
`stdin=` — and emits `{"type":"Pipeline","stages":[...]}` with the
per-stage exec statements) is py-sh-go's own fix and lands after the
renderer has the arm; the coverage worker retries the gap automatically
once this request completes.

## FAILING-CASE

Minimal Python program (python3 runs it fine — stdout `hi`):

```python
import subprocess
p1 = subprocess.Popen(["echo", "hi"], stdout=subprocess.PIPE)
p2 = subprocess.Popen(["grep", "hi"], stdin=p1.stdout)
p2.wait()
```

The A1 the frontend WOULD emit for the faithful pipeline lowering (the
node the contract already defines; today the frontend instead silently
drops the pipe kwargs and emits two standalone Background execs):

```json
{
  "type": "Program",
  "contract_version": 1,
  "imports": [],
  "requires": [],
  "stmt_lines": [],
  "var_types": [],
  "subs": [],
  "stmts": [
    {
      "type": "Pipeline",
      "stages": [
        [{"type": "Expr", "expr": {"type": "Call", "func": "exec", "args": [{"type": "Str", "value": "echo", "style": "DoubleQuoted"}, {"type": "Array", "elements": [{"type": "Str", "value": "hi", "style": "DoubleQuoted"}]}]}}],
        [{"type": "Expr", "expr": {"type": "Call", "func": "exec", "args": [{"type": "Str", "value": "grep", "style": "DoubleQuoted"}, {"type": "Array", "elements": [{"type": "Str", "value": "hi", "style": "DoubleQuoted"}]}]}}]
      ],
      "last_output": null,
      "capture": null,
      "cmd_str": null,
      "purity": "Spawn"
    }
  ]
}
```

Current behavior (verified 2026-08-14 against the checked-out core —
the same shape any testdata example would produce):

    reached the ESTree renderer: Pipeline { stages: [[Expr(Call {

So no testdata example can cover `A1 node Pipeline`: the frontend's own
gate (ingress acceptance passes — the deserializer accepts the node —
but the executed-stdout oracle's `--shir-in-estree` conversion panics)

## OUTCOME: implemented — stmt_to_estree (sh2perl/src/shir.rs) gained the
IrStmt::Pipeline arm: the stages render as arrows via the constructed
expression-form `Call("pipeline", [Array([Arrow, …])])` routed through
expr_to_estree — the exact machinery the `$(a | b)` expression form and the
bash corpus's statement pipelines use (native folds, ECHO_SINK_DEPTH
discipline, expr_has_await + sync_arrow_flip_deep *Sync-twin verdict), so
the A1 node lowers byte-identically to a bash statement pipeline. The
capture form (`capture: "var"`) lowers via the command-substitution
machinery (`sh2.setVar(var, await sh2.capture(() => …pipeline…))` /
captureSync). The request's failing-case JSON (echo | grep) now renders
(was exit=101 panic) and executes through estree-runner.mjs printing "hi"
matching python3; also verified: runtime pipeline/pipelineSync paths
(echo|cat, 3-stage tr chain), dynamic-stage async pipeline, pipeline
inside Subshell, capture form (native fold + runtime captureSync path),
and the `$?`-after-pipeline status protocol (echo hi | grep nope →
status=1, matches bash). Regressions: ./fail-estree --gate green
(ESTREE 521/521, PERL 360/161 — per-test perl verdicts identical with the
arm reverted), harness/check_ast.pl 22 passed, cargo test --lib 292 passed
(the 1 failure, glsl_backend bridges_tex_group_dependency, is a sibling
worker's uncommitted in-flight glsl_backend.rs edit — passes at HEAD's
glsl_backend.rs with this change present).
