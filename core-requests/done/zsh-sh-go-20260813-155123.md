# zsh-sh-go: shell lowering never emits the A1 `Ident` expr node — no byte-locked shell frontend can cover it

Same shared-core situation as `core-requests/zsh-sh-go-20260813-153215.md`
(the A1 `ForInit` node): the node is complete end-to-end in the contract,
but the shared core's SHELL lowering never emits it, so a byte-locked
shell frontend cannot cover it. This request files the A1-node `Ident`
gap for the zsh-sh-go ledger (`frontends/coverage/coverage-gap.sh
zsh-sh-go` → `A1 node Ident`, first line of the actionable list, gate
green).

## NEED

The shared core's shell frontend must emit the A1 `Ident` expr node
(`{"type":"Ident","name":…}`) for at least one shell construct so
`debashc --shir FILE --raw` can actually produce it. Today the shell
frontend path **never** constructs `IrExpr::Ident` for any source
program. The complete list of `IrExpr::Ident` creation sites in the tree
is:

- `src/shir_json_in.rs:880` — the A1 JSON **deserializer** (round-trip
  input only, no source);
- `src/shir.rs:14071` (the lifted `Number(i)` coercion source),
  `14753` / `14765` / `15164` (the *Sync/async for-loop plumbing's
  `js_var` store-sync / coercion references) — all inside the ESTree
  lowering (`stmt_to_estree` & helpers, src/shir.rs:13657+), i.e. AFTER
  the `--shir` JSON emission, so they never appear in A1 output;
- `src/shir.rs:31164+` — a `#[test]` fixture
  (`try_stmt_lowers_to_js_try_catch`).

The parser itself has **zero** `IrExpr::Ident` constructions
(`src/parser/`), and `ir.rs:391` documents the node as "Bare identifier
(ESTree-path only — e.g. the for-loop variable name)". Empirically,
`debashc --shir FILE --raw` over all 80+ `frontends/zsh-sh-go/testdata/`
files emits no `Ident` anywhere, and no other frontend in the workspace
emits it either (0 files with `"type": "Ident"` across the
py/go/c/posix/perl/fish/cpp/bat/zig/powershell testdata).

The node itself is complete end-to-end — no contract change needed:

- schema: `frontends/shir-contract/schema.json` exprs.Ident
  (`{type, name}`, both required)
- serializer: `src/shir_json.rs:359` —
  `IrExpr::Ident(name) => json!({ "type": "Ident", "name": name })`
- deserializer: `src/shir_json_in.rs:880` — `"Ident" => IrExpr::Ident`
- estree renderer: `src/shir.rs:27493` —
  `IrExpr::Ident(name) => Expr::Identifier { name }` (verified:
  `--shir-in-estree` on a JSON program carrying an Ident arg renders
  `{"type":"Identifier","name":"myvar"}`; the perl path consumes it too)

## WHY

zsh-sh-go gate is GREEN but `frontends/coverage/coverage-gap.sh
zsh-sh-go` reports `A1 node Ident` uncovered. The frontend is byte-locked
to the core's `debashc --shir FILE --raw` emit (Makefile's BYTE-EQUALITY
ORACLE: `make test` diffs frontend emit against core emit, so a testdata
example can only contain node types the core emit produces), and the core
emit for every construct in the subset is `Var`/`Interpolate`/`Arith`/
`Call` — never `Ident`. Probing the natural candidates:

```
for i in 1 2 3; do echo $((i * 2)); done   # t51_arith_loop: body read is {"type":"Var","name":"i","sigil":null}
for ((i=0; i<3; i++)); do echo $i; done    # cstyleFor Call (see the pending ForInit request)
((i++))                                    # Arith/Assign — no Ident
echo $i                                    # Interpolate/Var — no Ident
```

Every variable read in shell lowers to `Var` (store-backed; the estree
gen re-derives bare `Identifier`s itself for numeric-lifted vars via
`expr_to_estree`'s `is_lifted` arm at src/shir.rs:27467), so no source
construct maps to `Ident`. A testdata example cannot contain the node:
any frontend emit carrying `Ident` would DIFF against the core emit and
fail the gate.

This is NOT a by-design subset refusal: FRONTEND.md excludes nothing
here — the frontend's emitter (`analysis.go` `exprJSON`, line 2686)
simply has no `Ident` case, and there is no source spelling of the
construct to refuse (`Ident` is a contract-internal bare-JS-identifier
node, not a source-language construct). What is inexpressible is the
**Ident emission shape**, which only the shared core's shell lowering
can provide — the identical situation to the pending A1-node ForInit
request (`core-requests/zsh-sh-go-20260813-153215.md`; both are
"A1 node … is complete end-to-end in the contract, but the shared core's
SHELL lowering never emits it"). Escalating per the core-requests
channel (the estree worker is the single owner of src/shir.rs).

## MINIMAL-CORE-CHANGE

Scope: `src/shir.rs` only — the shell lowering's for/while loop-var
reads. The one shell construct whose ESTree form already IS a bare
identifier is the **numeric-lifted loop variable**: `expr_to_estree`'s
`IrExpr::Var` arm (src/shir.rs:27467) renders `is_lifted(name)` reads as
`Expr::Identifier`, and the *Sync loop plumbing synthesizes
`IrExpr::Ident(js_var)` for the loop var (src/shir.rs:14753/14765/15164).
Concretely: in the loop-body lowering (the `for`/`while` statement arms
that run inside `shir_to_shir_json` — the A2 verdicts are available at
emit time, `analyze_var_types` runs in `shir_json.rs:31` for the
non-raw export and the frontends already carry the same verdicts), emit
in-body reads of a numeric-lifted loop variable as `Ident` instead of
`Var`:

- before: `{"type":"Var","name":"i","sigil":null}` (t51_arith_loop today)
- after: `{"type":"Ident","name":"i"}` (same ESTree output — the
  `is_lifted` Var arm and the Ident arm both render `Identifier`, so
  the estree/perl/etc. renders are unchanged)

Serializer, deserializer, schema, and all renderers already exist —
nothing else in the core needs to change. Frontend byte-equality gates
(zsh-sh-go, posix-sh-go, and any other shell frontend with a
numeric-loop example) will show `DIFF` until each frontend mirrors the
new shape in the same window — the established pattern from
`core-requests/done/posix-sh-go-20260806-174619.md`; the zsh-sh-go
mirror is `analysis.go` `exprJSON`'s `VarE` case (add the lifted-var
`Ident` arm).

If the corpus mediation judges the `Var` shape irreplaceable (the A1
JSON is the contract for all backends and the estree renderer is the
single consumer of the lifted-Var→Identifier derivation), the
alternative is to mark this request REJECTED with a mediation note —
but then `A1 node Ident` stays permanently uncovered for ALL frontends
(none emits it today), and the A1-node proxy keeps reporting it as the
first actionable gap for zsh-sh-go.

## FAILING-CASE

Minimal zsh-sh-go (zsh) snippet — the coverage example this request
unblocks (currently uncreatable):

```zsh
for i in 1 2 3; do
    echo $((i * 2))
done
```

Today `debashc --shir failing.zsh --raw` emits — and the zsh-sh-go
frontend must byte-match — no Ident anywhere; the loop body read is a
`Var`, not an `Ident` (actual emit, `stmt_lines` omitted):

```json
{"type":"For","var":"i",
 "iter":{"type":"Array","elements":[{"type":"Str","style":"DoubleQuoted","value":"1"},{"type":"Str","style":"DoubleQuoted","value":"2"},{"type":"Str","style":"DoubleQuoted","value":"3"}]},
 "body":[{"type":"Expr","expr":{"type":"Call","func":"exec","purity":"Emulable",
   "args":[{"type":"Str","style":"DoubleQuoted","value":"echo"},
     {"type":"Array","elements":[{"type":"Arith","ast":{"type":"Bin","op":"*",
       "lhs":{"type":"Var","name":"i"},"rhs":{"type":"Num","value":2}}}]}]}}]}
```

After the change the A1 must contain (the deserializer + estree renderer
already consume this shape):

```json
{"type":"Arith","ast":{"type":"Bin","op":"*","lhs":{"type":"Ident","name":"i"},"rhs":{"type":"Num","value":2}}}
```

Repro of the gap itself (no core change needed to see it):
`bash frontends/coverage/coverage-gap.sh zsh-sh-go` →
`A1 node Ident` (first line of the actionable list), with the gate
green — the examples cannot cover the node until this request lands.

Every ArithAst consumer got the arm: serializer (Ident → {"type":"Ident","name"}), deserializer (KNOWN_ARITH + arith_from), estree renderer (bare Identifier — the lift invariant guarantees the binding), all backends (c/go/js/perl/python/rust/sh/zig/glsl + ir.rs perl renderer + shir_passes lifetime/metric) render Ident exactly like Var (or-pattern arms). schema.json arith.Ident added. The rewrite is export-only: `debashc --shir --raw` for `for i in 1 2 3; do echo $((i * 2)); done` now carries `{"type":"Ident","name":"i"}` inside the Arith Bin; a string-loop (`for s in a b c`) also emits Ident (string-lifted reads render as bare identifiers too); non-loop lifted vars keep Var.
