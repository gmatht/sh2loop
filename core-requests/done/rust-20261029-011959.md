## Why the analysis is wrong here

The only reader of `"t1"` is `arrayIndex(getVar("x"), 0)` — the NAME is
a **runtime value** (it flows through `x`). A static name analysis sees
no read of `t1` and treats the store write as dead / one-shot-hoistable,
but at runtime the read is a plain store lookup by string. `setArray`
writes must stay store-visible whenever any read can carry the name
dynamically (or conservatively: never drop/hoist-away a `setArray`
whose name is also reachable as a string value).

## RESOLVED (same day) — both halves landed in the core

- `sh2perl/src/transforms/dead_store_elim.rs`: a plain identifier string
  literal is now a READ (`is_plain_name`), so `setArray("pair", ["t1"])`
  keeps `t1`'s store. Excluded: a call's own FIRST argument — the write's
  own name must not keep itself alive, or the pass switches off entirely.
  Pin: `name_as_data_keeps_store` (with a control asserting an unread
  scalar store is still dropped).
- `sh2perl/src/estree.rs`: the native-array fold counts literal
  occurrences of a tracked name against its call-name-argument
  occurrences; a surplus is `name_data` and vetoes the fold, so the seed
  stays a `sh2.setArray(...)` store write instead of becoming a lexical
  `let` the store read never consults. Pin:
  `array_name_as_data_keeps_store`.
