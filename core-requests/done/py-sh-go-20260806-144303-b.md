# py-sh-go: dict literals/access need A1 assoc arrays (t73_dict)

## NEED

An explicit A1 shape for associative arrays so py-sh-go can lower Python
dicts: a dict-literal declaration (assoc marker on setArray) and
by-name access (`assocGet(name, key)` / `assocSet(name, key, value)`),
accepted by the shir_json.rs deserializer func whitelist + purity table.

## WHY

`make test` gate: after the worker fixed t72 (list `append`/`len`, now
green), the gate stops at t73_dict.py — the first dict test:

```
FAIL t73_dict.py (frontend emit)
```

py-sh-go cannot lower `d = {"a": 1, "b": 2}`, `d["a"]`, or `d.get("b")`:
the lexer skips `{`/`}`, and there is no dict node in A1. The runner
already has assoc machinery (estree-runner.mjs assocSet/assocGet/
assocNames) but it is leaked through `declare -A` exec — A1 has no assoc
shape, so the frontend cannot emit it. This is the py instance of the
pending `frontends-assoc-arrays-20260806.md` request (which lists this
exact failing case); this file pins the concrete corpus test.

## MINIMAL-CORE-CHANGE

- shir_json.rs: whitelist + purity for `assocSet` / `assocGet` (and
  `assocNames`/`assocKeys` for iteration), following the estree-runner
  signatures (`assocSet(name, key, value)` / `assocGet(name, key)`).
- A declarative assoc marker (e.g. an `isAssoc`/`Assoc` field on
  setArray — the runner's setArray already takes isAssoc) rather than
  the `declare -A` exec leak.
- Structural gate / var_types: dict → assoc type.
- Deserializer + estree.rs renderer support for the new nodes; verify
  `./fail-estree` stays at the trusted baseline.

## FAILING-CASE

```python
# frontends/py-sh-go/testdata/t73_dict.py
d = {"a": 1, "b": 2}
print(d["a"])
print(d.get("b"))
```

Expected stdout: `1` then `2`. Gate verdict today: `FAIL t73_dict.py
(frontend emit)` — the frontend cannot express any of the three
statements. (zsh `typeset -A` and perl `%h` frontends have the same
gap per frontends-assoc-arrays-20260806.md.)
