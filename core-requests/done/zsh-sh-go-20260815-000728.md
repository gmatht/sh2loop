## NEED

The A1 contract needs a representation for the zsh parameter-expansion
flag prefix `(flag_name)` — the tree-sitter-zsh `flag` node (`src/
grammar.json` rule `flag`: `( flag_name [:sep:] | [.sep.] )`, flag_name
= `[a-zA-Z@-]+`) — in the braced-expansion `param` node: `${(t)x}`
(type), `${(f)x}` (split on newline), `${(k)map}` (assoc keys),
`${(j:,:)arr}` / `${(s:,:)x}` (join/split with separator), `${(U)x}` /
`${(L)x}` (case map), and the subscript search flags `${arr[(i)pat]}` /
`[(I)]` / `[(k)]` / `[(r)]`. Today the flag prefix is absorbed into the
variable name in both the core and the zsh-sh-go frontend port, so the
expansion always reads as an unset variable.

## WHY

The zsh-sh-go coverage step (ts-node-gap.sh, tree-sitter node-type
truth) reports `ts node flag` uncovered, but NO testdata example can
pass the executed-stdout oracle: for any set/non-empty parameter the
native zsh output diverges. Verified end-to-end 2026-08-15 with the
current binaries (frontend emit -> `debashc --shir-in-estree` ->
estree-runner.mjs):

    x="a b c"; echo "${(t)x}"
    arr=(p q r); echo "${(j:,:)arr}"; echo "${arr[(i)q]}"
      native zsh 5.9 -> "scalar" / "p,q,r" / "2"
      transpiled A1  -> "" / "" / "SH2ARITH"

Only an UNSET/EMPTY parameter coincides (both sides empty) — a
degenerate corner that would enshrine the mis-tokenization as "covered"
(a passing test hiding a lowering gap, which the project forbids
blessing), not exercise the construct. The A1 `param` node has no
contract-defined slot for a flag prefix, so the runner cannot
legitimately interpret `"(f)x"` as a name either.

## MINIMAL-CORE-CHANGE

In `src/parser/` (the braced-expansion chain,
`parse_variable_expansion` / `parse_parameter_expansion_content`):
recognize the zsh flag prefix `(flag_name)` — and
`(flag_name:sep:)` / `(flag_name.sep.)` — immediately after `${` (and
inside subscripts: `${arr[(i)pat]}` keeps the flag in the subscript
text), split it off the variable name, and carry it as an extra `param`
arg so the serialized A1 round-trips it, e.g.:

    param("", "x", "f")          # ${(f)x}
    param("", "x", "s", ",")     # ${(s:,:)x}
    param("", "arr", "j", ",")   # ${(j:,:)arr}
    param("", "arr", "i", "pat") # ${arr[(i)pat]}

(concrete arg layout open to the estree worker; must round-trip
shir_json.rs / shir_json_in.rs). Real bash rejects `${(...)` ("bad
substitution"), so no bash-corpus file can collide with the new shape.
Then map it in `src/estree.rs` to a runner helper in
harness/sh2-namespace.mjs (zsh mode) implementing at least `t`, `f`,
`s:`, `j:`, `k`, `U`/`L` and the subscript search flags `i`/`I`/`k`/`r`
against the existing vars/arrays/assoc stores. The zsh-sh-go frontend
follows once the core emits the new shape (its byte-equality oracle
tracks the core; the subscript spellings are already waiver-eligible
via harness/zsh-subscript.ere).
