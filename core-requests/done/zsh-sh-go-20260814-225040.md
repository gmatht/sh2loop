# zsh-sh-go: the A1 Break node is never produced by the shell parser (`break` lowers to an opaque `call("break")`)

## NEED
The core's bash-shaped parser must lower the `break` command to the
first-class A1 `Break` node (`{"type":"Break"}`) instead of the opaque
`call("break")` expression. The A1 contract already defines the node
(`frontends/shir-contract/schema.json`: `"Break": {"properties": {"type": {"const": "Break"}}}`)
and the c-sh-go frontend already emits it for C's `break;` — but no
shell-source parser produces it, so the zsh-sh-go frontend (whose gate
is BYTE-EQUALITY with `debashc --shir FILE --raw` on every testdata
file) cannot cover it with any example.

## WHY
The zsh-sh-go coverage step (coverage-gap.sh, the A1-node proxy) reports
`A1 node Break` as an unexercised vocabulary node. The construct IS
covered in source terms — `testdata/t81_break.zsh` exercises `break`
inside a `while` loop and passes the gate — but the frontend emits:

```json
{"expr": {"args": [], "func": "break", "purity": "Control", "type": "Call"}, "type": "Expr"}
```

a `Call`, not a `Break` node — byte-identical to the core's lowering
(`src/shir.rs:7216`: `Command::Break(_) => IrStmt::Expr(call("break", vec![]))`).
The coverage detector keys on the emitted node TYPE, so no additional
`break` example can ever retire the gap: any valid zsh `break` lowers to
`Expr(Call break)` on both sides of the oracle. This is not a subset
refusal (the frontend accepts `break`; t81 is green) and not a missing
contract node (the node exists and the C frontend emits it) — it is a
shared-core parser limitation: the core's `command_to_ir` never produces
`IrStmt::Break` from shell source. The only construction of
`IrStmt::Break` in the core today is a unit-test fixture assertion
(`src/shir_passes/strip.rs:285`), confirming no production path exists.

The node is fully wired on the consumer side: `shir_json.rs:211`
serializes it (`{"type":"Break","runs":…}`), `shir_json_in.rs:482`
round-trips it, the estree renderer maps it to `sh2.break()`
(`shir.rs:15725`, alongside the equivalent `Call func=="break"`
special-case at `shir.rs:15695`), and the perl/go/rust/zig/glsl
backends render it (`last;` / `break;`). Only the producer is missing.

## MINIMAL-CORE-CHANGE
In `src/shir.rs` (the command-to-shIR lowering):

1. `command_to_ir` (line ~7216):
   `Command::Break(_) => IrStmt::Expr(call("break", vec![]))`
   → `Command::Break(_) => IrStmt::Break`
   (the level argument of `break N` is already dropped today by the `_`
   pattern; the A1 `Break` node has no fields, so nothing is lost).
2. The expression-context site (line ~8016,
   `Command::Break(_) => call("break", vec![])`) stays as-is — an
   IrExpr slot cannot hold a stmt node, and that path only matters for
   `break` inside expression positions.
3. No serializer/deserializer/renderer change needed (all listed above
   already handle `IrStmt::Break`).

Then the zsh-sh-go frontend follows (its byte-equality oracle tracks the
core): `lowering.go:2284` `case "break"` emits the `{"type":"Break"}`
stmt node instead of `call("break")`, and a new testdata example (e.g.
t81-style `break` inside a loop, or `break 2` from a nested loop) covers
the node and the gap retires.

Verification for the estree worker: after the change, every bash corpus
file containing `break` changes emitted shape (Call → Break) — run
`./fail-estree` (must stay at the trusted baseline; backends already
render `IrStmt::Break`) and `harness/check_ast.pl` (no break-shape pins
found, but re-check). The semantic output is unchanged: both forms
render to `sh2.break()` / `last;` / `break;` today.

## FAILING-CASE
```zsh
# /tmp/tbreak.zsh — minimal break-in-loop (mirrors testdata/t81_break.zsh)
i=0
while (( i < 5 )); do
    echo $i
    ((i++))
    if (( i == 3 )); then
        break
    fi
done
echo done
```
```console
$ frontends/zsh-sh-go/zsh-sh-go --shir /tmp/tbreak.zsh --raw
# the `break` lowers to {"expr":{"args":[],"func":"break","purity":"Control","type":"Call"},"type":"Expr"}
# — no {"type":"Break"} anywhere in the emit; coverage-gap.sh still
# reports "A1 node Break" after t81_break.zsh passes the gate green.
$ bash frontends/coverage/coverage-gap.sh zsh-sh-go
A1 node Break
# ... (and A1 node Continue — the same pattern for `continue`, which the
# contract also defines as a first-class node)
```
The executed stdout is correct (native zsh and the estree runner both
print `0 1 2 done`); the gap is purely the A1 node-shape, which the
frontend cannot produce while its byte-equality oracle is pinned to the
core's `call("break")` lowering.

## OUTCOME: implemented — verified 2026-08-15 against HEAD+this round: the first-class A1 node is now produced by the shell lowering (Break: shir.rs command_to_ir `Command::Break(_) => IrStmt::Break`; Continue: `Command::Continue(None) => IrStmt::Continue`; Capture: word_ir/parse_string_interpolation `None => IrExpr::Capture{..}` + estree arm; translated string: parse_string_interpolation `$"` prefix + `translate(...)` + runner lang dispatch) and the estree corpus stays at the 545/546 baseline (cargo test --lib 292/293, check_ast 22/0, PERL count unchanged 309/237).
