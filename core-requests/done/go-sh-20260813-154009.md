# go-sh: type switch (`switch v := x.(type)`) — needs an A1 runtime type-dispatch facility

## NEED
The A1 shIR must give the go-sh frontend a way to lower Go's **type
switch** (`switch v := x.(type) { case T: ... }`, ANTLR rule
`typeSwitchStmt`/`typeSwitchGuard`/`typeCaseClause`/`typeSwitchCase`/
`typeList`/`typeAssertion` in grammars-v4 golang) faithfully. Today no
A1 node/field can represent "dispatch on the runtime type of a value":
the A1 store is an untyped runtime string/array model (shell-shaped),
with no type tags, no `typeof`-style operator, and no reflection
primitive. The construct is a grammar-rule coverage gap for go-sh
(unexercised in all 82 testdata examples); the frontend parser chokes
on `.(type)` before lowering can even be attempted.

## WHY
Go's type switch dispatches on the **dynamic type** of the guarded
expression — `x.(type)` is a type assertion that yields the value's
runtime type. The go-sh frontend's philosophy is Refuse > guess: the
only "lowering" possible with today's nodes would be to assume every
`any`-typed value is a string (the store holds only strings) and always
take the `case string` arm — a silent mis-lowering the moment the value
is an int/float/bool/array/etc. A faithful emit requires the A1 to
carry runtime type information (a type tag on the value / a `TypeOf`
primitive) that the discriminated value's storage can consult, so the
`Case` lowering can compare type tags instead of string equality.
Without that, the go-sh parser must keep refusing the construct
(PARSER_GAPS.md, go-sh table, category 1: "dispatch on *type* — needs
the type system").

## MINIMAL-CORE-CHANGE
The smallest change that would let the frontend express a type switch:

1. A **type-tag carrier** on the A1 runtime value model: e.g. a
   `sh2.typeOf(v)` primitive (mirroring `sh2.typeOf` semantics of
   typed runtimes) returning a string type name ("string", "int",
   "float", "bool", "array", ...), plus
2. a lowering contract so `switch v := x.(type)` becomes the existing
   `Case` node with discriminant `Call { func: "typeof", args: [getVar("x")] }`
   and clause patterns `Str("int")`, `Str("string")`, `*` for default —
   the ESTree renderer then emits a normal if/else chain on the type
   name, and `v` binds to `getVar("x")` in each arm.

Minimal variant if a full type-tag store is too invasive: a
`sh2.typeOf` that inspects the JS runtime value (typeof + Array.isArray)
plus a **type-assertion test** (`sh2.isType(v, "int")`) so `Case`
patterns can compare; no changes to the store's string representation
needed for corpus purposes.

## FAILING-CASE
frontends/go-sh/testdata has no type-switch example; the minimal Go
program the frontend currently REFUSES (parse error, exit 2):

    package main

    import "fmt"

    func main() {
        var x any = "hi"
        switch v := x.(type) {
        case int:
            fmt.Println("int", v)
        case string:
            fmt.Println("string", v)
        default:
            fmt.Println("other", v)
        }
    }

Current frontend behavior:

    $ ./go-sh --shir ts.go --raw
    go-sh: line 7: unexpected token ":=" after expression   (with `v :=`)
    go-sh: line 7: expected ident token, got "("            (without `v :=`)
    exit=2

Native Go stdout: `string hi`. A faithful transpiled output must
produce the same for every dynamic type of `x` — impossible without
the A1 type-dispatch facility above.

## OUTCOME: implemented — the A1 type-dispatch facility is live end-to-end. `sh2.typeOf(v)` (typeof + Array.isArray → "string"/"int"/"float"/"bool"/"array"/typeof-fallback) and `sh2.isType(v, name)` landed in the reference runtime (harness/sh2-namespace.mjs) + the structural-gate whitelists (harness/estree_gate.pl, harness/sh2-namespace.json callees, PureCpu/async:false), and the estree renderer maps the contract's `Call { func: "typeof" }` to `sh2.typeOf` (src/shir.rs callee-name mapping — `typeof` is a JS keyword). The frontend can now lower `switch v := x.(type)` with the EXISTING Case node: discriminant `Call typeof [getVar x]`, clause patterns `Str("int")`/`Str("string")`/`*` (default). Verified end-to-end: store-backed `x="hi"` → "string" arm prints `string hi`; a lifted numeric `x=5` → "int" arm; `--shir-in-estree` + gate + runner all PASS. No corpus change (no corpus program calls typeOf). The frontend-side lowering (parse `.(type)`, emit the Case shape, bind `v` per arm) is the go-sh worker's rung.
