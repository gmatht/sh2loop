# zsh-sh-go: unquoted `${#name}` lowers to getVar("#name") — the ESTree emitter reads it from the sh2 store while const vars are lifted to native JS bindings (stale "")

## NEED
The ESTree read-side lowering must honor **lifted (const) variables** for
the `getVar("#name")` call form (the A1 shape of unquoted `${#name}` —
and of zsh `$#name`), not just for `getVar("name")` / `param("len", …)`.
Today a lifted var's length reads the sh2 **store**, which was never
written (store-sync elimination), so `${#x}` yields `""`/`"0"`.

## WHY
`frontends/zsh-sh-go` gate (`make test`): all 53 testdata scripts are A1
**byte-equal** to the core frontend, but the executed-stdout comparison
(harness/frontend-stdout.sh: frontend A1 → `debashc --shir-in-estree` →
node harness/estree-runner.mjs vs native zsh) fails on t38_strlen.zsh
in its unquoted spelling (`echo ${#s}`):

    zsh:            5
    core pipeline:  0   (getVar("#s") reads the store; `s` is lifted)

Verified the CORE's own pipeline produces the identical wrong output
from the core's own A1 on a BASH source — a pure shared-core gap:

    x=42; echo ${#x}     bash → 2; core A1→ESTree→runner → 0

(Generated JS: `let x = 0; x = 42; process.stdout.write(String(x) +
"\n"); process.stdout.write(String(sh2.getVar("#x")) + "\n");` — the
read site falls through to the store while `x` is a native binding.)
The QUOTED spelling `"${#s}"` already works because the core lowers it
to `param("len", "s")`, whose call sites get the value-override
mechanism — the zsh gate uses that spelling today (t38 testdata NOTE),
but the unquoted form (the common zsh spelling) stays broken for any
script that uses it, and the A1 shape is emitted by the core itself.

## MINIMAL-CORE-CHANGE
No new IR node / deserializer / contract work — `Call` round-trips
already; this is the read-side lifted-var inlining in src/shir.rs
(the `--shir-in-estree` lowering; see `str_operand` ~src/shir.rs:10092
and `fully_lifted_template` ~src/shir.rs:15708, which inline
`getVar("name")`/`$name` reads of `is_lifted_str`/`is_lifted` vars as
native identifiers). Two equally small options:

1. **Native inline (no runtime change):** when rendering
   `Call{func:"getVar", args:[Str("#name")]}` (src/shir.rs getVar
   read-site matches, e.g. ~2210 / ~3597 / ~17014), if `name` is
   lifted, emit `String((<binding>).length)` — the length of the
   native binding, exactly what `param("len")` sites already achieve
   via the value override.
2. **Value-override (runtime half is trivial):** emit
   `sh2.getVar("#name", <binding>)` and make the runtime's
   `getVar(name, value)` (harness/sh2-namespace.mjs) use `value` for
   the `#name` form (`String(value).length`, arrays → `arrayLen`).
   The runtime already supports `getVar("#name")` → length from the
   store (added for the zsh gate); honoring a trailing value is a
   3-line addition.

Option 1 keeps the emitter self-contained; option 2 matches the
existing param() override pattern. Either must not regress
`./fail-estree` (the bash corpus has no lifted-var `getVar("#…")`
reads today, so both are additive).

## FAILING-CASE
Minimal bash repro (no zsh needed — the core's own pipeline fails):

    x=42
    echo ${#x}

bash → `2`; `debashc --shir` → `--shir-in-estree` → estree-runner →
`0`. A1 evidence (the core's own `--shir --raw`):

    {"args": [{"style": "DoubleQuoted", "type": "Str",
      "value": "#x"}], "func": "getVar", "purity": "Emulable",
      "type": "Call"}

zsh gate repro (currently worked around via the quoted spelling):
`frontends/zsh-sh-go/testdata/t38_strlen.zsh` with `echo ${#s}` —
zsh → `5`, pipeline → `0`. Gate: `cd frontends/zsh-sh-go && make
test` — must reach "frontend-stdout [zsh]: 53/53 match, 0 FAIL".
