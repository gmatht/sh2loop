# go: the A1 emitter's builtins namespace is ahead of the published contract — backend ingress refuses legitimate A1

## NEED

The five names that exist only in the core checkout's **working tree**
`BUILTINS` table (`id`, `od`, `panic`, `realpath`, `tty`) must reach `main`
(commit + merge), because a backend gate builds its **renderer** from a
worktree synced to `main` while its **emitter** is built from the core
checkout's working tree. Until they do, every backend whose ingress
validates the `builtin` op refuses any corpus file that carries one of
them, and the gate records that refusal as a backend failure.

## WHY

The contract is split across two refs at verification time:

    sh2perl/src/transforms/builtin.rs        (core checkout, dirty)  ->  74 names
    sh2perl/backends/go/src/transforms/builtin.rs  (backend/go == main) -> 69 names

`git -C sh2perl/backends/go rev-list --count HEAD..main` is **0** (the
worktree is synced), and `git -C sh2perl status --short src/transforms/`
shows `M src/transforms/builtin.rs` — the widening is *uncommitted*, so
`setup_backends.sh --sync` cannot deliver it: there is nothing to merge.

The emitter binary the gate invokes is built from that dirty tree
(`otranspilerl` path-depends on `sh2perl`), so its A1 uses the 74-name
namespace while the renderer it is piped into enforces the 69-name one.
The refusal is the ingress contract working as designed — the mismatch is
that the contract has two live versions.

This is the same class as `core-requests/done/perl-20261025-025000-emit-exec-retry.md`:
core-side churn that the gate reports as a per-file verdict. It is not a go
renderer defect (the same file renders rc=0 through the main tree's
`--target go` arm, which never runs the ingress validator).

## MINIMAL-CORE-CHANGE

None to the ABI. Commit `src/transforms/builtin.rs` (BUILTINS 69 -> 74) on
the core branch and merge it into `main`; backends pick it up with
`setup_backends.sh --sync`. The five additions are already written and
documented in that file (“the drift is exactly what turned the core
worker's A1 gate red on 2026-10-25”).

If publishing is deliberately deferred, the alternative is to keep the
emitter's `builtin` op inside the *published* namespace until it is
committed — either way the emitter and the published table must be the same
version at gate time.

## FAILING-CASE

    $ otranspilerl-cli --target shir sh2perl/examples/realpath-cmdsub.sh \
        | go/target/debug/shir_render --target=go -
    ShIR JSON ingress: Program.stmts[1].body[12].then[0].then[1].expr.args[0].elements[1].body[0].expr.func[builtin]:
      args[0] must be a builtins.json command name
    rc=1

The builtin names that file's A1 carries are `echo head local od printf
realpath rm set shift true`; `od` and `realpath` are the two missing from
the published table.

Effect on the gate (`setup_backends.sh --backend-gate go`, 2026-10-25):

    [go] backend gate: 642/651 corpus render OK, 2 fail (0 stubs, 1 equiv, 0 static-analysis), 7 skip
    fails:
    .../realpath-cmdsub.sh        <- this request (render rc=1, ingress)
    .../058_advanced_bash_idioms.sh <- cross-gate interference, not a go defect:
                                       it counts files in the CWD and a second
                                       gate was writing into $WORKSPACE; it is
                                       3/3 identical to bash run on its own.

## OUTCOME: implemented

The 74-name table was already committed to `main` as 864bfd3f5
(`transforms: sync the embedded builtin namespace with harness/builtins.json`),
so the published contract carries `id od panic realpath tty`. The remaining
gap was delivery: `backend/go` sat one commit behind `main`, still holding the
69-name copy. Merged `main` into `backend/go` (commit 72420a457, the single
builtin.rs hunk, clean) and rebuilt `shir_render`.

Verified: the exact failing case now renders with rc=0 and no ingress error —

    $ otranspilerl-cli --target shir examples/realpath-cmdsub.sh \
        | backends/go/target/debug/shir_render --target=go -
    rc=0   (the A1 carries builtin ops for od and realpath; previously refused)

and the rendered Go program's stdout is byte-identical to `bash
realpath-cmdsub.sh`. Ingress validates via `crate::transforms::builtin::is_builtin`,
i.e. the same `BUILTINS` const we synced, so no ABI change was needed.

Note on the main checkout: its working tree was on a feature branch
(`fm-wc-semantics2`) whose HEAD predates 864bfd3f5, and a concurrent worker
reverted the uncommitted widening there mid-round. That checkout is not the
published contract (`main` is), and a 69-name emitter is harmless here — it
leaves `realpath`/`od` as `exec`, which ingress accepts — so this does not
reopen the failure.
