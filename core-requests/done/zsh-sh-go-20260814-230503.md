# zsh-sh-go: the A1 Capture node is never produced by the shell parser (`$(...)`/backticks lower to the opaque `call("capture")`)

## NEED
The core's bash-shaped parser must lower command substitution (`$(...)` and
backticks) to the first-class A1 `Capture` expr node
(`{"type":"Capture","expr":...,"native":false}`) instead of the opaque
`call("capture", [Arrow(...)])` expression. The A1 contract already defines
the node (`frontends/shir-contract/schema.json` exprs vocabulary:
`"Capture": {"fields": {"type":"str","expr":"expr","native":"bool"}}`), but
no shell-source parser produces it — so the zsh-sh-go frontend (whose gate
is BYTE-EQUALITY with `debashc --shir FILE --raw` on every testdata file)
cannot cover it with any example.

## WHY
The zsh-sh-go coverage step (coverage-gap.sh, the A1-node proxy) reports
`A1 node Capture` as an unexercised vocabulary node. The construct IS
covered in source terms — `testdata/t34_cmdsub.zsh` (`x=$(echo hi)`) passes
the gate — but the frontend emits:

```json
{"args":[{"body":[...],"type":"Arrow"}],"func":"capture","purity":"Spawn","type":"Call"}
```

a `Call`, not a `Capture` node — byte-identical to the core's lowering
(`src/shir.rs:8094` and `src/shir.rs:8716`:
`None => call("capture", vec![IrExpr::Arrow(command_arrow_stmts(cmd))])`).
The coverage detector keys on the emitted node TYPE, so no additional
capture example can ever retire the gap: any valid zsh `$(...)` or backtick
lowers to `Call capture` on both sides of the oracle. This is not a subset
refusal (the frontend accepts command substitution; t34 is green) and not a
missing contract node (the node exists, is serialized at
`src/shir_json.rs:421`, round-trips at `src/shir_json_in.rs:984`, and has
analysis arms throughout `src/shir.rs` — 589/1289/1863/2001/2202/2461/
3313/3615/3755/4513/4881/10561/12934/14637/14789/15548) — it is a
shared-core parser limitation: the core's `word_ir` /
`parse_string_interpolation` never produce `IrExpr::Capture` from shell
source. The only constructions of `IrExpr::Capture` in the core today are
in the PERL GENERATOR (`src/generator/words.rs:858,866` and
`src/generator/commands/pipeline_commands.rs:719,858`, for clean `qx{}`
emission of head/tail/find cmdsub), confirming no frontend-parse path
exists. Same shape as the precedent `A1 node Break`
(`core-requests/zsh-sh-go-20260814-225040.md`, pending).

## MINIMAL-CORE-CHANGE
In `src/shir.rs` (the command-substitution lowering):

1. `word_ir`'s `Word::CommandSubstitution` arm (line ~8094):
   `None => call("capture", vec![IrExpr::Arrow(command_arrow_stmts(cmd))])`
   → `None => IrExpr::Capture { expr: Box::new(IrExpr::Arrow(command_arrow_stmts(cmd))), native: false }`
2. `parse_string_interpolation`'s `StringPart::CommandSubstitution` arm
   (line ~8716): the same replacement.
3. The `$(( expr ))` arithmetic branch above both stays as-is
   (`call("arith", ...)` / `IrExpr::Arith`) — only the runtime capture path
   changes.
4. `captureWords` (for-iterable captures, `for x in $(...)`) stays a
   runtime `Call` — the A1 contract has no captureWords node, so it is out
   of scope.
5. CONSUMER COMPANION (required, or the estree gate regresses): the
   estree renderer `expr_to_estree` (`src/shir.rs:30835`) has NO
   `IrExpr::Capture` arm today — the runtime capture renders via the
   `Call { func, .. } if func == "capture"` special-case (~line 16131,
   `x = await sh2.capture(...)`). Add an `IrExpr::Capture { expr, native }`
   arm producing the same runtime-capture lowering as the `Call capture`
   arm (e.g. by rewriting `Capture{expr,native:false}` to the equivalent
   `Call{capture}` for the runtime; the exact mapping is the worker's
   call). The zig backend already tolerates `Capture` (`src/zig_backend.rs:1063`).

Verification for the estree worker: after the change, every bash corpus
file containing `$(...)`/backticks changes emitted shape (Call → Capture) —
run `./fail-estree` (must stay at the trusted baseline), `harness/check_ast.pl`
(re-check for capture-shape pins), and the zsh-sh-go gate. The semantic
output is unchanged: both forms render to the same `sh2.capture(...)` /
async-capture machinery today.

Then the zsh-sh-go frontend follows (its byte-equality oracle tracks the
core): `lowering.go:1111` (`$(...)` in interpolation) and `lowering.go:1326`
(backtick/`$(...)` quoted RHS) emit the `{"type":"Capture","native":false}`
node instead of `call("capture", ...)`, and a testdata example (e.g. a
t34-style `x=$(echo hi)` plus a backtick capture) covers the node and the
gap retires.

## FAILING-CASE
```zsh
# minimal command substitution — mirrors testdata/t34_cmdsub.zsh
x=$(echo hi)
echo $x
```
Currently emitted (both `debashc --shir FILE --raw` and the zsh-sh-go
frontend, byte-identical):

```json
{"expr":{"args":[{"body":[{"expr":{"args":[{"style":"DoubleQuoted","type":"Str","value":"echo"},{"elements":[{"style":"DoubleQuoted","type":"Str","value":"hi"}],"type":"Array"}],"func":"exec","purity":"Emulable","type":"Call"},"type":"Expr"}],"type":"Arrow"}],"func":"capture","purity":"Spawn","type":"Call"},"targets":[{"indices":[],"sigil":null,"var":"x"}],"type":"Assign"}
```
Expected after the change: the same tree with
`{"type":"Capture","expr":{...Arrow...},"native":false}` in place of the
`Call capture`. A backtick form (`` x=`echo hi` ``) lowers through the same
site and must produce the same node.
