## WHY
The coverage hook (`rules-gap.sh py-sh-go`) still reports `sliceop` as a
Python3 grammar rule no testdata example exercises (verified again
2026-08-14 02:19 against the built `./py-sh-go --shir`). No example can
be created: the frontend still refuses EVERY sliceop form, so any
testdata example would fail the gate's emit step. This is NOT a by-design
subset refusal: py-sh-go has no FRONTEND.md; refused-py-sh-go.txt has no
slice/step entry; PARSER_GAPS.md's py-sh-go table categorizes `sliceop`
as category 1 (A1-EXTENSION — "step slices: the shell param-slice idiom
has no step; `a[1:3]` maps (t37/t66), `a[1:3:2]` can't"), the category
whose section ("Escalating the A1-EXTENSION items") describes rows as
"requests waiting to be filed", NOT subset decisions; and the 2-part
slice IS supported and covered (t37_substring, t66_array_slice lower to
the 4-arg `param("slice", …)`).

STALL-CAP RISK (why this 4th file exists): the stall cap in
main_loop_estree.pl auto-moves a pending request to done/ as 'stalled'
after 3 untouched cycles — `py-sh-go-sliceop-20260814-001712.md` is at
cycle 1/3 (its `.stall` file holds `1`). If the estree worker keeps
leaving these untouched, they will be auto-stalled to done/, which the
coverage worker's prune step (`worker-coverage-step.sh`) would then
misread as "request completed" and drop `sliceop` from
core-pending-py-sh-go.txt — hiding a still-unfixed gap behind a false
resolution. An auto-stall is NOT an implementation: the frontend would
still refuse `a[1:6:2]`.

## FAILING-CASE
Minimal Python program (python3 runs it fine):

```python
a = ["a", "b", "c", "d", "e", "f"]
print(" ".join(a[1:6:2]))
```

python3 stdout: `b d f` (indices 1, 3, 5).

Variants that must also work once the frontend arm lands (the contract
already handles all of them — verified): `print(" ".join(a[::2]))` →
`a c e`; `print(" ".join(a[1:6:]))` → identical to `a[1:6]` (`b c d e f`).

Current behavior (re-verified 2026-08-14 02:19 against the built
`./py-sh-go --shir`):
`a[1:6:2]` / `a[1:6:]` → `py-sh-go: parse: expected "]"` (exit 2);
`a[::2]` / `a[::-1]` → `py-sh-go: parse: unexpected token ":"`. So no
testdata example can cover `sliceop`, and the construct remains
inexpressible end-to-end even though every A1 contract / runtime piece
for the 5-arg step slice is in place.
