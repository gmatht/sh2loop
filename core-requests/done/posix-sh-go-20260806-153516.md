## NEED
The A1 contract must carry the **quoted vs unquoted** distinction for
expansion sites where bash field-splits, and the ESTree lowering +
runner must honor it. Today `for w in "$y"` and `for w in $y` are
**byte-identical** in A1 — both emit the For.iter element as
`Call{func:"getVar", args:[Str "y"]}` — so the ESTree backend lowers
both to a native `ForOfStatement` over `[].concat(y)` (one iteration)
and the runner never splits. Same for `set -- $y` → `exec set -- [getVar y]`
→ one positional `"a b c"` instead of three.

## WHY
`frontends/posix-sh-go` gate (`make test`): 56/56 testdata scripts are
A1 **byte-equal** to the core frontend (`debashc --shir --raw`), so the
frontend cannot deviate; the executed-stdout comparison
(harness/frontend-stdout.sh: frontend A1 → `--shir-in-estree` → node
estree-runner.mjs vs native bash) fails on the unquoted spelling:

    y="hello world"
    for w in $y; do echo "word=$w"; done

bash → `word=hello` / `word=world`; the core A1→ESTree→runner pipeline →
`word=hello world` (single iteration). Verified the CORE's own pipeline
produces the identical wrong output from the core's own A1 — a pure
shared-core gap (the Perl backend shares it: `for my $w (${y})` iterates
the scalar once). The frontend's testdata now uses the quoted spelling
(`for w in "$y"`, NOTE comment) so the gate is green, exactly the
zsh-sh-go t38 pattern for `${#s}` (see
`core-requests/zsh-sh-go-20260806-152949.md`) — but every real POSIX sh
script using the unquoted form stays broken until the core fixes it.

## MINIMAL-CORE-CHANGE
(As in the 152225 re-file — implement that request.) Smallest viable
slice: **only the for-iter site** (t04_params.sh's case), plus the
`set --` exec-arg site if free.

1. **A1 + lowering (contract):** when the IR builder (src/parser/ +
   lowering, the same path that builds `For.iter` and `exec_args_ir`)
   sees an UNQUOTED expansion in a for-iter / exec-arg position, emit
   `Call{func:"split", args:[<the expansion's Call>], purity:"Emulable",
   type:"Call"}` — a new reserved func in the A1 contract (shir_json.rs
   already round-trips arbitrary Call funcs, so this is additive; the
   deserializer needs no change unless it validates func names).
2. **ESTree lowering (src/estree.rs, the `For.iter` → ForOfStatement
   path):** lower `split(x)` to `x.split(/\s+/)` (default-IFS whitespace
   splitting, filtering empty fields), so the native `ForOfStatement`
   iterates per field and the runner needs no new helper.

Scope note: fixing for-iters is sufficient for the failing case; the
`set --` case is the same one-line pattern and should ride along only
if it doesn't regress `./fail-estree` (the bash corpus has no unquoted
for-iter/exec-arg splits today, so both are additive).
