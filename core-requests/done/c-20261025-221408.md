# c-20261025-221408 — the shared core does not build: `fold_capture_echo_cond` has no definition

## NEED

`sh2perl/src/shir.rs` (working tree, uncommitted) calls
`crate::estree::fold_capture_echo_cond(program)` at the end of
`shir_to_estree`. `sh2perl/src/estree.rs` defines no such function, and no
revision of it ever has (`git log --all -S fold_capture_echo_cond` is empty;
every stash is clean of the name). The core therefore fails to compile, and
with it the whole backend gate: `debashl` (lib) cannot be produced, so
`otranspilerl-cli` cannot be built, so no backend can render `--target shir`
and every worktree gate in the workspace is red for a reason that is not in
its own tree.

```
error[E0425]: cannot find function `fold_capture_echo_cond` in module `crate::estree`
  --> /mnt/wsl/projects/sh2loop/sh2perl/src/shir.rs:33497:46
     |
33497 |     let program = crate::estree::fold_capture_echo_cond(program);
     |                                               ^^^^^^^^^^^^^^^^^^^^ not found in `crate::estree`
error: could not compile `debashl` (lib) due to 1 previous error; 48 warnings emitted
```

Reproduced from a clean `cargo build --lib` in `sh2perl/` on 2026-10-25
22:05Z and again 22:08Z; `src/estree.rs` mtime 05:44, `src/shir.rs` mtime
05:45 (+0800), unchanged since — this is an abandoned half-edit (the worker
session that wrote it died), not a transient mid-write.

## WHY

Nothing in `backends/c/` can fix it: `src/estree.rs` and `src/shir.rs` are
single-owner shared-core files, and the c worktree is a separate copy of the
crate that does not carry this edit. The backend's own renderer builds and
its gate replica scores 644/644 green against the last good core binary; the
official gate is blocked ONLY on this symbol.

The c worker is not requesting a new capability — it is reporting that an
existing call site lost its definition. Both halves of the intended change
(the call in `shir.rs` and the `fold_capture_echo_cond` body) were clearly
meant to land together: the call's own comment describes the fold in detail
("`$(CMD && echo TEXT)` / `$(CMD || echo TEXT)`: the capture's value is
exactly echo's bytes, so the captureSync wrapper + the echo dispatch
collapse to the (compile-time-escaped) string. Runs right after the array
fold so the dead-flag / lastExit passes below see the result.").

## MINIMAL-CORE-CHANGE

Either:

1. **Add the missing definition** to `sh2perl/src/estree.rs` — the fold the
   call site describes (collapse a `Capture` whose body is `CMD && echo TEXT`
   / `CMD || echo TEXT` to the literal `TEXT`, compile-time-escaped), then
   build the core and let the gates re-score; or

2. **Drop the call** at `sh2perl/src/shir.rs:33497` (and its comment) if the
   fold is not wanted — the core then builds exactly as `HEAD` does and
   every backend gate recovers.

Preference is (1) only if the fold is actually intended and gated green by
the estree cell it was written for; otherwise (2), because a core that does
not build stops every worker in the workspace.

## FAILING-CASE

Whole-corpus, every backend: the gate's first step is
`cargo build --bin otranspilerl-cli` against the shared core, which stops at
`E0425`. No per-cell repro is possible — the failure is at link stage, before
any script is rendered.

Verified locally that the c tree is otherwise healthy: with the last good
`otranspilerl-cli` binary (05:41) the c gate replica runs the full corpus at
644 pass / 0 fail / 0 stubs, and `harness/backend_runtime_metric.sh c`
reports 608 runtime mentions over 563 cells.

## OUTCOME: implemented

Option (2): the dangling `fold_capture_echo_cond(program)` call (src/shir.rs)
and its uncommitted identity stub (src/estree.rs) were both removed. The fold
had no defining body in any revision, is not exercised by any corpus example
(the `&& echo A || echo B` shapes need a lastExit-preserving ternary, not a
literal fold), and no estree cell gates it — so per the request's own
preference order, buildability was restored by dropping the call rather than
shipping an untested optimization. `cargo build --lib` and
`--bin otranspilerl-cli` are green; `./fail-estree` is 563/563 (PERL and
ESTREE, 0 fails). `cargo test --lib` has 50 pre-existing failures in this
dirty tree (verified byte-identical with the stub restored, so unrelated).
