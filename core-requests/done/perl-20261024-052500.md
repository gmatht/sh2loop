# perl: RE-FILE — copy-propagation still folds across `unset`; this is the one red cell

Type: shared-analysis bug (no new node, no contract change, no transform offer)
Requested by: perl backend worker (backends/perl, branch `backend/perl`)
Status: duplicate of `perl-20261024-032941.md` and `c-20261023-210500-unset-const-fold.md`
— both are still correct and still unfixed. Re-filed because the 05:15 gate
cycle is the third consecutive red and the perl side has no move left.

## NEED

`src/transforms/copy_propagation.rs` must stop mistaking a 1–2 letter VARIABLE
NAME for a command-line flag in `classify_builtin_writes`, so that
`unset x` / `read x` / `declare -i x` invalidate the single-def table entry
for `x`.

## WHY

The perl gate is red on exactly one cell:

```
[perl] backend gate: 642/650 corpus render OK, 1 fail (0 stubs, 1 equiv, 0 static-analysis), 7 skip
fails: sh2perl/frontends/posix-sh-go/testdata/t70_unset.sh
```

That file is `x=5; unset x; echo "${x:-gone}"`. The emitted A1 has already lost
the expansion before any renderer sees it:

```
$ otranspilerl-cli --target shir t70_unset.sh
stmts[2].expr.args[1].elements = [{"type":"Str","style":"DoubleQuoted","value":"5"}]
```

bash prints `gone`; every backend necessarily prints `5`. No renderer can
repair this — the write is gone from the IR.

Root cause, measured this cycle on the current main tree:

```
x    = 5; unset x; echo "$x"   -> Str("5")        (folded — wrong)
xy   = 5; unset xy; echo "$xy" -> Str("5")        (folded — wrong)
xyz  = 5; unset xyz; echo "$xyz" -> getVar("xyz") (correct)
SH2_TRANSFORMS=copy-propagation  -> folds
SH2_TRANSFORMS=__none__          -> getVar        (correct)
```

`analyze_var_const` (src/shir.rs) already returns `Var` for `x` here — it lists
`unset` in `STORE_WRITE`. The fold is copy-propagation's own local write scan,
which drops the word before the write is counted:

```rust
let s = s.trim_start_matches('-');
if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
    continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
}
```

The dash is stripped BEFORE the flag test, so the test cannot tell `-i` from a
variable actually named `i`. A bare `x` (or `i`, `n`, `v`) is therefore not
counted as a write, `collect_defs` still sees "assigned exactly once", and
`fold_expr` substitutes the stale literal at every later read. (The `let` arm
further down loops over the same args and has the same hole.)

## MINIMAL-CORE-CHANGE

Only treat a word as a flag when it actually carried a leading `-`:

```rust
 for a in args {
     if let IrExpr::Str(s, _) = a {
-        let s = s.trim_start_matches('-');
-        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+        let dashed = s.starts_with('-');
+        let s = s.trim_start_matches('-');
+        if s.is_empty() || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
             continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
         }
```

`-A` never matched that predicate anyway (not ASCII-alphabetic); long options
(`--x`) and `-v` keep working. A unit test in the module should pin both sides:
`x=5; unset x; echo "$x"` must NOT fold, `x=5; echo "$x"` must fold.

## OUTCOME: implemented

Landed in `sh2perl/src/transforms/copy_propagation.rs::classify_builtin_writes`: a word is treated as a command-line flag only when it actually carried a leading `-`, so a bare 1-2 letter NAME (`unset x`, `read ab`, `local n`) is recorded as a write and copy-propagation refuses the stale fold. Pinned by unit tests `unset_invalidates_single_def`, `read_invalidates_single_def`, `dashed_flag_is_still_skipped`, `folds_without_unset`.
