## NEED

A word in a store-writing builtin's argument list (`unset`/`read`/`declare`/`local`/
`export`/`readonly`/`mapfile`/`readarray`) must be treated as a command-line FLAG only
when it actually carried a leading `-`. The dash is stripped BEFORE the flag test, so a
bare 1–2 letter VARIABLE NAME (`x`, `ab`) is indistinguishable from `-i`: the write is
never recorded, the name still looks "assigned exactly once", `collect_defs` returns it
as a foldable single-def literal, and `fold_param_const`'s `(":-", 3)` arm substitutes
the stale literal into `${x:-gone}` — across the `unset`.

The expansion is gone from the A1, so NO backend can repair it: perl, c, rust, python,
sh and estree all render the literal.
