## NEED

In `classify_builtin_writes`, a word in a store-writing builtin's argument list
must only be treated as a command-line FLAG when it actually carried a leading
`-`. Today the dash is stripped BEFORE the flag test, so a bare 1–2 letter
VARIABLE NAME (`x`, `i`, `n`, `v`, `ab`) is indistinguishable from `-i` and is
dropped — the write to that name is never recorded.

Consequence: the variable still looks "assigned exactly once", `collect_defs`
returns it as a foldable single-def literal, and `fold_expr` substitutes the
stale literal into every later read — including `${x:-gone}` via
`fold_param_const`'s `(":-", 3)` arm.

## WHY (it is a shared-analysis bug, not a perl gap)

The A1 has already lost the expansion, so NO renderer can repair it:

```
$ printf 'x=5\nunset x\necho "${x:-gone}"\n' > /tmp/tc.sh
$ otranspilerl-cli --target shir /tmp/tc.sh | jq -c '.stmts[2].expr.args[1].elements[0]'
{"style":"DoubleQuoted","type":"Str","value":"5"}     # folded ACROSS the unset — wrong
$ SH2_TRANSFORMS=none otranspilerl-cli --target shir /tmp/tc.sh | jq -c '.stmts[2].expr.args[1].elements[0]'
{"args":[{"value":":-"},{"value":"x"},{"value":"gone"}],"func":"param"}   # correct
```

The threshold is NAME LENGTH, not the construct (measured on `d99fdefab`):

```
x=5;   unset x;   echo "${x:-gone}"   -> Str("5")        # folded — wrong
ab=5;  unset ab;  echo "${ab:-gone}"  -> Str("5")        # folded — wrong
abc=5; unset abc; echo "${abc:-gone}"  -> param(":-",…)   # correct
```

The same hole swallows `read n`, `declare -i x`, `mapfile -t a`, `export X`
(→ `t45_env_set.sh` below).

## MINIMAL-CORE-CHANGE

`src/transforms/copy_propagation.rs` line 409-412 — hoist whether the token
actually started with a dash and require it for the flag test. Nothing else
changes; over-counting a write is always SOUND here (it only refuses a fold):

```diff
@@ -407,9 +407,10 @@
     ) {
         for a in args {
```

Notes for the applier:

- This is the ONLY site with the `all(ascii_alphabetic) && len <= 2` heuristic
  in `src/` (`grep -rn 'len() <= 2' src/transforms src/shir_passes` → 1 hit), so
  there is no sibling to fix in the same commit.
- `-A` in that comment never matched the predicate anyway (not ASCII-alphabetic).
- `unset -- x` keeps working: `--` trims to empty → skipped as a flag; `x` is
  then counted.
- **It must land on MAIN.** The backend gates build
  `$ROOT/otranspilerl` (`debashl = { path = "../sh2perl" }`), i.e. the main
  checkout's core. A fix committed only inside `backends/perl/src` would not
  move any gate.

## OUTCOME: implemented
