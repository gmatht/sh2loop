# powershell-sh-go: A1 Function node has no named-block field — PowerShell begin/process/end blocks are inexpressible

## NEED
The A1 contract must extend the `Function` statement node (or add a
named-block statement) so the powershell-sh-go frontend can lower
PowerShell named blocks (`block_name` = `dynamicparam`/`begin`/
`process`/`end`/`clean` + a statement_block each, per
wharflab/tree-sitter-powershell rule `named_block`) and the ESTree
backend can render them. Proposed shape (serde_json BTreeMap-sorted
keys, mirroring the existing node style; absent blocks = empty arrays,
so the existing 13-field shape is untouched):

```json
{
  "type": "Function",
  "name": "foo",
  "params": [],
  "named_blocks": {
    "begin":       [<stmt>...],   // runs once, before pipeline input
    "process":     [<stmt>...],   // runs once PER pipeline input item
    "end":         [<stmt>...],   // runs once, after input is exhausted
    "clean":       [<stmt>...],   // PS 7.3+: runs after end (finally-like)
    "dynamicparam": [<stmt>...]   // runs during parameter binding
  },
  "body": [<stmt>...]             // existing field; plain functions unchanged
}
```

`params` already exists on `Function` (schema.json has only type/name/
body today — the frontend plan's param binding needs it regardless);
a `named_blocks` map (or, if the core prefers flat statements, a
`NamedBlock { "type": "NamedBlock", "name": "begin", "body": [...] }`
stmt type) is the minimal addition. The one field that MUST land is a
place for the block_name-keyed bodies.

## WHY
The coverage hook reports `block_name` as a parser node no testdata
example exercises. The reason no example exists: the frontend cannot
express it. `lowerStatement` in frontends/powershell-sh-go/lower.go
handles only `pipeline`; a function definition refuses loudly:

    $ ./powershell-sh-go --shir /tmp/fn.ps1 --raw
    REFUSE: statement type "function_statement" near "function foo { ... }"
    (PLAN_POWERSHELL_F.md v1 subset — refuse > guess)

This is NOT a by-design subset refusal. PLAN_POWERSHELL_F.md's v1
mapping table explicitly plans `function name { … }` → "A1 Function
(param binding → positional; `return v` → the value channel)", and the
pinned-refusal list (net member access, classes, scriptblocks as
VALUES, `$_`, try/catch, splatting, …) does not include functions or
named blocks — the refusal is an unlanded rung (REFUSE > GUESS), not an
exclusion. The grammar parses named blocks cleanly (verified: the
`function foo { begin {…} process {…} end {…} }` CST yields
`function_statement → script_block → named_block_list → named_block →
block_name`). The other `block_name` path, `script_block_expression`
(`Write-Output { begin {…} }`), IS a documented by-design refusal
(scriptblocks as values).

But even when the function rung lands, the plain form `function foo {
Write-Output "x" }` lowers fine while the named-block form cannot: the
A1 `Function` node has a single `body: stmt[]` — no representation for
up to five distinct bodies with distinct execution semantics
(dynamicparam during parameter binding; begin once; process once PER
pipeline input item — PowerShell's filter semantics; end once; clean
finally-like). Concatenating the bodies into `body` would miscompile:
a `begin { echo 1 } process { echo 2 }` function invoked without
pipeline input must print only "1", and with two input items must print
"1","2","2" — no combination of existing A1 nodes reproduces the
per-input-item invocation. The executed-stdout oracle
(native_limits_powershell record vs transpiled ESTree run) can never
pass for a named-block example without the node. The frontend could
express it if shIR had the field — lower.go needs only a
`function_statement` case walking `named_block_list` (its
`lowerStatementList`/`lowerCommand` machinery already handles the
block bodies).

## MINIMAL-CORE-CHANGE
1. src/ir.rs + src/shir.rs: add a named-blocks container to the
   function statement (e.g. `named_blocks: Vec<(String, Vec<IrStmt>)>`
   or a `NamedBlock { name: String, body: Vec<IrStmt> }` struct in
   `IrStmt::Function`).
2. src/shir_json.rs / src/shir_json_in.rs: serialize/deserialize the
   new field on `"Function"` (empty map/array when absent, so all
   existing emits and the ESTree corpus stay byte-identical), keeping
   the A1-ingress oracle (`debashc --shir-in-estree`) accepting
   frontend emits.
3. src/estree.rs: render the named blocks in their semantic order —
   dynamicparam/begin before the body, process wrapped in a
   per-input-item loop over the runtime's pipeline-input channel
   (v1 text approximation: the frontend's pipeline is TEXT — a
   process block may run once per line of stdin, matching the plan's
   text-pipe stance), end/clean after the body.
4. frontends/shir-contract/schema.json: add the field to the
   `"Function"` entry (workspace-side; keeps check_schema.py green) —
   per core-requests/README.md the estree worker's fix surface is the
   shared core + harness/*; schema.json is updated by whoever lands
   the node.

The frontend side (a `function_statement` case in lower.go emitting
the node) is powershell-sh-go's own fix and lands after the contract
has the field; the coverage worker retries the gap automatically once
this request completes.

## FAILING-CASE
Minimal PowerShell program (pwsh runs it fine; the semantic the node
must preserve: `"x" | foo` prints "start", "item", "item", "done" —
process runs once per input item, begin/end once):

```powershell
function foo {
  begin { Write-Output "start" }
  process { Write-Output "item" }
  end { Write-Output "done" }
}
```

Current behavior: `./powershell-sh-go --shir` refuses with
`REFUSE: statement type "function_statement"` (exit 1), so no testdata
example can cover `block_name` and the A1 node is missing end-to-end
(frontend emit → ingress acceptance → ESTree run vs native pwsh
stdout).

## OUTCOME: implemented
Core change landed (sh2perl commit to follow): `IrStmt::Function` gained
`named_blocks: Vec<(String, Vec<IrStmt>)>` (ir.rs); shir_json.rs emits the
`"named_blocks"` map ONLY when non-empty (all existing emits stay
byte-identical — posix-sh-go byte-equality oracle still 88/88); the A1
ingress (shir_json_in.rs) accepts the map with the five PowerShell block
names (dynamicparam/begin/process/end/clean) and REFUSES unknown names;
the ESTree renderer wraps the define arrow as
dynamicparam → begin → process (once per pipeline input line, via the new
runtime helper `sh2.pipelineInputLines()` in harness/sh2-namespace.mjs,
gated in estree_gate.pl + documented in sh2-namespace.json) → end → body
→ clean, always async (`fn_call_sync_set` excludes named-block functions
so call sites await the arrow); schema.json Function entry gained the
field. Verified: `./fail-estree` 521/521 (0 failed), PERL count unchanged,
`cargo test --lib` 248 pass (2 new tests), named-block semantics exercised
end-to-end (`echo -e "x\ny" | node harness/estree-runner.mjs` → start,
item, item, done, body, clean; no stdin → start, done, body, clean).
Note: `params` was NOT added — no frontend emits it today and the request
marks named_blocks as the MUST; a follow-up request can add it.
