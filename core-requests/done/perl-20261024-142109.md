Type: shared-analysis BUG in an existing pass (`src/transforms/copy_propagation.rs`,
`classify_builtin_writes`). No new node, no contract change, no transform offer.

Requested by: perl backend worker (`backends/perl`, branch `backend/perl`).

Status: **7th re-file** of one bug. Earlier requests, all still correct, all still
unfixed: `perl-20261024-032941.md`, `perl-20261024-052500.md`,
`perl-20261024-071410.md`, `perl-20261024-073500-unset-const-fold.md`,

This file adds only what the earlier ones did not pin down: (a) the exact

measured blast radius (1–2 letter names only), and (d) that the newer
rewrite of the same pass has the same hole in a different shape.

## NEED

`unset NAME` must disqualify `NAME` from the single-def fold **for every
NAME**, including one- and two-letter names.

## WHY

The perl gate is red on exactly one cell, every cycle:

```
fails: sh2perl/frontends/posix-sh-go/testdata/t70_unset.sh
```

`harness/perl_gate_local.sh` reproduces it (`649/650 render OK, 1 fail

The information is destroyed in A1, before any renderer runs — no backend
can repair it. Measured with `otranspilerl-cli --target shir` on the tree

```
SH2_TRANSFORMS=__none__ on the two failing cases -> getVar / param Call (correct)
```

So the blast radius is exactly the 1–2 letter names, which matches the
mechanism: `classify_builtin_writes` strips a leading `-` *before* testing
"is this a flag?", so a bare `x` is indistinguishable from `-x` and is
dropped before it can be counted as a write. With the write invisible,
`x` still looks "assigned exactly once", and the pass substitutes the stale
literal at the later read.

## MINIMAL-CORE-CHANGE

`src/transforms/copy_propagation.rs`, `classify_builtin_writes` (line ~408),
inside the `typeset|declare|local|export|readonly|read|readarray|mapfile|unset`
arm:

```rust
 for a in args {
     if let IrExpr::Str(s, _) = a {
-        let s = s.trim_start_matches('-');
-        if s.is_empty() || (s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2) {
+        let dashed = s.starts_with('-');
+        let s = s.trim_start_matches('-');
+        if s.is_empty()
+            || (dashed && s.chars().all(|c| c.is_ascii_alphabetic()) && s.len() <= 2)
+        {
             continue; // a flag like -i/-r/-x/-a/-A/-l/-u/-n/-g/-t/-p/-f/-F
         }
         let name = s.split('=').next().unwrap_or(s);
```

`-A` still matches (`dashed` true, `"A"` is ASCII alphabetic, len 1), so no
existing flag behaviour changes; a bare `x` no longer matches, so it is
counted. Long options (`--x`) still take the flag arm.

**Why this does not introduce the obvious regression.** `site()` is called
with `top = false` from this arm, and `collect_defs` refuses any def whose
`top` is false (`if !*top { return None; }`). So a builtin write is a
*count only* — it can never become a foldable literal value. That is already
why `unset foo; echo "$foo"` renders `getVar("foo")` today (count 1,
`top=false`, no fold) rather than folding to the string `"foo"`. Counting
`unset x` therefore only moves `x` from count 1 to count 2, which is exactly
the "assigned more than once" disqualified state. No new fold can appear.

Unit test to pin both sides (the module already has `assign`, `getvar`,
`str_lit`, `expr_stmt` helpers and a `#[cfg(test)] mod tests`):

```rust
/// `x=5; unset x; echo $x` — the store write disqualifies the fold.
/// Pinned with a 1-letter name: `classify_builtin_writes` used to read a
/// bare `x` as the flag `-x` and drop the write.
#[test]
fn unset_invalidates_single_def() {
    let unset_x = IrStmt::Expr(IrExpr::Call {
        func: "builtin".into(),
        args: vec![str_lit("unset"), IrExpr::Array(vec![str_lit("x")])],
    });
    let mut stmts = vec![assign("x", int_lit(5)), unset_x, expr_stmt(getvar("x"))];
    assert!(!transform(&mut stmts));
    assert_eq!(stmts[2], expr_stmt(getvar("x")));
}

/// control: the same program without the `unset` still folds.
#[test]
fn folds_without_unset() {
    let mut stmts = vec![assign("x", int_lit(5)), expr_stmt(getvar("x"))];
    assert!(transform(&mut stmts));
    assert_eq!(stmts[1], expr_stmt(int_lit(5)));
}
```

## THE REWRITE HAS THE SAME HOLE — fix it in whichever revision lands

`backends/perl/src/transforms/copy_propagation.rs` carries a NEWER, much
smaller rewrite of the pass (242 lines; `collect_defs` / `count_assigns` /
`fold_stmt`). Its write scan counts only `IrStmt::Assign` and
`IrStmt::Declare`:

```rust
fn count_assigns(stmts: &[IrStmt], counts: &mut HashMap<String, usize>, values: &mut HashMap<String, IrExpr>) {
    for st in stmts {
        match st {
            IrStmt::Assign { targets, expr, .. } => { /* counts */ }
            IrStmt::Declare { vars, init, .. } => { /* counts */ }
            _ => {}
        }
    }
}
```

`unset` never reaches it at all, so the same fold survives there for **every**
name length, not just 1–2 letters (`x=5; unset x; echo "$x"` keeps
count 1). The `dashed` patch above does not exist to port; the rewrite needs
its own arm: treat `unset` / `read` / `readarray` / `mapfile` / `declare` /
`local` / `export` / `readonly` args as invalidating writes (bump the count,
insert no value), because that revision's `Def` map has no `top` flag to
protect it. Fixing only the old revision makes the cell pass today and
re-breaks it at the next rewrite merge.

## OUTCOME: implemented

Landed in `sh2perl/src/transforms/copy_propagation.rs::classify_builtin_writes`: a word is treated as a command-line flag only when it actually carried a leading `-`, so a bare 1-2 letter NAME (`unset x`, `read ab`, `local n`) is recorded as a write and copy-propagation refuses the stale fold. Pinned by unit tests `unset_invalidates_single_def`, `read_invalidates_single_def`, `dashed_flag_is_still_skipped`, `folds_without_unset`.
