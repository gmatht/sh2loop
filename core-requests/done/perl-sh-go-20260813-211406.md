# perl-sh-go: env-fallback strip (estree-20260813-182440) breaks the reference executor — gate DIFFs "undefined" on $ENV reads

## NEED

The store-read strip from core-request `estree-20260813-182440` (emit
bare `sh2.vars.x` instead of `sh2.vars.x ?? (process.env.x ?? "")`) must
NOT land while the reference executor's `vars` store lacks the env
fallback — or, equivalently, the runtime change the strip depends on
(the `vars` Proxy resolving env names, as in sh2runtime.js) must land in
`harness/sh2-namespace.mjs` FIRST and be verified by the frontend gates
(`frontend-stdout.sh` for pl/py/go/sh/fish/zsh/...) before the emitter
drops the fallback tail.

## WHY

2026-08-13 20:31-20:32 the perl-sh-go gate failed 3/68 (`t02_control`,
`t05_env_read`, `t53_param_default` — every test that READS `$ENV`),
with the transpiled side printing the literal string `undefined` where
native perl printed the env value or the `// "def"` default:

    DIFF t05_env_read.pl:     native /home/llm   vs   transpiled undefined
    DIFF t53_param_default:   native a=def       vs   transpiled a=undefined
    DIFF t02_control:         native world/home/llmfrom-system vs worldundefinedfrom-system

The failure signature matches the strip exactly: the emitter was rebuilt
mid-iteration of 182440 (the estree worker's 20:23 commit + uncommitted
shir.rs/estree.rs edits), and the harness runtime's `sh2.vars` is a
PLAIN null-prototype object (`harness/sh2-namespace.mjs` line 416:
`vars: Object.create(null)`), NOT the env-fallback Proxy that
sh2runtime.js provides. With the fallback tail stripped, `sh2.vars.HOME`
is JS `undefined` → template literal renders "undefined". `t45_env_set`
(pure write-then-read) passed; all non-env tests passed — 3/3, 0 false
positives. The strip's own gate note ("identical for env-backed values
— all never nullish") is only true against sh2runtime.js; the reference
executor every frontend gate (and `./fail-estree`) actually runs is
`harness/sh2-namespace.mjs`, whose `getVar()` method (line 578) is the
only place with `process.env[name] ?? ''`.

The strip is currently reverted (the tree emits the fallback again and
the perl-sh-go gate is green 68/68), but it will recur on the next
iteration — and the estree worker's own `./fail-estree` may not catch
the mid-iteration window before a rebuilt `target/debug/debashc` is
snapshotted by a frontend gate (the snapshot protects against relink
tears, not against a legitimately-linked semantically-broken build).

## MINIMAL-CORE-CHANGE

Either (a) do not strip — keep the `?? (process.env.x ?? "")` tail in
`store_var_read` (shir.rs ~27483) and the native-store fold
(estree.rs ~3094) until the runtime work lands; or (b) land the runtime
side first: give `harness/sh2-namespace.mjs`'s `vars` the sh2runtime.js
Proxy semantics (`get` trap: `k in target ? target[k] :
(process.env[k] ?? '')`, never nullish), re-run `./fail-estree` AND the
frontend gates, then strip. If (b) is chosen, the proxy must keep
`delete`/`has`/spread (`{...vars}` at subshell boundaries, line 2073)
behaving exactly as today for explicitly-unset names.

## FAILING-CASE

`frontends/perl-sh-go/testdata/t05_env_read.pl` (any frontend test that
reads `$ENV`):

    # t05_env_read: read an environment variable
    print "$ENV{HOME}\n";

With the stripped emitter + current harness runtime:

    $ ./perl-sh-go --shir testdata/t05_env_read.pl --raw | debashc --shir-in-estree | estree-runner.mjs
    undefined            # native perl prints /home/llm
