# shir-perl: preserve process substitution through the ShIR (ast_to_ir drops <(cmd))

## NEED

`ast_to_ir` (src/shir.rs) must not drop process substitution. Today it
emits `IrRedirect { mode: "unsupported", target: Str("") }` for both
`<(cmd)` and `>(cmd)` — the inner command text is lost. The IR needs the
process-substitution command preserved so the Perl renderer (and any
bash-capable backend) can reconstruct it.

Minimal contract: emit the redirect with a distinct mode and the inner
command text in the target:

- `<(echo hi)` → `IrRedirect { fd: None, mode: "process-in", target: Str("echo hi") }`
- `>(cmd)`     → `IrRedirect { fd: None, mode: "process-out", target: Str("cmd") }`

(`IrRedirect.mode` is a free `String`; `shir_json.rs`/`shir_json_in.rs`
already serialize/deserialize it as a plain string — no contract/deserializer
change needed. The `fd` stays `None`; the target is the reconstructed inner
command text, e.g. via the same word-to-shell reconstruction the frontends
already use.)

## WHY

The parser already parses process substitution perfectly:

```
Redirect { operator: ProcessSubstitutionInput(Simple(SimpleCommand {
    name: Literal("echo"), args: [Literal("hi")] })), target: Literal("") }
```

but the lowering throws it away (`mode: "unsupported"`, empty target). The
Perl renderer then dies (`debashc: ... redirect mode`) or, in `&&`/`||`
chains / captures, emits `grep -f` with no argument (the `<(cmd)` arg
vanished — see `019_grep_regex.sh`: `echo ... | grep -f <(echo -e ...)`
prints `grep: option requires an argument -- 'f'`).

Corpus files blocked by this single gap (~18 reference process
substitution; the deterministic failures): 012_process_substitution.sh,
040_process_substitution_comm.sh, 041_process_substitution_mapfile.sh,
042_process_substitution_advanced.sh, 096_head_procsub.sh,
process-substitution.sh, 070_cmp_basic.sh, 019_grep_regex.sh (partial).

## MINIMAL-CORE-CHANGE

In `ast_to_ir`'s redirect lowering (src/shir.rs), match the parser's
`RedirectOperator::ProcessSubstitutionInput/Output` variants and emit:

```rust
IrRedirect {
    fd: None,
    mode: if input { "process-in" } else { "process-out" }.to_string(),
    target: <the inner command reconstructed to shell text>,
    interpolate: false,
}
```

The inner command is already a parsed `Command` — reconstruct it with the
existing word/command-to-shell helpers (same text the bash-fallback path
uses). If reconstruction is awkward, even `target` = the inner command's
original source span (if available) would do — the renderer only needs
text it can append to a `bash -c` command line.

Note the ESTree backend currently also sees `mode: "unsupported"` — this
change is additive for it (new modes, no behavior change for existing
modes), and the estree runner can keep treating the new modes as
unsupported until it wants them.

## FAILING-CASE

```sh
#!/bin/bash
diff <(echo a) <(echo b)
grep x <(echo xy)
echo "done"
```

Current: `--shir` emits `{"mode":"unsupported","target":{"value":""}}`,
`--shir-in-perl` dies with `debashc: shIR construct not yet supported by
the Perl backend (redirect mode)`.

After the core change: the Perl renderer appends ` <(echo a) <(echo b)`
to the reconstructed `bash -c` command (bash expands process substitution
natively), and the file passes `harness/ir-perl-metric.sh`.

## (secondary, same effort) parse-gap files

`multiple-awk-in-dqs.sh`, `parse-paren-after-do.sh`,
`parse-unexpected-end-of-input.sh`, `subshell-sed-squote-dquote.sh` fail
`debashc --shir` outright (empty JSON — parser error). If the mediation
batch has room, these are cheap parser-fix candidates that unblock the
ShIR path entirely for those files.
