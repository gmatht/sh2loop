# py-sh-go: debashc --shir-in-estree emits INVALID ESTree JSON (uncommitted hand-rolled writer, CallExpression arm double comma) — wedges every frontend's executed-stdout gate

## NEED
`debashc --shir-in-estree` must emit parse-valid ESTree JSON again. The
current uncommitted working-tree `estree_to_json` writer in
`src/estree.rs` (a mid-WIP serde_json-replacement perf pass) produces a
double comma (`],,"optional"`) for every `CallExpression` node, so the
harness's `estree-runner.mjs` (JSON.parse) dies on the FIRST call in any
transpiled program and every frontend gate's executed-stdout comparison
sees empty transpiled stdout.

This is NOT an A1-contract gap: py-sh-go's A1 emit is valid (the
ingress-acceptance loop — `debashc --shir-in-estree` acceptance — passed
all 82 tests; the failure is downstream, at the executed-stdout stage,
and the emitted JSON is the writer's output, not the A1 input). The
committed core HEAD is clean (`HEAD:src/estree.rs:292` still uses
`serde_json::to_string`); the regression is exclusively the uncommitted
WIP diff in `src/estree.rs` (+902/-146, includes the writer) and the
`src/shir.rs` WIP routing `shir_to_estree_json` through it.

## WHY
py-sh-go gate (2026-08-15 17:25:40): `--- frontend-stdout [py]: 1/82
match, 81 FAIL, 0 SKIP`, `make: *** [Makefile:70: test] Error 1`. Every
DIFF shows non-empty native python3 stdout vs EMPTY transpiled stdout.
Root cause traced byte-for-byte: `write_expr`'s `CallExpression` arm
ends with `out.push_str("],")` immediately followed by
`write_bool_field(out, "optional", *optional)` — and `write_bool_field`
pushes its OWN leading comma, yielding `...}],,"optional":false}`.
`estree-runner.mjs` then fails `JSON.parse` ("Expected double-quoted
property name in JSON at position 833") and outputs nothing. Every py
test lowers `print(...)` → `exec echo` → `process.stdout.write(...)`
(an ESTree `CallExpression`), so every test hits it. (The estree
worker's own `json_writer_matches_serde` unit test in the same file
would also catch this the moment `cargo test` runs.)

## MINIMAL-CORE-CHANGE
One character-class fix in `src/estree.rs`, `write_expr`, the
`Expr::CallExpression` arm (~line 3263):

```rust
-            out.push_str("],");
-            write_bool_field(out, "optional", *optional);
+            out.push_str("]");
+            write_bool_field(out, "optional", *optional);
```

(`write_bool_field` supplies the comma.) Verified against the broken
binary: statement-only programs (`x=1`, `if true; then :; fi`, `:`) are
VALID; every program containing a call is BROKEN at exactly
`],,"optional"`. `MemberExpression` (`computed` + `optional` via two
`write_bool_field`s), `UnaryExpression` (`prefix`), `Property`, and
`ArrowFunctionExpression` arms are correct — the CallExpression arm is
the only comma-collision in the writer. No contract/deserializer/parser
change needed; a unit-test run of `json_writer_matches_serde` (or
`./fail-estree`) plus a JSON.parse of `--shir-in-estree` output is the
verification.

## FAILING-CASE
Minimal (shell side — the writer is shared by the AST and A1 paths):

```sh
printf 'echo hi\n' > /tmp/probe.sh
cd sh2perl && ./target/debug/debashc --shir /tmp/probe.sh > /tmp/p.a1 \
  && ./target/debug/debashc --shir-in-estree /tmp/p.a1 > /tmp/p.e
python3 -c "import json; json.load(open('/tmp/p.e'))"   # ← fails:
# Expecting property name enclosed in double quotes at position 505
grep -o '],"optional"' /tmp/p.e   # shows the `],,"optional"` double comma
```

py-sh-go side: `frontends/py-sh-go/testdata/t01_print.py`
(`print("hello from py-sh-go")` + two var prints) — native python3
prints 3 lines; transpiled run is empty because the ESTree JSON never
parses. Expected after the fix: `OK t01_print.py (stdout match)` in
`make test` (and 82/82 in the executed-stdout phase).

## OUTCOME: implemented — 2026-08-15: the CallExpression arm of the estree_to_json writer no longer pushes its own trailing comma (`out.push(])` + write_bool_field supplies it — the `],,"optional"` collision is gone; json_writer_matches_serde pins the writer). Re-verified end-to-end: py-sh-go t01_print.py --shir-in-estree output JSON.parses cleanly (0 double commas).
