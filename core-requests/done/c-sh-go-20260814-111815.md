# c-sh-go: the A1 DoWhile node panics the ESTree renderer — the frontend can only lower do-while to a duplicated While

## NEED

`debashc --shir-in-estree` (the c-sh-go gate's ingress-acceptance AND
executed-stdout oracle) must handle the A1 `DoWhile` statement node the
C frontend would emit for `do { b } while (c);`. The contract node already
exists end-to-end on the JSON side: `frontends/shir-contract/schema.json`
has `DoWhile { body: stmt[], cond: expr, until: bool }`,
`src/shir_json.rs:216` serializes it, `src/shir_json_in.rs:489`
deserializes it. What is missing is the ESTree RENDER arm: `stmt_to_estree`
(src/shir.rs, the `--shir-in-estree` path) has an `IrStmt::While` arm
(line 15416) but no `IrStmt::DoWhile` arm, so the node falls into the
`unreachable!` at src/shir.rs:16892 → panic → exit 101.

## WHY

The c-sh-go coverage hook (`frontends/coverage/coverage-gap.sh`) reports
the A1 vocabulary node `DoWhile` as a parser construct no testdata example
exercises. The frontend parses C `do-while` fine (t28_dowhile.c is a
passing gate example) but DELIBERATELY lowers it to the pre-test `While`
by body duplication — the code comment at cmd/c-sh-go/main.go:3825:

    // do b while (c) → b; while (c) b — the A1 While is pre-test and
    // DoWhile has no ESTree lowering in the core, so the body
    // duplication is the faithful form ...

This is NOT a subset refusal (do-while is fully within the v1/v2 subset —
the frontend would happily emit the faithful DoWhile node); it is a
shared-core limitation: emitting `DoWhile` today breaks the gate's
executed-stdout oracle (`debashc --shir-in-estree` panics, exit 101 →
"FAIL (emit is not valid A1 shIR)"). Same shape as the ForInit gap
(core-requests/done/c-sh-go-20260812-205941.md): contract node exists,
renderer panics, frontend avoids emitting, escalated to the estree
worker.

## MINIMAL-CORE-CHANGE

Add an `IrStmt::DoWhile { body, cond, until }` arm to `stmt_to_estree`
(src/shir.rs, next to the `IrStmt::While { cond, body }` arm at line
15416), rendering the ESTree `DoWhileStatement { body: BlockStatement,
test }` — body first, then the post-test condition (do-while semantics:
the body runs at least once, unlike the While arm's pre-test shape):

- `until: false` → `test = <cond>` (C `do … while (c)`).
- `until: true` → `test = <!cond>` (the contract's repeat-until form;
  mirrors the existing backends: js_backend.rs:635 lowers `until` to
  `while (!(cond))`).

Reuse the While arm's condition-rendering machinery (the `cond` is an A1
`Call`/test-string here — the c frontend emits `condCall`/`testCall`
test strings, same as its While nodes). The `until` field is currently
unused by the C frontend (always `false`), so the `false` path alone
unblocks the coverage gap; the `true` path keeps the arm total.

## FAILING-CASE

Contract-valid A1 (deserializes fine — the panic is in the renderer),
the exact shape the c-sh-go frontend would emit for
`int i = 0; do { i++; } while (i < 3); printf("%d\n", i);` once the core

Repro:

    debashc --shir-in-estree /tmp/dowhile-a1.json

→ panics, exit 101:

    thread 'main' panicked at src/shir.rs:16892: internal error: entered
    unreachable code: Perl-only IR statement reached the ESTree renderer:
    DoWhile { body: [Assign { targets: [AssignTarget { var: "i", ... }],

After the fix, `--shir-in-estree` must exit 0 and the executed stdout

its do-while lowering to the faithful `DoWhile` node (one t28-shaped
coverage example, gate green), dropping the body-duplication workaround.

## OUTCOME: implemented

The `IrStmt::DoWhile { body, cond, until }` arm landed in the ESTree
renderer (commit af6944b, verified this round): `until:false` renders
`DoWhileStatement { test: <cond>, body }` (body-first, post-test — C
`do … while (c)`); `until:true` negates the test (`!` unary, the
repeat-until form mirroring js_backend.rs). The request's exact
failing-case JSON now exits 0 under `debashc --shir-in-estree` and the
executed stdout via harness/estree-runner.mjs is `3` (matches gcc on
the C source); the `until:true` variant executes correctly too.

Pinned by a new shir_json_in.rs unit test (JSON → IR → ESTree, the
exact `--shir-in-estree` path — the A1 node never comes from the bash
parser, which lowers `until` to a negated `While`) covering both
`until` values.

Collateral fixed in the same commit (a733a06): af6944b also re-tightened
`redirect_specs_sync_ok`/`redirect_call_sync_ok` to an fd-dup-only rule,
which broke 4 estree unit tests and contradicted 43df68e's verified
runtime audit (the "async fs bridge" throw never existed in any
sh2-namespace.mjs version; `_applyRedirectSpecs`/`_ensureRedirectFiles`
are fully synchronous — existsSync/openSync/closeSync/expandWord). The
sync-twin widening is restored; file targets remain sync-capable.
