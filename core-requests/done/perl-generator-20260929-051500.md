## ROOT CAUSES (all read off the emitted Perl, not guessed)

The failures cluster into a handful of specific emitter bugs. Each is
localized to `ir.rs`'s `emit_stmt`/`emit_expr` arms. Per class, the exact
emitted line and the one-line change:

### 1. `while` fed by a pipeline / process substitution reads the parent's STDIN — the loop body never runs
`IrStmt::Redirect`'s redirect arm (`ir.rs:1943-1959`) only handles a **plain
`< FILE`**. A `cmd | while read` or `done < <(cmd)` loses the producer, so the
loop reads the *inherited* STDIN. `065_yes_head_while.sh` loses **100 of 100**
output lines:
```perl
__sh_uu_run('yes', 'Line:LINE'); ...
__sh_uu_run('head', '-n', '100'); ...
while (do { my $__rd = <STDIN>; ... }) {   # STDIN is the gate's, not the pipe
```
Fix: extend the `Redirect`/`While` arm to open a process substitution /
pipeline stage as STDIN (`open(my $fh,'-|',…)` + `local *STDIN`), the way
`native_mapfile_read` already does for `mapfile`.
Affects: `065_yes_head_while` (−100 lines), `063_11_complex_while_loop`,
`063_hard_to_parse`, `096_head_procsub`, `parse-error-block-in-pipeline` (both
time out at perl=124 — consistent with a loop waiting on a stdin that never closes).

### 2. Command-substitution capture inside a function body emits a hard-coded `''`
`062_09_complex_function.sh`:
```perl
    my $result = '';            # `local result=$(echo "$param1" | sed …)`
    print("Result: " . ($result), "\n");
```
The capture becomes a literal `''`, so the line prints `Result: ` instead of
`Result: test"quote`. Same signature in `062_hard_to_lex` (3), `058_advanced_bash_idioms` (5), `063_09_complex_function_parameter_handling`.
Note `capture_from_expr`/`capture_body_is_native` (`ir.rs:786-812`) already
whitelist `echo`/`sed`-shaped bodies; the function-body path appears to bypass it.
Affects: `062_09_complex_function`, `062_hard_to_lex`, `058_advanced_bash_idioms`,
`063_09_complex_function_parameter_handling`.

### 3. `$(VAR+=word)` is emitted as a call to an undefined `assign()`
`051_primes.sh` (and `062_hard_to_lex`, `062_14`, `parse-array-plusassign`):
```perl
$y = assign("y", "+=", "2");
$z = assign("z", "+=", substr($primes[$@], 0, 1));
```
`assign` is never defined in the preamble (`grep -l 'sub assign'` → 0 files),
so the call dies at runtime. The `assign(NAME, op, VALUE)` write is
lowered at `ir.rs:2326` and `:7150`; the **statement** path is unhandled
(the capture path is handled — `emit_capture_assign`, `ir.rs:5357`).
Affects: `051_primes`, `062_hard_to_lex`, and it fires twice in `051_primes`
alone (`y+=2` on a scalar, `z+=(a b)` on an array).

### 4. `printf` `%b` and `%q` fall straight through to Perl's `printf`
`printf-format-and-v.sh` → `+0name=foo-bar` (the `%b` output becomes `0`):
```
 hi 42
-a	b
-name=foo-bar
+0name=foo-bar
```
perl stderr: `Argument "a\tb\n" isn't numeric in printf`.
`%b` (interpret escapes) has no Perl equivalent and `%q` (shell-quote) is
absent entirely — `parse-dollar-single-quote.sh` dies with
`Invalid conversion in printf: "%q"`. Corpus-wide only
`printf-format-and-v`, `parse-dollar-single-quote`, `070_gnuisms_thorough`
use these, so a small `%-translate` shim is enough.
Also visible here: `printf -v name` *does* work (line 3 is correct), so this
is only the `%b`/`%q` gap.

### 5. `eval "<string>"` is stringified, not evaluated
`063_12_complex_eval.sh`:
```
-Eval result: 0
+Eval result: $(( ${var:-0} + ${array[${index:-0}]:-0} ))
```
The whole point of the test — eval of a constructed string — is lost. Needs an
`eval` builtin arm that runs the Perl equivalent of the parsed string (or
routes to the string through the same lowering).

### 6. `~` is not expanded in a word position
`043_home.sh` compares `[ ~ = "$HOME" ]`; bash expands `~` in an unquoted word,
the emitter keeps it literal:
```perl
$CHILD_ERROR = ((lc('~') eq lc($ENV{HOME})) ? 0 : 1);
```
`ls $HOME` passes (shell-out) but `[ ~ = … ]` folds to a literal. Affects
`043_home` (1 test, 3 asserts) and is the shape behind `realpath-cmdsub` /
`qx-var-builtin-cd` reaching a literal `~`/`cd do { …`.

### 7. `test`/`[` argv corrupted by `${VAR+word}` (unquoted expansion)
`variable-plus-operator.sh`:
```perl
$CHILD_ERROR = (length('-n')) ? 0 : 1;   # test -n "${MYVAR+set}"
```
`${MYVAR+set}` became empty, so `test -n` **always** passes; bash prints
nothing. (Contrast: the *quoted* form `${2:-default}` in `062_09` is correct.)
