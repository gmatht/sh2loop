# c-sh-go: the strip_cfor wiring order is wrong — a goto inside a for-body survives to the renderer (t30_goto_nested.c)

## NEED

The `strip_cfor` pass wired by the previous request (`c-sh-go-20260812-205941`)
must run **BEFORE** `restructure_goto_only` in the three CLI A1-ingress paths
(`cli/src/lib.rs` `--shir-in-estree`, `--shir-in-perl`, `--shir-in-sh`), not
after it. Currently:

```rust
debashl::shir_passes::restructure_goto_only(&mut prog);
debashl::shir_passes::strip_cfor(&mut prog);
```

must become:

```rust
debashl::shir_passes::strip_cfor(&mut prog);
debashl::shir_passes::restructure_goto_only(&mut prog);
```

(the `process_subst::transform_program` call stays after both).

## WHY

With the current order, `--shir-in-estree` panics on the c-sh-go gate's
`t30_goto_nested.c`:

```
FAIL t30_goto_nested.c (emit is not valid A1 shIR — the gap the worker fixes)
thread 'main' panicked at src/shir.rs:13915:
internal error: entered unreachable code: Perl-only IR statement reached the
ESTree renderer: Goto("out")
```

Root cause: the frontends emit `goto`/`Label` INSIDE the `ForInit` body
(`for (...) { ... if (c) goto out; }`), and the goto-restructure pass has NO
`ForInit` descent — neither `restructure_children` nor `find_nested`/
`descend_from` in `src/shir_passes/restructure.rs` match `IrStmt::ForInit`.
So when restructure runs FIRST, a goto inside a for-body is invisible to it;
`strip_cfor` then moves the body into a `While`/`Block` — but restructure has
already run, and the `Goto("out")` reaches the renderer's
`unreachable!("Perl-only IR statement …")` arm.

Running `strip_cfor` FIRST lowers the ForInit to `init; while(cond){…}` — the
exact pre-ForInit shape the frontends used to emit — and the goto lands in a
`While`/`Block` that `restructure_children`/`descend_from` DO descend into
(proven: t27_goto, t29_funcptr, t31_goto_forward — gotos in while/block
contexts — pass on the current binary).

## MINIMAL-CORE-CHANGE

Swap the two calls in all three ingress paths in `cli/src/lib.rs`
(currently lines 936-937 / 967-968 / 992-993), keeping the ForInit comment
with the strip call. No other code change. The alternative (adding
`IrStmt::ForInit { init, cond, step, body }` descent to
`restructure_children` AND `find_nested`/`descend_from` in
`src/shir_passes/restructure.rs`) also works but is bigger.
