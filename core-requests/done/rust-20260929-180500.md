# rust: process-substitution producer is dropped from the shIR

## NEED

The procsub lowering emits only the CONSUMER's read redirect. The PRODUCER's
`> __ps_tmpN` write redirect never reaches the A1, so `__ps_tmpN` is created
(empty) and never written. Every backend that consumes this A1 reads an empty
file: the consumer sees instant EOF.

## WHY (failing case, minimal)

`/tmp/t6.sh`:

```bash
f=$(mktemp)
max_lines=3
counter=0
printf '# c\nhas $(sub) here\nplain\n${p} l\n' > "$f"
while read -r line && [ -n "$line" ] && (( counter < max_lines )); do
  if [[ "$line" =~ ^[[:space:]]*# ]]; then continue; fi
  case "$line" in
    *\$\(*\)*) echo "CS: $line" ;;
    *\$\{[^}]*\}*) echo "PE: $line" ;;
  esac
  (( counter++ ))
done < <(grep -v "^#" "$f" | head -n "$max_lines")
rm -f "$f"
```

Expected (bash):
```
CS: has $(sub) here
PE: ${p} l
```

Actual (rust backend): the `while` body never runs — the loop reads the empty
temp file and exits at once. The producer's `grep | head` inherits raw fd 1 and
LEAKS its own output to the program's stdout, so the program appears to print:

```
has $(sub) here
plain
${p} l
```

which is both wrong (no `CS:`/`PE:` prefixes) and a stdout-fd leak.

**Not rust-specific.** The same A1 breaks the reference renderer worse — the
perl backend prints NOTHING at all (rc=0, empty stdout). estree emits no
`__ps_tmp` reference whatsoever. This is a shared-core lowering gap.

## EVIDENCE

`otranspilerl-cli --target shir /tmp/t6.sh` — the complete list of Redirect
nodes in the A1:

```
(1, 'w',  printf output)      <- the fixture write, unrelated
(0, 'r',  __ps_tmp0)         <- consumer read  (the while loop's stdin)
(0, 'r',  __ps_tmp0)         <- consumer read
```

There is **no** `(1, 'w', __ps_tmp0)` producer write. `__ps_tmp0` appears 8x
in the A1, all as a read target or a `mktemp`/cleanup reference; it is never
assigned by a redirect.

`src/rust_backend.rs:8922-8962` already anticipates this shape — it special-cases
`ps_tmp.is_some() && inner.iter().any(|s| matches!(s, IrStmt::While { .. }))`
and converts the temp file into a FIFO with a background producer thread. But
that branch keys on the producer block containing a `While`. A FINITE producer
(`grep … | head …`) has no `While`, so it falls through to the generic path,
which writes the pipeline to `__sh_pbuf0` and never flushes it to
`__ps_tmp0`.

The `__SH_OUTFILE_TL` / `__sh_pbuf0` machinery is exactly the producer-write
plumbing that the generic path already computes — it just is not bound to the
procsub temp file.

## MINIMAL-CORE-CHANGE

In the shIR lowering for process substitution, when a `< <(producer)` is
rewritten to `__ps_tmpN = mktemp` + `producer > __ps_tmpN` + `consumer < __ps_tmpN`,
EMIT the producer write as a real redirect node:

```
Redirect { redirects: [{ fd: 1, mode: "w", target: Var("__ps_tmpN") }],
           inner: [ <producer pipeline> ] }
```

alongside the existing consumer read. The renderer entry point is
`src/parser/` → the pass that rewrites procsub to the `__ps_tmpN` triple
(the same pass that synthesizes the trailing `rm -f __ps_tmpN` cleanup,
which the rust renderer already recognizes at
`src/rust_backend.rs:15309-15335`).

Constraints:
- The producer write must appear ONCE, in source order before the consumer read.
- Keep the existing `rm -f __ps_tmpN` cleanup emission unchanged.
- Do NOT change the consumer-read shape — backends already handle it.

Once the producer write is present, `src/rust_backend.rs:8930`'s FIFO/thread
branch stays correct for INFINITE producers, and the FINITE producer falls
into the generic path which already builds the `__SH_OUTFILE_TL` write — it
only needs the target bound to `__ps_tmpN`. The rust side may then need a
small follow-up to route `__sh_pbuf0` into the temp file; that is a
backend-local concern and will be filed separately if it is still needed
after the core fix.

## FAILING-CASE

- `sh2perl/examples/063_11_complex_while_loop.sh` — rust backend corpus gate
  FAIL (MISMATCH). Same construct: `done < <(grep -v "^#" "$input_file" | head -n "$max_lines")`.
- Minimal repro above; also fails identically through the perl backend.

## OUTCOME: implemented — already landed in commit 0a5ae92f3 "process_subst: the producer's redirect is the INVERSE of the consumer's". In materialize_redirect's non-exec (compound-statement consumer) branch the producer had been handed the CONSUMER's (fd, mode) pair, so `done < <(P)` emitted the producer as a READ — mktemp created the file, nothing wrote it, the consumer hit instant EOF, and the producer's real output leaked to stdout. The process-out consumer also used fd 0 instead of fd 1. Three-line inversion fix; the appendable (exec-consumer) branch was already correct, which is why `diff <(a) <(b)` worked while compound consumers did not.
