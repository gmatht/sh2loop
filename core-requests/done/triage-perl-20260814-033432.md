# triage: perl backend can't render what the zsh-sh-go frontend emits

## NEED
The perl renderer must handle this A1 (the estree reference renders it and
matches native).

## FAILING-CASE
frontend zsh-sh-go, example t32_redirect.zsh (cross-product pair).

## EVIDENCE
estree matches native; perl differs

## OUTCOME: implemented
Genuine shared-core perl-renderer bug, fixed in commit 970d3e9 (this
round). The t32 A1 (Redirect target = Interpolate carrying the `$$` pid;
examples/pid_tempfile is the corpus twin) rendered broken perl: the
non-Str redirect target was silently dropped (`'echo' 'data' > ''`), the
cat-side read emitted the syntax error `${\$}` (the generator's `${$}`
PID interpolation mangled by `$`-escaping), and emulated cat/rm read the
never-populated `$ENV{var}` instead of the preamble's `my $var`. Fixes:
(1) ir.rs Redirect arm binds interpolated/variable targets to a temp
`$ENV{__sh2_rdN}` slot in Perl (perl's `$$`, so the bash -c child writes
the SAME file the perl-side cat reads) and references `"$__sh2_rdN"`
from the bash text; var_exports_str skips the __sh2_* slots. (2)
generator_emulate_command registers the command's non-env var reads as
Generator.declared_locals (`$var` reads match the `my $var` preamble).
(3) words.rs push_string_expr no longer escapes `$` inside `${...}`
interpolation blocks. Verified: t32_redirect.zsh renders + runs "data"
(matches native); pid_tempfile.sh + 4 more corpus examples flipped
perl-FAIL → PASS (perl 320 → 325, no drops); estree 521/521, cargo test
--lib 269/0, check_ast 22/0. Two ir.rs regression tests lock the shapes.
