# perl: top-level `--shir`/`--shir-raw` arms still decode lossily — the gate's emit path

## NEED
The top-level `--shir` and `--shir-raw` arms in `cli/src/lib.rs` (NOT the
`file --shir` subcommand) must read source bytes with the SAME
marked-lossy decoding the estree / legacy-perl / `parse_file_to_shir`
paths use — `SharedUtils::bytes_to_marked_lossy` (PUA markers
U+E000+byte) — instead of `String::from_utf8_lossy` (U+FFFD).

This SUPERSEDES the pending part of `core-requests/perl-20260814-175710.md`:
that request's `parse_file_to_shir` change (the `file --shir` subcommand)
IS landed and verified, but the backend gate and the frontend byte-equality
oracles invoke the TOP-LEVEL `--shir FILE --raw` form, whose arms are still
lossy. Both arms are at:

- `cli/src/lib.rs` `"--shir"` arm (~line 877): `Ok(bytes) => cli_commands::export_shir(&String::from_utf8_lossy(&bytes), raw),`
- `cli/src/lib.rs` `"--shir-raw"` arm (~line 915): `Ok(bytes) => cli_commands::export_shir_raw(&String::from_utf8_lossy(&bytes)),`

## WHY
`sh2perl/examples/utf8-non-utf8-content.sh` contains an ISO-8859-1 byte
0xE9 inside a double-quoted echo. bash passes the raw byte through:

    $ bash utf8-non-utf8-content.sh | xxd
    ... 6163 63e9 6e74 ...   (acc<E9>nt)

The perl backend gate (`setup_backends.sh --backend-gate perl`) fails the
file: `debashc --shir FILE --raw` (the gate's emit) carries U+FFFD
(ef bf bd) because the top-level arm decodes lossily, and the perl
renderer can only reproduce what the contract carries. The js gate fails
it for the same reason. The renderer side is DONE and verified: the perl
worktree (`perl_backend.rs` `perl_str`) decodes U+E000..U+E0FF back to
`\xNN` byte escapes — feeding it the `file --shir` output (which has the
markers) produces BYTE-IDENTICAL stdout vs bash.

With the top-level arms fixed, the perl gate reaches 613/613 (it is at
612/613 now — the other 7 failures were the backend gate's exit-code
check, fixed gate-side, see below).

## MINIMAL-CORE-CHANGE
In `cli/src/lib.rs`, both arms: replace
`String::from_utf8_lossy(&bytes)` with
`debashl::shared_utils::SharedUtils::bytes_to_marked_lossy(&bytes)` —
exactly what `cli/src/cli_commands.rs::parse_file_to_shir` already does
(landed for perl-20260814-175710). No serializer/deserializer change:
serde_json round-trips the PUA chars (U+E000..U+E0FF are valid UTF-8)
and `shir_json_in` passes them through. Frontend byte-equality oracles
are unaffected in the direction that matters: frontends that already
match the core's CURRENT lossy output on valid-UTF-8 files still match
(valid files are unchanged); a frontend that emits its own PUA markers
for invalid bytes will now match the core instead of mismatching.

## FAILING-CASE
```
$ printf 'echo "acc\351nt"\n' > /tmp/iso.sh
$ sh2perl/target/debug/debashc --shir /tmp/iso.sh --raw | grep -o 'acc.\{0,4\}nt' | xxd
... 6163 63ef bfbd 6e74     # U+FFFD — byte 0xE9 lost (top-level arm)
$ sh2perl/target/debug/debashc file --shir /tmp/iso.sh | grep -o 'acc.\{0,4\}nt' | xxd
... 6163 63ee 83a9 6e74    # U+E0E9 PUA marker — already correct (parse_file_to_shir)
```

## Gate-side context (NOT a core change — for the harness owner)

The backend gate's equivalence check previously required rc=0 on BOTH
sides plus stdout equality. Seven corpus files exit nonzero BY DESIGN
(bash's own exit code: `exit 1`, `exit 3`, `[[ ... ]] &&` short-circuits,
a `bad substitution`), so no renderer could pass them — for ANY backend.
The gate's own comment says "only stdout is ever compared", and the
system's estree oracle (fail-estree) compares stdout + exit codes as
EQUALITY with an argv0 rewrite. The perl worker has FIXED the gate
mirroring fail-estree (setup_backends.sh, committed):

1. perl arm runs `perl -M5.010 -e '$0 = shift @ARGV; my $__f = shift @ARGV; do $__f' "$f" /tmp/eq.pl` — argv0 = the source path, so `$0`-dependent stdout agrees with bash (the A1 JSON carries no source path, and adding one would break the frontends' byte-identical A1 comparison).
2. perl exit codes must MATCH bash's (not both-0); other backends keep the old rc=0 contract (their arms collapse rc to 0/1); a 124 timeout on either side is a fail.

The perl renderer also gained (branch backend/perl, committed):
- a trailing `exit(($? >> 8));` when the LAST top-level statement's
  rendering sets `$?` (bash's exit = last command's status) — 0
  regression on the corpus, and it makes the short-circuit / bad-subst
  files reproduce bash's exit code;
- optional A1 `source`-field support (`shir_to_perl_src` + the
  `--shir-in-perl` CLI reads `"source"` from the JSON; `$0` renders as
  the baked literal) — unused by the gate (argv0 covers it) but ready
  for direct CLI use.
