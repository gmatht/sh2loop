# parser: bash-parses 4 corpus examples the core frontend rejects — all generators should parse them

## NEED
The core shell parser must parse the 4 examples bash accepts (the backend
gate skips them as "core-unparseable"; the user directive: "if bash can
parse them so should we").

## WHY
1. `examples/parse-unexpected-end-of-input.sh` — an `if` never closed with
   `fi` — bash accepts (EOF terminates the block) — the parser errors
   "Unexpected end of input" (+ a `?` lexer error on the trailing `$?`).
2. `examples/parse-paren-after-do.sh` — `for …; do { … }` — a brace-group
   body after `do` — bash accepts — "ParenClose unexpected after do".
3. `examples/subshell-sed-squote-dquote.sh` + `examples/multiple-awk-in-dqs.sh` —
   `$()` containing both single AND double quotes (`sed 's/"//g'`) inside
   a function body / a DQS — the nested-quote parser regression
   ("Unexpected end of input" / "Unexpected character: ?").
4. The `?` lexer error at 6:17 / 11:3 — `$?` in these (already-broken)
   contexts should lex as the status expansion, never "unexpected".

## MINIMAL-CORE-CHANGE
- tolerate a missing block terminator (`fi`/`done`) at EOF (bash behavior);
- allow a brace-group as a `do`/`then` body;
- fix the nested single+double quote handling inside `$()`/`"..."` (the
  infinite-loop regression the subshell-sed example documents).

## FAILING-CASE
`bash -n examples/parse-paren-after-do.sh` → OK (bash parses);
`debashc file --estree examples/parse-paren-after-do.sh` → "Parse error:
Unexpected end of input".
