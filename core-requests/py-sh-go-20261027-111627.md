Frontend: `frontends/py-sh-go` (gate `make test` → 97/101, 4 FAIL)
Filed: 2026-10-27T11:16+08:00 — by the py-sh-go frontend worker
Class: BUG in an existing shared analysis/lowering (not a new node, not a transform)

## NEED

For a **value-returning, positional-lifted** script function, the capture
form of a call must yield the function's VALUE.

py-sh-go emits, for `print(f(41))`:

```json
{"type":"Call","func":"capture","purity":"Spawn","args":[
  {"type":"Arrow","body":[
    {"type":"Expr","expr":{"type":"Call","func":"exec","purity":"Spawn","args":[
      {"type":"Str","style":"DoubleQuoted","value":"f"},
      {"type":"Array","elements":[{"type":"Int","value":41}]}]}}]}]}
```

The core recognizes exactly this shape (`shir.rs` ~65737, *"`$(f args)` of a
VALUE-RETURNING param-lifted function: the call returns the value directly"*)
and hands it to `try_native_fn_call`. That helper's **POSITIONAL_LOCAL**
branch (~46801-46819) now returns

```rust
return Some(seq(vec![run, last_exit_eq_zero()]));   // (f([41]), sh2.lastExit === 0)
```

`value_return_fn("f")` is true (`SH2_DBG_VR=1` → `DBG value_return: {"f"}`),
so the capture's value becomes the *success predicate*, not the return value.

## WHY (cannot be fixed in the frontend)

- The A1 above is the canonical shape: the core frontend emits the same
  `capture(Arrow([Expr(exec(...))]))` for shell `$(f args)`, and the frontend
  contract requires py-sh-go's A1 to match it.
- The param read must stay `Var("1")` (positional). That is what puts `f` in
  POS_LIFT; materializing named params instead would diverge from the core
  frontend and break the C backend, which reads `Var("1")` as `_sh_argv[1]`.
- The same A1 renders CORRECTLY through the C backend — verified directly, not
  just from the triage rows (`py-sh-go × c/rust` = PASS for all four):
  `otranspilerl-cli - --target c < t90.a1.json` → `cc -O1 t90.c -lgmp` →
  `[1, 18446744073709551617]` / `[1, 1267650600228229401496703205389]`, exactly
  native. Only the ESTree reference is wrong, so this is the reference
  lowering, not the emit.
- Not a new regression in committed code: `git blame` shows the status tail as
  **Not Committed Yet** (working tree, 2026-10-27). It is right for statement
  and condition positions (`if f …` must branch on `$?`) and only wrong where
  the value is consumed. The capture arm was not updated alongside it.

## MINIMAL-CORE-CHANGE

Give value-consuming callers the value form of the same call:

1. Add a value variant — e.g. `try_native_fn_value_call(name, args)` (or a
   `want_value: bool` on `try_native_fn_call`) that, in the POS_LIFT branch,
   returns `run` (`call`, or `await_expr(call)` when not sync) **without**
   `last_exit_eq_zero()`.
2. Use it at the capture arm (`shir.rs` ~65751) where the value-returning
   case already takes this path, so `$(f args)` of a value-returning lifted
   function yields the call's value.
3. Leave every statement/condition site on the current `seq([run, status])`
   path — `if f …`, bare `f …`, `f … && …` must keep bash status semantics.

No new contract node; `src/shir_json.rs` / schema / backend renderers are
unaffected.

## FAILING-CASE

Minimal (emitted by `./py-sh-go --shir mini.py --raw`):

```
def f(n):
    return n + 1
print(f(41))
```

```
$ otranspilerl-cli - --target estree < mini.a1.json > mini.e.json
$ node harness/estree-runner.mjs mini.e.json --source mini.py
false                       # expected: 42
```

Generated JS (the value is the sequence's last element):

```js
(process.stdout.write(String((f([41]), sh2.lastExit === 0)) + "\n"), sh2.lastExit = 0, true);
```

Assignment position is affected identically (`v = f(41)` →
`sh2.setVar("v", (f([41]), sh2.lastExit === 0))`), so this is not specific to
`echo`/interpolation.
