# sh: lift test-position grep to POSIX case — `echo X | grep P && A || B` becomes a pure-shell `case` (no grep dependency)

## NEED
A shir_passes PatternLift (`src/shir_passes/pattern/grep_to_case.rs`,
registered in the canonical pipeline + the A1-ingress pipeline — every
backend and every frontend that emits a test-position `grep` benefits)
that rewrites the test-position subset of `grep` invocations into a POSIX
`case` statement, so the rendered sh has **zero external-tool
dependency** for that class:

- `echo "$x" | grep [-q] [-i] LITERAL_GLOB` (and the `&&`/`||` chain
  idiom) → capture the LHS into a temp var, then
  `case "$x" in *pat*) A ;; *) B ;; esac` (the `&&`/`||` arms become the
  matched/unmatched branches).
- `if echo "$x" | grep -q P; then …` → `case "$x" in *P*) … esac`.
- `-i` → lowercase both sides with `tr 'A-Z' 'a-z'` (POSIX, supported
  on every sh from dash to busybox to BSD; a tiny `_lc` helper is
  emitted once per program and reused).
- `grep -F` patterns are a free win (already literal).

## WHY
The test-position grep is the single most common shell idiom in real
scripts (every `cmd | grep pat && A || B`, every `if … | grep -q`).
Today every sh render shells out to `grep` — which works when grep is
present but is exactly the kind of tool dependency the sh backend
exists to avoid (and the chimera gate's `pcregrep` family shows the
tax: tools absent from the minimal sandbox). The case form is *the*
POSIX-native test construct and renders to pure shell. It dovetails
with the existing `grep → contains` lift the estree worker already
has (estree keeps its runtime call; the case form is the POSIX
alternative and the sh backend's preferred path). 018_grep_params is
the cleanest example (`echo "text" | grep -i "PATTERN" && echo OK ||
echo FAIL`) and 017/062_05 are in scope too.

## MINIMAL-CORE-CHANGE
- `src/shir_passes/pattern/grep_to_case.rs`: `PatternLift` impl. Match
  `IrStmt::Exec` with `cmd == "grep"` in a TEST context (`&&`/`||`
  chain, `if`/`while` condition, `IrStmt::Test`-equivalent — wherever
  the existing `grep → contains` lift recognizes). The LHS is the
  pre-grep pipeline; capture it into a fresh temp var
  (`__g<seq>_<n>`) and emit a `case` against the rewritten pattern.
- **Pattern normalization (the load-bearing correctness step):**
  - Glob wildcards (`*`, `?`, `[abc]`) → pass through.
  - Regex metachars **NOT in the glob set** (`.`, `+`, `?` as regex,
    `^`, `$`, `(`, `)`, `|`, `\`, `{`, `}`) → **refuse loudly**
    (emit an `Unsupported` marker; the stub-gate + no-pcre bucket
    handles it). A silent escape would change grep's answer (e.g.
    `grep 'a.b'` matches `aXb`; `case "$x" in a.b)` matches the literal
    `a.b`) — a wrong-answer bug, not a portability gap. Conservative
    refuse is the right policy here.
  - `-F` flag → strip (already literal).
  - `-i` flag → emit a one-time `lc() { tr 'A-Z' 'a-z'; }` helper;
    apply to both sides.
  - Anchors `^` / `$` → `case` has no `^`/`$`; full-string match can
    be expressed as `case "$x" in "literal") …` (no wildcards);
    otherwise refuse.
- Out of scope (the lift does NOT match these — keep `grep` or refuse
  per no-pcre): `-P`/`-E` (regex/PCRE), content-over-file (forces
  reading the whole file), `-Z` (NUL-separator rewrite — separate
  transform), `-c`/`-l`/`-n` (no direct case analog).
- Register the lift; `cargo test --lib` green; `./fail-estree` stays
  at the trusted baseline (existing `grep → contains` is the parallel
  estree path; the new lift is additive and may convert some
  `contains` calls to `case` for the sh backend, which the sh renderer
  emits as native `case … esac`).

## FAILING-CASE
```sh
echo "text with pattern" | grep -i "PATTERN" && echo "OK" || echo "FAIL"
```
Today renders as `echo "text with pattern" | grep -i "PATTERN" && …` —
shells out to grep in the chimera sandbox. After the lift:
```sh
__g0=$(echo "text with pattern")
case $(printf '%s' "$__g0" | tr 'A-Z' 'a-z') in \
  *$(printf '%s' "PATTERN" | tr 'A-Z' 'a-z')*) echo "OK" ;; \
  *) echo "FAIL" ;; esac
```
Pure POSIX shell, no grep dependency, matches bash's answer. The
regex variant (`grep -E 'a.b'`) and the no-pcre variant (`grep -P`)
both stay as `grep` calls (refused if the target lacks the flag) and
do NOT regress.

## REGEX-POLICY NOTE
The conservative refuse-on-regex-metachar is the design call here.
A best-effort escape policy was considered and rejected: it would
silently change grep's answer on patterns like `a.b`, `x+`, `(...)`,
producing a wrong-answer bug rather than a portability gap. Refuse
loudly, let the user / corpus flag it, and the worker picks up the
case on the failure-driven loop.
